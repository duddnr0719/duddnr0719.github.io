> 델리게이터 = 메서드를 담는 자료형. 메서드 이름, 무명 델리게이터, 람다로 채울 수 있고, 매개변수로 넘기면 콜백, `+`/`-`로 여러 개를 묶을 수 있다. 람다가 바깥 지역 변수를 붙잡아 두는 게 클로저.
### 델리게이터란
- 메서드는 **행위**, 변수는 **데이터**. 행위를 변수처럼 저장하고 넘기려고 만든 게 델리게이터(와 람다)
- 델리게이터 선언은 "이런 모양(반환형 + 매개변수)의 메서드를 담는 자료형"을 만드는 것 → 클래스를 선언하는 것과 비슷
```csharp
delegate void TestDelegate();                 // 자료형 선언
TestDelegate t = <메서드 이름 | 무명 델리게이터 | 람다>;
```
### 같은 일을 세 가지 방법으로: 정렬
- `List.Sort()`에 IComparable 대신 **비교 방법을 직접 넘길 수 있음**. 받는 매개변수 타입은 `Comparison<T>`
  - `public delegate int Comparison<in T>(T x, T y)` → int를 반환하고 T 두 개를 받는 메서드
```csharp
List<Product> products = new List<Product>()
{
    new Product() { Name = "감자", Price = 500 },
    new Product() { Name = "사과", Price = 700 },
    new Product() { Name = "고구마", Price = 400 },
    new Product() { Name = "배추", Price = 600 },
    new Product() { Name = "상추", Price = 300 },
};

// ① 메서드 이름
products.Sort(SortWithPrice);
static int SortWithPrice(Product a, Product b) { return a.Price.CompareTo(b.Price); }

// ② 무명 델리게이터: 이름 없는 메서드를 그 자리에서
products.Sort(delegate (Product a, Product b)
{
    return a.Price.CompareTo(b.Price);
});

// ③ 람다: 매개변수 자료형 생략, return 하나면 중괄호·return도 생략
products.Sort((a, b) => a.Price.CompareTo(b.Price));

// 결과: 상추 300, 고구마 400, 감자 500, 배추 600, 사과 700
```
- 내림차순은 `b.Price.CompareTo(a.Price)`
### 이벤트 연결과 클로저
```csharp
int closerVariable = 52273;            // 생성자의 지역 변수
Button button = new Button() { Text = "버튼" };
button.Click += delegate (object? sender, EventArgs e)
{
    MessageBox.Show("델리게이터: " + closerVariable);
};
Controls.Add(button);
```
- 생성자가 끝나면 지역 변수는 사라져야 하지만, 버튼을 누르면 52273이 그대로 나옴
- **클로저**: 델리게이터·람다가 참조하는 바깥 지역 변수는 그 델리게이터가 살아 있는 동안 함께 유지됨 (그 변수 = 클로저 변수). 이 때문에 GC 규칙도 "클로저로 잡혀 있으면 수거하지 않음"으로 확장
- 함정: 클로저는 값이 아니라 **변수 자체**를 붙잡음
```csharp
var actions = new List<Action>();
for (int i = 0; i < 3; i++)
    actions.Add(() => Console.Write(i));
foreach (var f in actions) f();     // 012가 아니라 333 (모두 같은 i를 공유)
// 해결: 루프 안에서 int copy = i; 를 만들어 copy를 캡처 (foreach 변수는 반복마다 새로 만들어져 괜찮음)
```
### 델리게이터 선언과 초기화
- `[접근 제한자] delegate [반환형] [이름]([매개변수]);`
- **클래스 안·밖** 어디든 선언 가능(자료형이니까), **메서드 안에서는 불가**
```csharp
public delegate void TestDelegateA();          // 클래스 밖
class Program
{
    public delegate void TestDelegateB();      // 클래스 안
    static void Main(string[] args)
    {
        TestDelegateB a = TestMethod;          // 메서드 이름
        TestDelegateB b = delegate () { };     // 무명 델리게이터
        TestDelegateB c = () => { };           // 람다
        a(); b(); c();                         // 메서드처럼 호출
    }
    static void TestMethod() { }
}
```
- 정적·인스턴스 메서드 모두 담을 수 있음
- 매번 선언하기 귀찮으면 기본 제공 제네릭 델리게이터: `Action<T…>`(반환 없음), `Func<T…, TResult>`(반환 있음), `Predicate<T>`(bool 반환)
```csharp
delegate int AddDelegate(int x, int y);
AddDelegate add = (x, y) => x + y;                         // 연습문제 07
delegate void PrintDelegate(string message);
PrintDelegate print = message => Console.WriteLine(message); // 연습문제 08 (매개변수 하나면 괄호 생략)
Func<int, int, int> add2 = (x, y) => x + y;                // 같은 걸 선언 없이
```
### 콜백 메서드
- 매개변수로 받아서 안에서 호출하는 메서드. "무엇을 할지"는 호출하는 쪽이 정함
```csharp
class Students
{
    private List<Student> listOfStudent = new List<Student>();
    public delegate void PrintProcess(Student student);

    public void Add(Student student) { listOfStudent.Add(student); }

    public void Print()                       // 기본 출력
    {
        Print((student) => { Console.WriteLine(student); });
    }

    public void Print(PrintProcess process)   // 출력 방식을 밖에서 받음
    {
        foreach (var item in listOfStudent)
            process(item);
    }
}

Students students = new Students();
students.Add(new Student("윤인성", 4.2));
students.Add(new Student("연하진", 4.4));
students.Print();                    // 윤인성 : 4.2 / 연하진 : 4.4
students.Print((student) =>
{
    Console.WriteLine();
    Console.WriteLine("이름: " + student.Name);
    Console.WriteLine("학점: " + student.Score);
});
```
### 델리게이터 연산 (멀티캐스트)
- `+`로 합치면 호출할 때 **순서대로 모두** 실행, `-`로 뺌 (`*`, `/`는 없음)
```csharp
public delegate void SendString(string message);

SendString sayHello = Hello, sayGoodbye = Goodbye;
SendString multi = sayHello + sayGoodbye;
multi("윤인성");
// 안녕하세요. 윤인성 씨...!
// 안녕히 가세요. 윤인성 씨....
multi -= sayGoodbye;
multi("윤인성");
// 안녕하세요. 윤인성 씨...!
```
- 이벤트 `button.Click += …`의 `+=`가 바로 이 연산
### 응용: 스레드
- 스레드 = 코드를 읽고 실행하는 독립된 주체. 여러 개를 만들면 여러 코드를 동시에 처리
- `Thread` 생성자에 실행할 메서드(이름·무명 델리게이터·람다)를 넘기고 `Start()`
```csharp
using System.Threading;

Thread threadA = new Thread(() => { for (int i = 0; i < 1000; i++) Console.Write("A"); });
Thread threadB = new Thread(() => { for (int i = 0; i < 1000; i++) Console.Write("B"); });
Thread threadC = new Thread(() => { for (int i = 0; i < 1000; i++) Console.Write("C"); });
threadA.Start();
threadB.Start();
threadC.Start();
// AABCCCC…BBBB…AAAA… 처럼 섞여서 출력, 순서는 매번 다름
```
- 무거운 작업을 별도 스레드로 돌리면 UI가 멈추지 않음 (단, WinForms 컨트롤은 UI 스레드에서만 건드려야 해서 다른 스레드에선 `Invoke`를 써야 함)
### 윈도 폼: 람다 이벤트와 대화상자
```csharp
Button button = new Button() { Text = "버튼", Width = 100, Height = 23 };
button.Click += delegate (object? sender, EventArgs args)
{
    MessageBox.Show("무명 델리게이터를 사용한 이벤트 연결입니다.");
};
button.Click += (sender, args) =>
{
    MessageBox.Show("람다를 사용한 이벤트 연결입니다.");
};
Controls.Add(button);   // 클릭하면 메시지 상자 두 개가 차례로
```
- **대화상자**
  - 정적: 도구 상자에서 SaveFileDialog를 폼에 끌어다 놓기 → Designer.cs에 `private SaveFileDialog saveFileDialog1;`
  - 동적: `SaveFileDialog dialog = new SaveFileDialog();`
```csharp
private void button1_Click(object? sender, EventArgs e)
{
    saveFileDialog1.Filter = "텍스트 파일 (*.txt)|*.txt";
    if (saveFileDialog1.ShowDialog() == DialogResult.OK)        // 취소하면 FileName이 비어 있음
        File.WriteAllText(saveFileDialog1.FileName, textBox1.Text);
}
```
  - 교재처럼 결과 확인 없이 `File.WriteAllText`를 부르면 [취소]를 눌렀을 때 빈 경로로 예외가 남 → `DialogResult.OK` 확인 권장
  - 그 밖에 `OpenFileDialog`(FileName), `ColorDialog`(Color), `FontDialog`(Font)
