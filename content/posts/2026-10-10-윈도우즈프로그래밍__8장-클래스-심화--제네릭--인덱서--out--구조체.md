> 제네릭은 자료형을 나중에 정하는 틀, 인덱서는 객체에 `[]`를 쓰게 해주고, out은 매개변수로 값을 돌려받는다. 구조체는 값 복사되는 가벼운 클래스. 인터페이스는 "이 메서드를 꼭 구현하라"는 규약(IComparable, IDisposable).
### 제네릭
- 클래스 안에서 쓸 자료형에 **별칭**을 붙여두고, 쓸 때 정함 (`List<int>`가 대표 예). 관례상 `T`
```csharp
class Wanted<T>
{
    public T Value;
    public Wanted(T value) { this.Value = value; }
}

Wanted<string> wantedString = new Wanted<string>("String");
Wanted<int> wantedInt = new Wanted<int>(52273);
Wanted<double> wantedDouble = new Wanted<double>(52.273);
Console.WriteLine(wantedString.Value);   // String
Console.WriteLine(wantedInt.Value);      // 52273
```
- 여러 개도 가능: `class Test<T, U> { }`
- **where 제약 조건**
```csharp
class Test<T, U>
    where T : class          // T는 참조 형식만
    where U : struct         // U는 값 형식만
{ }

class Sorter<T>
    where T : IComparable    // CompareTo()가 있는 형식만 → 안에서 비교 가능
{ }
```
  - 그 밖에 `where T : new()`(기본 생성자 필요), `where T : 부모클래스`
### 인덱서
- 인스턴스에 `[]`를 붙여 배열처럼 쓰게 하는 특수 속성. `this[...]`로 선언
```csharp
class SquareCalculator
{
    public int this[int i]
    {
        get { return i * i; }
    }
}

SquareCalculator square = new SquareCalculator();
Console.WriteLine(square[10]);   // 100
Console.WriteLine(square[20]);   // 400
Console.WriteLine(square[30]);   // 900
```
- `set`도 만들면 `obj[i] = 값`이 가능. 대괄호 안 자료형은 int 말고도 string 등 아무거나 (Dictionary의 `dict["key"]`가 그 예)
### out 키워드
- 매개변수를 통해 결과를 **밖으로 내보냄** → 여러 값을 반환하는 효과
- 대표 예: `int.TryParse(string s, out int result)`
  - `Parse`는 잘못된 입력이면 예외로 프로그램이 죽지만, `TryParse`는 성공 여부를 bool로 반환하고 값은 out으로
```csharp
Console.Write("숫자 입력: ");
int output;
bool result = int.TryParse(Console.ReadLine(), out output);
if (result)
    Console.WriteLine("입력한 숫자: " + output);
else
    Console.WriteLine("숫자를 입력해주세요!");    // "ㅇㅂㅇ" 입력 시
```
- out 자리에는 **변수**만 (리터럴이면 CS1620). 최신 문법은 `int.TryParse(s, out int n)`처럼 그 자리에서 선언 가능
- out 매개변수는 메서드 안에서 **반드시 값을 할당**해야 함
```csharp
static void NextPosition(int x, int y, int vx, int vy, out int rx, out int ry)
{
    rx = x + vx;     // 다음 위치 = 현재 위치 + 속도
    ry = y + vy;
}

int x = 0, y = 0, vx = 1, vy = 1;
NextPosition(x, y, vx, vy, out x, out y);
Console.WriteLine("다음 좌표: (" + x + "," + y + ")");   // (1,1)
```
- 참고: `ref`는 들어갈 때도 값이 필요하고(읽고 쓰기), `out`은 나올 때 값을 채워야 함(쓰기 전용)
### 구조체 (struct)
- 간단한 객체용. int, double 같은 기본 숫자 형식도 사실 구조체(`System.Int32`)
| | 클래스 | 구조체 |
|---|---|---|
| 형식 | 참조 형식 | 값 형식 |
| 대입·전달 | 참조 복사 (같은 객체 공유) | **값 복사** (통째로 복사) |
| 상속 | 가능 | 불가 (인터페이스 구현은 가능) |
| `new` 없이 생성 | 불가 | 가능 (필드를 다 채우면) |
| null | 가능 | 불가 (`Nullable<T>`, `int?`로 우회) |
```csharp
struct Point
{
    public int x;
    public int y;
}

Point point;          // new 없이
point.x = 10;
point.y = 10;
Console.WriteLine(point.x);   // 10 (x를 안 채우고 쓰면 CS0170)

Point zero = new Point();     // 기본 생성자 → 모든 필드 0
```
- 교재의 제약: 매개변수 없는 생성자를 직접 못 만들고, 필드 선언 시 초기화 불가(CS0573), 생성자에서 모든 필드를 초기화해야 함
  - 이건 **C# 9까지** 규칙. C# 10(.NET 6)부터는 매개변수 없는 생성자와 필드 초기화를 직접 쓸 수 있고, C# 11부터는 생성자에서 안 채운 필드가 자동으로 기본값이 됨 (.NET 8로 확인: `public int x = 5;`와 `public Point() { … }` 모두 컴파일됨)
  - 시험은 교재 기준으로 답할 것
- 값 복사 vs 참조 복사
```csharp
PointClass a = new PointClass(10, 20);
PointClass b = a;           // 참조 복사
b.x = 100; b.y = 200;
// a: 100,200   b: 100,200   ← 같은 객체

PointStruct sa = new PointStruct(10, 20);
PointStruct sb = sa;        // 값 복사
sb.x = 100; sb.y = 200;
// sa: 10,20    sb: 100,200  ← 별개
```
- 언제 구조체? 작고(16바이트 안팎), 불변에 가깝고, 자주 만들고 버리는 값 (좌표, 색, 크기)
### 윈도 폼: 메뉴와 상태 표시줄
- **MenuStrip**: 도구 상자에서 폼에 끌어다 놓기 → 스마트 태그(`>`) → [항목 편집…] → MenuItem 추가, `Text`로 이름. 하위 메뉴는 `DropDownItems`의 […]. 항목을 선택해 Click 이벤트 연결 (디자이너에서 메뉴에 바로 타이핑해도 됨)
- **StatusStrip**: 폼 아래쪽 상태 표시줄. 항목 컬렉션 편집기에서 StatusLabel 추가 → 코드에서 `toolStripStatusLabel1.Text = "준비";`
### 인터페이스 입문
- 클래스가 지켜야 할 **규약**. 기본 제공 인터페이스는 대문자 `I`로 시작
- **IComparable**: `List.Sort()`는 요소끼리 비교할 줄 알아야 함
```csharp
class Product : IComparable
{
    public string Name { get; set; }
    public int Price { get; set; }

    public override string ToString() { return Name + " : " + Price + "원"; }

    public int CompareTo(object obj)    // 규약: 이 메서드를 구현해야 함
    {
        return this.Price.CompareTo((obj as Product).Price);
    }
}

List<Product> list = new List<Product>()
{
    new Product() { Name = "고구마", Price = 1500 },
    new Product() { Name = "사과", Price = 2400 },
    new Product() { Name = "바나나", Price = 1000 },
    new Product() { Name = "배", Price = 3000 },
};
list.Sort();
foreach (var item in list) Console.WriteLine(item);
// 바나나 : 1000원 / 고구마 : 1500원 / 사과 : 2400원 / 배 : 3000원
```
  - IComparable 없이 `Sort()` → `InvalidOperationException` (적어도 하나 이상의 객체가 IComparable을 구현해야 합니다)
  - `class Product : IComparable` 쓴 뒤 `Ctrl + .` → [인터페이스 구현]으로 메서드 틀 자동 생성
  - `CompareTo`는 작으면 음수, 같으면 0, 크면 양수
  - 제네릭 버전 `IComparable<Product>`를 쓰면 `(obj as Product)` 변환이 필요 없음
- 인터페이스는 실체가 없어 `new IComparable()` 불가
- **IDisposable**: `Dispose()` 규약. `using` 블록을 벗어나면 자동 호출 → 파일·DB 연결 같은 자원 정리
```csharp
class Dummy : IDisposable
{
    public void Dispose() { Console.WriteLine("Dispose() 메서드를 호출합니다."); }
}

using (Dummy dummy = new Dummy())
{
    // 사용
}   // 여기서 자동으로 Dispose() → "Dispose() 메서드를 호출합니다."
```
- 직접 만들기: `interface IBasic { }`. 솔루션 탐색기 → 추가 → 새 항목 → 인터페이스 (`I` + 대문자로 시작하는 이름이면 VS가 인터페이스 틀로 생성)
