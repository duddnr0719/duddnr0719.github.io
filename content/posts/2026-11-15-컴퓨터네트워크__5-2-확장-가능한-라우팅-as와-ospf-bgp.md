### 확장 가능한 라우팅과 자치 시스템(AS)
- **이상적 라우팅 가정과 실제 네트워크의 한계**
  - **기존 가정** = 모든 라우터가 동일하며 단일 네트워크로 이어져 있다는 이상적 환경 전제
  - **확장(scale) 문제** = 목적지(호스트) 수가 6억 개를 넘음 → 단일 라우팅 테이블에 전체 목적지를 수록할 수 없고, 테이블 교환 트래픽만으로 링크 대역폭 고갈 유발
  - **관리 자치권(administrative autonomy) 문제** = 다수 조직의 네트워크가 모인 구조(`internet = network of networks`) → 각 조직 관리자가 독자적 방식대로 자사 망을 운영·관리하고자 함
- **자치 시스템(AS, autonomous system) 기반 계층 분리**
  - 라우터들을 영역(도메인) 단위의 **자치 시스템(AS)**으로 그룹화해 확장성 문제 해결
  - **인트라-AS(intra-AS) 라우팅(인트라-도메인)** = 동일 AS 내부의 호스트·라우터 간 경로 결정
    - 한 AS 내 라우터는 모두 같은 인트라-도메인 프로토콜을 실행하되, 서로 다른 AS끼리는 각기 다른 인트라-AS 프로토콜 채택 가능
  - **게이트웨이 라우터(gateway router)** = AS 경계에 위치해 타 AS 라우터와 직결되는 라우터로, 인트라-도메인 및 **인터-도메인 라우팅**을 함께 수행
  - **인터-AS(inter-AS) 라우팅(인터-도메인)** = 서로 다른 AS 사이를 잇는 라우팅
- **포워딩 테이블 구성과 AS 간 연동**
  - 포워딩 테이블 엔트리는 인트라-AS와 인터-AS 알고리즘의 결합으로 채워짐
    - **인트라-AS 알고리즘** = AS 내부 목적지 엔트리 지정
    - **인터-AS + 인트라-AS 알고리즘** = AS 외부 목적지 엔트리 설정
  - **외부 패킷 전달 절차(AS1 → AS2 · AS3 예)**
    - AS1 내부 라우터가 외부행 데이터그램을 수신하면 목적지로 이어지는 게이트웨이 라우터로 넘겨야 함
    - 이를 위해 AS1 인터-도메인 라우팅이 (1) AS2·AS3 경유 도달 가능 목적지 학습 → (2) 해당 도달 정보를 AS1 내부 전체 라우터로 전파하는 역할 수행
  - **내·외부망 도메인 조회 사례(`nslookup`)** = 동일 도메인 질의 시에도 외부망 노출 IP는 인터-AS가, 내부망 노출 IP는 인트라-AS가 각각 관리해 서로 다른 주소가 반환됨

### 인트라-AS 라우팅 프로토콜과 OSPF
- **주요 인트라-AS 프로토콜 비교**
  - **RIP(Routing Information Protocol, `[RFC 1723]`)** = 30초 주기로 DV를 광고하는 거리 벡터 방식(80년대·90년대 일부 쓰였으나 현재는 널리 사용되지 않음)
  - **OSPF(Open Shortest Path First, 개방형 최단경로 우선, `[RFC 2328]`)** = 다익스트라(Dijkstra) 알고리즘을 쓰는 링크 상태 프로토콜
    - **IS-IS 프로토콜(`Intermediate-system`)** = RFC가 아닌 ISO 표준이지만 본질적으로 OSPF와 동일한 동작 방식
  - **EIGRP(Enhanced Interior Gateway Routing Protocol)** = 거리 벡터 기반 프로토콜로, 기존 Cisco 사 독점 규격에서 2013년 개방(`[RFC 7868]`)
- **OSPF의 핵심 특성**
  - **개방형(`"open"`)** = 라우팅 프로토콜 규격을 공용으로 공개·활용 가능
  - **링크 상태 플러딩(flooding)과 최단 경로 계산** = 각 라우터가 AS 내 모든 라우터로 링크 상태 정보를 플러딩 → 전체 토폴로지 맵 확보 → 다익스트라 최소 비용 경로 알고리즘으로 포워딩 테이블 산출
  - **IP 직접 캡슐화** = TCP/UDP 계층을 거치지 않고 IP 패킷 상에 OSPF 메시지를 직접 실어 전송
  - **유연한 링크 비용** = 대역폭 · 지연 등 여러 기준에 따라 링크 비용 지정 가능
  - **보안(security)** = 악의적 침입 차단을 위해 라우터 간 교환하는 모든 OSPF 메시지에 인증 절차 필수 적용
  - **계층(hierarchical) 지원** = 단일 라우팅 도메인 내부에서도 계층형 구조 구성 가능
- **계층 구조의 OSPF(Hierarchical OSPF)**
  - **2-단계 계층 구성** = **지역 영역(local area)**과 **백본(backbone)**으로 분할
  - **광고 범위 제한** = 링크 상태 광고가 소속 영역 내부로만 국한됨 → 각 노드는 자기 영역의 상세 토폴로지만 유지하고, 타 영역 네트워크에 대해서는 방향(최단 경로)만 파악
  - **계층 내 라우터 역할**
    - **내부 / 지역 라우터(internal / local routers)** = 소속 영역 내에서만 LS 정보를 플러딩해 영역 내부 라우팅을 계산하고, 영역 밖 패킷은 영역 경계 라우터로 전달
    - **영역 경계 라우터(area border routers)** = 자기 영역 내 목적지까지의 거리 정보를 요약(summarize)해 백본에 광고
    - **백본 라우터(backbone routers)** = 백본에 연결되어 백본 범위로 제한된 OSPF 수행
    - **경계 라우터(boundary router)** = 다른 AS들과 연결되는 접점 담당

### BGP 개요, 세션, 경로 속성과 메시지
- **BGP(Border Gateway Protocol)의 역할**
  - 사실상(de facto) 인터넷 표준 **인터-AS 라우팅 프로토콜**로, 각 서브넷이 외부망에 자신의 존재 · 도달 가능 대상 · 전달 경로를 **광고(advertisement)**하게 함
  - **eBGP(External BGP)** = 인접 AS로부터 서브넷 도달성(reachability) 정보 수집
  - **iBGP(Internal BGP)** = 수집한 도달성 정보를 자사 AS 내 모든 라우터에 전파
  - **경로 결정** = 도달성 정보와 **AS 정책**을 바탕으로 서브넷까지 가는 '좋은' 경로 선정 (게이트웨이 라우터는 eBGP와 iBGP를 동시에 운용)
- **BGP 세션과 경로 벡터(Path Vector) 동작**
  - **BGP 세션** = 두 BGP 피어(peer) 라우터가 반영구적 **TCP 연결**(포트 `179`) 위에서 목적지 네트워크 프리픽스별 경로 정보를 교환·광고
  - **경로 벡터(path vector) 의미** = 예컨대 AS3 게이트웨이 `3a`가 AS2 게이트웨이 `2c`에 `AS3, X` 경로를 광고하면, AS3가 AS2로부터 받은 `X`행 데이터그램을 전달하겠다는 약속을 뜻함
- **경로 속성(Path Attributes)과 BGP 루트(Routes)**
  - 프리픽스 광고에 BGP 속성이 결합해 **`프리픽스(prefix) + 속성(attribute) = 루트(route)`** 구성
  - **AS-PATH** = 광고가 경유한 AS 목록을 기록해 정책 부합 여부를 검증 (예: `AS3 → AS2 → AS1` 순 광고 시 AS1이 수신하는 경로 목록은 `AS2, AS3`)
  - **NEXT-HOP** = 다음 홉 AS로 연결되는 특정 인트라-AS 라우터를 가리켜, 자사 AS 내부에서 패킷을 보낼 다음 지점을 지정
- **정책-기반 라우팅과 다중 경로 광고 흐름**
  - **임포트 정책(import policy)** = 게이트웨이 라우터가 수신한 루트 광고에 자체 정책을 대입해 수용·폐기 결정 (예: `Y`가 의심스러운 지역/국가라면 `AS Y` 경유 루트를 버려 라우팅 차단)
  - **광고(수출) 제어 정책** = AS 정책에 따라 인접 AS에 특정 경로를 알릴지 여부를 통제 (예: `AS3-X` 경로 노출을 원치 않으면 AS1에 광고 생략 가능)
  - **경로 전파·선택 예(`AS3 → AS2 → AS1`)**
    - `3a`(AS3)가 eBGP로 `AS3, X` 광고 → `2c`(AS2)가 정책상 수락 후 iBGP로 AS2 전체 라우터에 전파
    - `2a`(AS2)가 정책에 따라 eBGP로 `1c`(AS1)에 `AS2, AS3, X` 광고
    - `1c`는 `2a`로부터 `AS2, AS3, X`를 학습하고 `3a`로부터 `AS3, X`를 학습함
    - AS1 정책에 따라 `1c`가 `AS3, X`를 선택 → iBGP로 AS1 내부 라우터에 전파
- **BGP 메시지 4종류** (TCP 연결 기반 피어 간 교환)
  - **OPEN** = 피어 간 TCP 세션 개설 및 송신자 인증
  - **UPDATE** = 신규 경로 광고 또는 기존 경로 철회
  - **KEEPALIVE** = `UPDATE` 부재 시 연결 유지 및 `OPEN` 요청에 대한 `ACK` 응답
  - **NOTIFICATION** = 직전 메시지 오류 보고 및 연결 종료 통지

### BGP·OSPF 협력과 인터-AS vs 인트라-AS 차이
- **고속도로 지도(BGP)와 시내 세부 지도(OSPF)의 협력**
  - 외부 목적지 `X`의 포워딩 테이블 엔트리를 채우기 위해 BGP와 OSPF가 역할을 분담함
  - **AS1 내부 라우터 `1a` · `1d` 엔트리 설정 예**
    - `1a` · `1b` · `1d`는 `1c`로부터 iBGP를 통해 "`X`행 경로는 `1c`를 경유한다"는 사실 학습
    - `1d`는 OSPF로 `1c`까지의 로컬 링크 인터페이스 `1`을 확인 → 포워딩 테이블에 `1c`와 `X` 모두 출력 인터페이스 `1`로 설정
    - `1a`는 OSPF로 `1c`까지의 로컬 링크 인터페이스 `2`를 확인 → 포워딩 테이블에 `1c`와 `X` 모두 출력 인터페이스 `2`로 설정
- **인터-AS와 인트라-AS 라우팅의 차이**
  - **정책(policy)**
    - **인터-AS** = 트래픽 전달 방식과 자사 망 경유 허용 대상을 관리자가 통제해야 함
    - **인트라-AS** = 단일 관리자가 통제하므로 별도 정책 결정 불필요
  - **확장성(scale)** = 계층적 라우팅으로 포워딩 테이블 크기와 갱신 트래픽 동시 감소
  - **성능(performance)**
    - **인트라-AS** = 성능 중심
    - **인터-AS** = 성능보다 **정책** 준수 우선

### 핫 포테이토 라우팅, ISP 정책 사례, BGP 경로 선택
- **핫 포테이토 라우팅(Hot Potato Routing)**
  - 목적지까지 여러 출구가 있을 때 인터-도메인 비용은 따지지 않고, **자사 AS 내 인트라-도메인 비용이 최소인 로컬 게이트웨이**로 패킷을 곧장 내보내 자사 망 부담을 줄이는 전략
  - **동작 예(AS2 라우터 `2d`)** = `2d`가 iBGP로 `X`행 경로 `2a`(`AS1, AS3, X`)와 `2c`(`AS3, X`)를 학습한 상황
    - OSPF 링크 가중치가 `2d → 2a`는 `201`, `2d → 2c`는 `263` → `X`까지 AS 홉 수가 더 많더라도 내부 비용이 작은 `2a` 선택
- **ISP 경로 광고 정책 사례(소비자 네트워크 중심 라우팅)**
  - ISP는 자사 고객 네트워크 트래픽만 라우팅하고, 타 ISP 간 트래픽이 자사 망을 경유하는 것을 차단하려 함
  - **사례 1(타 ISP 간 무수익 경유 차단)**
    - `A`가 `B` · `C`에 `Aw` 경로를 광고해도 `C` · `A` · `w`는 `B`의 고객이 아님 → `B` 입장에서는 `CBAw` 중계로 얻는 수익 부재
    - `B`가 `C`로의 `BAw` 광고를 생략 → `C`는 `CBAw`를 배우지 못한 채 `B`를 우회하는 `CAw` 경로로 `w`에 도달
  - **사례 2(다중-홈 소비자 네트워크, multiple-homed network)**
    - `A` · `B` · `C`가 공급자 네트워크(provider network)이고 `x` · `w` · `y`가 소비자일 때, `x`(`X`)는 두 공급자(`B`, `C`)에 동시 연결된 다중-홈 네트워크임
    - `X`는 자신을 거쳐 `B`에서 `C`로 트래픽이 오가는 것을 막고 두 경로를 `X` 자신의 통신 전용으로만 쓰기 위해 `B`에게 `C`행 경로를 광고하지 않음
- **BGP 경로 선택(제거 규칙, elimination rules)**
  - 목적지 AS로 둘 이상의 경로를 학습한 라우터는 단일 경로가 남을 때까지 아래 순서로 제거 규칙 적용
  - **1단계(지역 선호 값)** = 정책으로 부여된 **지역 선호 값 속성(local preference value attribute)**이 가장 높은 루트 선택
  - **2단계(최단 AS-PATH)** = 경유 AS 수(`shortest AS-PATH`)가 가장 짧은 루트 선택
  - **3단계(최소 비용 NEXT-HOP)** = 경로 비용이 가장 작은 **NEXT-HOP 라우터**를 갖는 루트 선택(**핫 포테이토 라우팅**)
  - **4단계(추가 기준)** = 3단계 이후에도 복수 루트가 남으면 **추가적인 기준**을 적용해 최종 결정
