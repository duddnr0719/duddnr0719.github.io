> counter++ 한 줄도 기계어로는 세 단계라 중간에 끊기면 값이 깨진다(경쟁 상태). 임계구역 해법은 상호 배제·진행·한정 대기를 만족해야 하고, 소프트웨어(Peterson)는 현대 CPU에서 깨질 수 있어 하드웨어 원자 명령(test_and_set, compare_and_swap)을 쓴다.
### 왜 동기화가 필요한가
- 프로세스들은 동시에 실행되고 언제든 중단될 수 있음 → 같은 데이터를 건드리면 손상 가능
- 생산자-소비자에 버퍼 안 아이템 수 `counter`를 추가하면 (넣을 때 ++, 꺼낼 때 −−)
```c
/* 생산자 */
while (true) {
    while (counter == BUFFER_SIZE) ;   /* 가득 참 */
    buffer[in] = next_produced;
    in = (in + 1) % BUFFER_SIZE;
    counter++;
}
/* 소비자 */
while (true) {
    while (counter == 0) ;             /* 비어 있음 */
    next_consumed = buffer[out];
    out = (out + 1) % BUFFER_SIZE;
    counter--;
}
```
- 각각은 맞아 보이지만 동시에 돌면 문제
### 경쟁 상태 (race condition)
- `counter++` = `register1 = counter` → `register1 = register1 + 1` → `counter = register1`
- `counter--` = `register2 = counter` → `register2 = register2 − 1` → `counter = register2`
- counter = 5에서 이렇게 섞이면
| 단계 | 실행 | 결과 |
|---|---|---|
| S0 | 생산자 register1 = counter | register1 = 5 |
| S1 | 생산자 register1 + 1 | register1 = 6 |
| S2 | 소비자 register2 = counter | register2 = 5 |
| S3 | 소비자 register2 − 1 | register2 = 4 |
| S4 | 생산자 counter = register1 | counter = 6 |
| S5 | 소비자 counter = register2 | **counter = 4** (정답은 5) |
- 컨텍스트 스위치가 언제 일어날지 모르므로 결과가 실행 순서에 따라 달라짐 = 경쟁 상태
### 임계구역 문제
- 임계구역(critical section): 공유 데이터를 건드리는 코드 영역. 들어갈 때 잠그고 나올 때 풂
```c
do {
    entry section        /* 진입 허가 요청 (잠금) */
        critical section
    exit section         /* 해제 */
        remainder section
} while (true);
```
- 해법이 만족해야 할 3조건
  1. **상호 배제**: 한 번에 하나만 임계구역에
  1. **진행(progress)**: 임계구역이 비어 있고 들어가려는 프로세스가 있으면, 누가 들어갈지 결정을 무한정 미루면 안 됨 (아무도 못 들어가는 교착 방지)
  1. **한정 대기(bounded waiting)**: 요청 후 다른 프로세스가 먼저 들어가는 횟수에 상한이 있어야 함 (기아 방지)
- 셋을 다 만족시키기는 생각보다 어려움. 잘못된 예
  - 상호 배제 위반: `while (lock == true); lock = true;` → T1이 while을 통과한 직후 끊기고 T2도 통과 → 둘 다 진입 (검사와 설정이 분리돼 있어서)
  - 둘 다 대기: `lock1 = true; while (lock2 == true);` / `lock2 = true; while (lock1 == true);` → 둘 다 깃발을 든 상태에서 서로 기다림 → 영원히 못 들어감 (슬라이드에선 한정 대기 위반 사례로 분류)
  - 진행 위반: `lock` 값으로 T1, T2가 반드시 번갈아 들어가게 하면, 상대가 안 들어가는 한 비어 있어도 못 들어감
### 단순한 방법들
- 인터럽트 끄기: 임계구역 동안 인터럽트를 막으면 단일 코어에선 해결. 멀티코어에선 모든 코어의 인터럽트를 막아야 해서 효율이 무너짐
- 커널에서의 처리
  - 선점형 커널: 커널 모드에서도 선점 가능 → 커널 자료구조 동기화가 반드시 필요하지만 반응성이 좋음
  - 비선점형 커널: 커널 모드를 나가거나 블록·양보할 때까지 안 뺏음 → 커널 안 경쟁 상태는 없지만 반응성이 떨어짐
### Peterson의 해법
```c
/* 프로세스 i (상대는 j) */
do {
    flag[i] = true;                /* 나 들어가고 싶어 */
    turn = j;                      /* 근데 너 먼저 */
    while (flag[j] && turn == j)   /* 상대가 원하고, 상대 차례면 대기 */
        ;
        /* critical section */
    flag[i] = false;
        /* remainder section */
} while (true);
```
- 3조건 증명 가능
  - 상호 배제: 들어가려면 flag[j] == false 또는 turn == i. turn은 하나라 둘이 동시에 만족 못 함
  - 진행: 둘 다 원하면 turn이 둘 중 하나로 정해져 있어 반드시 한쪽은 진입
  - 한정 대기: 나온 쪽이 다시 들어오려면 turn을 상대에게 넘기므로 최대 한 번만 양보
- 한계: 현대 CPU·컴파일러는 성능을 위해 서로 의존하지 않는 읽기·쓰기 순서를 **재배치**할 수 있음 → `flag[i] = true`와 `turn = j`의 순서가 바뀌면 둘 다 진입 가능. 그래서 실제론 하드웨어 지원이 필요
### 하드웨어 원자 명령
- 검사와 수정, 또는 두 값의 교환을 **중간에 끊길 수 없는 하나의 명령**으로 CPU가 실행
```c
do {
    acquire lock
        critical section
    release lock
        remainder section
} while (true);
```
- **test_and_set**: 원래 값을 돌려주고 TRUE로 바꿈 (원자적으로)
```c
boolean test_and_set(boolean *target) {
    boolean rv = *target;
    *target = true;
    return rv;
}

/* lock = false 로 초기화 */
do {
    while (test_and_set(&lock))
        ;   /* 이미 true였으면 다른 누가 잡은 것 → 대기 */
    /* critical section */
    lock = false;
    /* remainder section */
} while (true);
```
- **compare_and_swap (CAS)**: 기대값과 같을 때만 새 값으로 바꾸고, 원래 값을 반환. test_and_set보다 유연
```c
int compare_and_swap(int *value, int expected, int new_value) {
    int temp = *value;
    if (*value == expected)
        *value = new_value;
    return temp;
}

/* lock = 0 으로 초기화 */
do {
    while (compare_and_swap(&lock, 0, 1) != 0)
        ;   /* 0이 아니면 누가 쥐고 있음 */
    /* critical section */
    lock = 0;
} while (true);
```
- 둘 다 상호 배제는 되지만
  - 기다리는 동안 CPU를 계속 소모(**바쁜 대기**)
  - 누가 다음에 들어갈지 순서가 없어 **한정 대기를 보장 못 함**
### 한정 대기까지 보장하기
- 프로세스마다 `waiting[i]` 플래그를 두고, 나갈 때 다음 대기자를 직접 깨움
```c
do {
    waiting[i] = true;
    key = true;
    while (waiting[i] && key)
        key = test_and_set(&lock);
    waiting[i] = false;

    /* critical section */

    j = (i + 1) % n;                       /* i 다음 번호부터 순회 */
    while ((j != i) && !waiting[j])
        j = (j + 1) % n;
    if (j == i)
        lock = false;                      /* 기다리는 사람 없음 → 잠금 해제 */
    else
        waiting[j] = false;                /* j에게 바로 넘김 (잠금은 유지) */

    /* remainder section */
} while (true);
```
- 원형 순서로 넘기므로 최대 n − 1번 안에 차례가 옴 → 3조건 모두 만족
- 이걸 매번 짜는 건 복잡 → OS가 **mutex**, 세마포어 같은 도구로 감싸서 제공 (다음 강)
### 직접 확인해보기
```c
#include <pthread.h>
#include <stdio.h>
#define N 1000000
int counter = 0, lock = 0;

void *inc(void *a) { for (int i = 0; i < N; i++) counter++; return NULL; }
void *dec(void *a) { for (int i = 0; i < N; i++) counter--; return NULL; }

void *inc_cas(void *a) {
    for (int i = 0; i < N; i++) {
        while (__sync_val_compare_and_swap(&lock, 0, 1) != 0) ;  /* GCC 내장 CAS */
        counter++;
        __sync_lock_release(&lock);
    }
    return NULL;
}
/* dec_cas도 같은 모양 */
```
- `gcc race.c -o race -pthread`로 빌드. 잠금 없는 버전은 멀티코어에서 돌리면 실행할 때마다 0이 아닌 값이 나오고, CAS 버전은 항상 0
