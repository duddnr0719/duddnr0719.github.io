> C#은 .NET 위에서 도는 형식 안전한 객체 지향 언어. .NET 5부터 윈도우·리눅스·맥 어디서나 동작한다. 라이브러리는 내가 부르고, 프레임워크는 나를 부른다(제어 역전).
### C#이란
- 범용 목적의, **형식 안전(type-safe)** 한 **객체 지향** 언어. 기존 언어의 생산성을 개선하려고 만들어졌고 성능도 좋음
- 처음엔 윈도우 전용 → 지금은 윈도우, 맥, 리눅스, 안드로이드, iOS
### 플랫폼
- 응용 프로그램을 실행하는 하드웨어 + 소프트웨어 집합
- 예전엔 OS = 플랫폼 → 윈도우용 프로그램은 리눅스·맥에서 안 돎 (OS 종속)
- **소프트웨어 플랫폼**: OS와 앱 사이에 끼는 '중간 레고 블록'. 앱은 OS를 신경 쓰지 않고 개발 → 생산성↑
  - Java: JVM, JavaScript: 웹 브라우저
### .NET
- 마이크로소프트의 소프트웨어 플랫폼
- **CLR**(공통 언어 런타임): **CLI**(공통 언어 인프라) 규격의 구현. C#, VB.NET, F# 등 20개 이상의 언어를 .NET에 연결 (모두 중간 언어 IL로 컴파일돼 CLR에서 실행)
- **.NET Framework** = CLR + 클래스 라이브러리 (제품 이름)
  - 데스크톱: WinForms, WPF, UWP / 웹: Silverlight, ASP.NET, ASP.NET MVC / 서비스: WCF
- 역사
  - 리눅스 진영이 .NET을 리눅스에서 돌리려고 **Mono**(와 Moonlight) 프로젝트
  - 2014년 MS가 .NET을 오픈소스화, 크로스 플랫폼 **.NET Core**
  - 2020년 **.NET 5**로 하나로 통합 → 이후 .NET 6, 7, 8 …
- 모던 .NET: 윈도우·리눅스·맥·iOS·안드로이드, WinForms, ASP.NET, Unity, Xamarin(→ MAUI), 머신러닝용 ML.NET
### 라이브러리 vs 프레임워크
- **라이브러리**: 미리 만들어둔 클래스·서브루틴 모음. 화면 출력 같은 복잡한 기능을 선배들이 만들어 둔 것
  - 언어 자체는 "이름 뒤 `()`는 메서드 호출" 같은 규칙일 뿐, 실제 출력 기능은 라이브러리
  - C `printf("Hello World")`, C# `Console.WriteLine("Hello World")`, Java `System.out.println(...)`, Python `print(...)`, Ruby `puts(...)`
  - **내 코드가 라이브러리를 호출**
- **프레임워크**: **제어 역전(IoC)** 이 적용된 큰 라이브러리
  - 프레임워크가 프로그램의 시작부터 끝까지 흐름을 쥐고, 필요한 시점에 **내 코드를 호출**
  - Main을 내가 직접 제어하지 않는다면 프레임워크를 쓰는 중 (예: WinForms의 이벤트 핸들러, ASP.NET의 컨트롤러)
  - 요즘은 "큰 라이브러리 = 프레임워크"로 섞어 부르기도
### C#으로 할 수 있는 것
- **GUI**
  - **WinForms**: C++의 Win32 API/MFC를 C#으로 옮긴 형태. 폼 디자이너에서 버튼·콤보박스를 끌어다 놓는 식, 구조가 직관적이라 입문용
  - **WPF**: MVC·**MVVM** 패턴으로 생산성↑, DirectX 내장으로 3D까지. Silverlight, 윈도우 폰, UWP의 모태
- **웹**: ASP.NET, ASP.NET MVC (예: Stack Overflow). 모던 .NET 이후 리눅스 서버에서도 추가 비용 없이 운영
- **게임**: 클라이언트는 **Unity**의 주력 언어(윈도우, 맥, 리눅스, Xbox, PlayStation, 안드로이드, iOS), 서버도 성능 향상으로 C# 사용(넥슨 등)
- **IoT**: ATM·전광판의 윈도우 임베디드, 라즈베리 파이용 Windows 10 IoT Core
### 개발 환경
- Visual Studio 2022 Community 설치 → 워크로드에서 **[.NET 데스크톱 개발]** 체크
- 새 프로젝트 → C# **콘솔 앱** → 이름 `FirstProgram` → **[최상위 문 사용 안 함] 체크**
```csharp
namespace FirstProgram
{
    internal class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("Hello, World!");
        }
    }
}
```
- 이후 예제는 Main 메서드 부분만 표기
- **프로젝트**: 소스·이미지 등 개발에 필요한 파일의 기본 단위 / **솔루션**: 관련 프로젝트들의 묶음 (서버 + 클라이언트 + 관리 앱)
- 실행: [▶ 시작], [디버그] → [디버깅 시작], 또는 **F5** (디버깅 없이 실행은 Ctrl + F5)
- 오류: `Console.WriteRine("Hello World*);`처럼 오타가 있으면 빌드 오류 → [아니요] → 오류 목록에서 메시지("'WriteRine'에 대한 정의가 포함되어 있지 않습니다")를 더블클릭하면 해당 위치로 이동
- **IntelliSense**: `Ctrl + Space`로 자동 완성 + 메서드 설명·매개변수 안내
- CodeLens('참조 0개' 표시) 끄기: 우클릭 → CodeLens 옵션 → [CodeLens 사용] 해제
- VS 없이도 가능: `dotnet new console -o FirstProgram` → `cd FirstProgram` → `dotnet run`
### Write() vs WriteLine()
```csharp
static void Main(string[] args)
{
    Console.Write("Write");
    Console.WriteLine("WriteLine");

    Console.WriteLine("WriteLine");
    Console.WriteLine("WriteLine");

    Console.Write("Write");
    Console.Write("Write");
}
```
```
WriteWriteLine
WriteLine
WriteLine
WriteWrite
```
- `Write()`: 출력하고 줄을 바꾸지 않음 / `WriteLine()`: 출력하고 줄 바꿈
- `Write("Write")`를 5번 하면 `WriteWriteWriteWriteWrite` 한 줄
### 최상위 문 (Top-level statements)
- C 언어나 전통적인 C#은 `Main`을 감싸는 틀이 필요하지만, C# 9.0부터는 파일 맨 위에 바로 문장을 써도 됨
```csharp
// C# 10 이상, 이 한 줄이 프로그램 전체
Console.WriteLine("Hello, world!");
```
- 짧은 프로그램엔 편하지만 메서드 구성 등에 제약이 있어, 기초를 익히려고 교재는 전통적인 `Main` 구조를 사용
