> 네트워크 계층이 호스트끼리 이어준다면, 트랜스포트 계층은 프로세스끼리 이어준다. 그 핵심이 포트 기반 역다중화이고, UDP는 거기에 체크섬만 얹은 최소 프로토콜이다.
### 트랜스포트 계층 개요
- 서로 다른 호스트의 프로세스 간 **논리적 통신** 제공. 종단 시스템에서만 구현.
  - 송신: 메시지 → 세그먼트로 분할 + 헤더 → 네트워크 계층
  - 수신: 세그먼트 헤더 확인 → 메시지 재조립 → 소켓으로 역다중화
- 네트워크 계층 = 호스트 간 통신, 트랜스포트 계층 = 프로세스 간 통신(네트워크 계층에 의존)
- 집안 비유: 집 = 호스트, 사촌 아이들 = 프로세스, 편지 = 메시지, 앤과 빌 = 트랜스포트 프로토콜, 우편 서비스 = 네트워크 계층
- TCP: 신뢰적·순서 보장, 혼잡 제어, 흐름 제어, 연결 설정 / UDP: 비신뢰·비순서, IP 같은 best-effort
- 둘 다 지연 보장, 대역폭 보장은 없음
### 다중화 / 역다중화
- 다중화(송신): 여러 소켓의 데이터를 모아 나중에 역다중화에 쓸 헤더를 붙임
- 역다중화(수신): 헤더 정보로 올바른 소켓에 전달
- IP 데이터그램에는 출발지·목적지 IP, 그 안의 세그먼트에는 출발지·목적지 포트 → 호스트는 IP + 포트로 소켓을 찾음
### 비연결형 역다중화 (UDP)
- 소켓을 포트로 생성 (`new DatagramSocket(12534)`), 보낼 때 목적지 IP·포트 명시
- 수신 시 **목적지 포트만** 보고 소켓 결정 → 출발지가 달라도 목적지 IP·포트가 같으면 같은 소켓으로 감
- 예: 클라이언트 9157 → 서버 6428 요청, 응답은 출발지/목적지 포트가 뒤바뀐 6428 → 9157
### 연결지향 역다중화 (TCP)
- TCP 소켓은 **4-tuple**(출발지 IP, 출발지 포트, 목적지 IP, 목적지 포트)로 구분
- 서버는 클라이언트 연결마다 소켓을 따로 둬서 동시에 여러 연결 처리
- 예: 서버 B:80으로 오는 세그먼트 3개
  - A:9157 → P4, C:5775 → P5, C:9157 → P6
  - 목적지가 같아도 출발지가 다르면 다른 소켓
- 정리: UDP는 목적지 포트만, TCP는 4개 값 모두. 다중화/역다중화는 모든 계층에서 일어남.
### UDP
- IP에 다중화/역다중화 + 오류 검사만 추가. best-effort라 손실·순서 뒤바뀜 가능. 핸드셰이크 없이 세그먼트를 독립 처리.
- 쓰는 이유
  - 연결 설정이 없어 RTT 지연 없음
  - 연결 상태를 안 가져서 단순
  - 헤더가 작아 오버헤드 작음
  - 혼잡 제어가 없어 원하는 만큼 빨리 보냄
- 사용처: 스트리밍(손실 감내, 속도 민감), DNS, SNMP, HTTP/3
  - UDP 위에서 신뢰성이 필요하면 애플리케이션 계층에서 신뢰성·혼잡 제어를 추가(HTTP/3)
- RFC 768 (3페이지짜리)
### UDP 헤더 (각 16비트)
| 필드 | 설명 |
|---|---|
| Source port | 출발지 포트 |
| Dest port | 목적지 포트 |
| Length | 헤더 포함 세그먼트 전체 길이(바이트) |
| Checksum | 오류 검출 |
- 그 뒤에 애플리케이션 데이터(payload)
- 송신: 메시지 받기 → 헤더 값 결정 → 세그먼트 생성 → IP로 / 수신: 체크섬 검사 → 메시지 추출 → 소켓으로 역다중화
### UDP 체크섬
- 송신: 헤더 포함 세그먼트를 16비트 정수 열로 보고 **1의 보수 덧셈** → 결과를 **비트 반전**해서 체크섬 필드에 넣음
- 수신: 다시 계산해서 비교. 다르면 오류, 같으면 오류 없음으로 판단 (하지만 같아도 오류일 수 있음)
- 1의 보수 덧셈: 최상위 비트에서 캐리가 나오면 최하위에 다시 더함(wraparound)
```
  1110011001100110
+ 1101010101010101
------------------
 11011101110111011   ← 캐리 발생
  1011101110111100   ← wraparound (+1)
  0100010001000011   ← 체크섬 (비트 반전)
```
- 약점: 서로 다른 워드의 같은 자리 비트가 반대로 뒤집히면(한쪽 1→0, 다른 쪽 0→1) 합이 같아져 못 잡음 → 링크 계층·보안에서 보완
### UDP 요약
- 단순, 손실·비순서 가능한 best-effort
- 장점: 핸드셰이크 없음(RTT X), 서비스 특성에 맞춰 절충 가능, 체크섬으로 최소 신뢰성
- 필요한 기능은 위에서 직접 구현 (예: HTTP/3)
