> 미니어처 주차 환경에서 zero-shot 모델의 검출 실패 한계를 극복하기 위해 자체 데이터셋 구축부터 경량 모델 사전학습, TensorRT 엔진 최적화, 런타임 호모그래피 시점 보정까지 비전 파이프라인 전체를 구축함.

# 배경 — 왜 하게 됐나 ?
- 미니어처 주차장 관제 데모를 준비하면서 차량 검출 및 칸 점유 판정 비전 파이프라인 구축이 필요했음.
- 처음에는 별도 학습 없이 오픈소스 객체 검출 모델(COCO 사전학습 모델)의 zero-shot 추론이나 이미지 채도 기반 색상 검출로 차량을 인식하려고 했음.
- 하지만 실측 결과 두 방식 모두 완전히 실패함.
  - 채도 기반 방식 : 알록달록한 차는 쉽게 잡히지만 무채색(흰색 · 검정 · 은색 · 회색) 차는 바닥 매트와 채도 차이가 거의 없어 아예 검출되지 않음 (실제 F1 미니카 검출 누락 발생).
  - COCO zero-shot 검출기 : 수직 하향(탑뷰) 시점에서 미니카 11대를 배치하고 돌렸을 때 11대 중 0대 검출(0/11)로 단 한 대도 찾지 못함.
- 과거 실측에서도 카메라 시점이 다른 주차장으로 바뀌면 검출 정확도가 43.6%로 급락(미검출 기저율 수준)하고, 같은 주차장 다른 층에서도 49.1%로 떨어졌던 실측 기록이 있었음.
→ 따라서 사전학습 zero-shot에 기대지 않고 미니카 탑뷰 전용 데이터셋과 모델을 직접 구축하기로 결정함.
- 목표 :
  - 미니카 탑뷰 전용 경량 검출 모델 구축 및 엣지 임베디드 보드 실시간 추론 달성 (1초 1회 판정 주기 여유 있게 충족).
  - 카메라 물리적 밀림 및 시점 왜곡에 대응하는 런타임 자동 보정 체계 구축.
  - VLM, LLM, 검출기가 동시에 상주하는 엣지 환경에서 메모리 고갈 없이 90사이클 이상 안정 동작하는 E2E 파이프라인 검증.

# 환경
- 장비 :
  - 학습 서버 : GPU 서버 (A6000 48GB)
  - 엣지 보드 : 임베디드 보드 (Jetson Orin NX 16GB, 가용 메모리 15.6GB)
  - 센서 및 타깃 : 스마트폰 카메라(데이터 수집용 1280×720), 미니어처 주차 매트(25칸), 미니카 12대
- 소프트웨어 :
  - PyTorch, YOLOv8n, TensorRT FP16, OpenCV

# 진행 흐름
1. 사전학습 범위 축소 및 검출 방식 전환
	- 처음 계획 : 하드보드지와 고정 카메라 도착 시 빈 매트 사진과 차분하여 150 ~ 200장 규모의 데이터셋을 구축하고, 25개 칸 좌표까지 투영하여 칸 점유 판정까지 평가하려고 함.
	- 문제 발생 : 고정 장비 도착 지연으로 대기 상태 발생. 스마트폰 사진 9장(1280×720)으로 시험해보니 비스듬히 찍은 6장에서 종이 띠 들뜸으로 인해 단일 평면 투영 시 칸 위치가 반 칸가량 어긋남을 확인. 또한 150장 라벨링 공수는 일정상 너무 큼.
	- 검토한 대안과 버린 이유 :
	  - 개방형 어휘 검출기(OWLv2 등) : 텍스트 프롬프트로 검출 가능하나 탑뷰 미니카 인식 성능 미검증 및 별도 환경 필요로 배제.
	  - 칸 세그멘테이션 모델 별도 학습 : 고정 카메라는 1회 수동 지정으로 충분한데 세그멘테이션 라벨 추가 수집 부담 및 모델 오류 시 전체 판정 왜곡 위험으로 기각.
	- 바꾼 결정 : 사전학습 단계에서는 칸 좌표 정합을 배제하고 차량 바운딩 박스 라벨만 학습에 사용하기로 변경. 1차 수집 목표도 40장(학습 30장 · 평가 10장 · 박스 약 400개)으로 축소함 (단순 환경 · 데이터 증강 활용 · 점진적 초안 생성 활용 전제).
	→ 그래서 다음에 무엇을 하게 됐나 : 웹캠 환경에서 데이터 수집을 빠르게 하기 위한 자동 촬영 도구와 시점 보정 모듈을 미리 개발하기로 함.

2. 자동 촬영 도구 및 런타임 호모그래피 프레임 안정화 모듈 개발
	- 키보드/타이머 방식 대신 움직임 감지 자동 촬영 도구(`mini_capture.py --motion`) 구현. 프레임 차분으로 손 움직임을 감지하여 차를 옮기는 동안 대기하고, 손이 빠진 뒤 화면이 1.5초간 정지하면 자동 촬영 및 알림음 재생. 직전 저장 사진과 유사하면 중복 저장을 건너뛰는 필터 적용.
	- 고정 카메라용 빈 판 차분 초안 도구(`mini_draft_labels.py --from-empty`) 및 칸 재정렬 도구(`realign_slots.py`) 준비.
	- 런타임 프레임 안정화 모듈(`stabilize.py`) 개발 :
	  - 운영 중 카메라가 물리적으로 밀렸을 때 하위 모듈(칸 좌표, 판정, LED) 좌표계를 매번 동적 수정하면 잠재 결함 지점이 증가함.
	  - 따라서 입력 프레임을 역투영 호모그래피로 기준 빈 판 시점으로 되돌려 펴서 기존 파이프라인에 넘기는 방식 채택.
	  - 매 프레임 경량 검사 1 ~ 1.4ms 수행, 15초 주기로 정밀 비교(31ms) 수행.
	  - 동일한 이동이 1초 간격 2회 연속 감지되고 변환 후 칸 영역 일치성이 검증될 때만 보정 채택. 복원 불가한 큰 틀어짐이나 카메라 가림 발생 시 "카메라 위치 이상 — 재보정 필요" 경고 표출.
	  - 실사진 기반 합성 테스트 실측 : 카메라 1.5° 회전 및 18px 평행이동 시 기준 시점으로 정상 복원하여 칸 모서리 오차 0.1px 미만 달성.
	- 관련 도구들을 정리하여 로컬 테스트 615개 통과 확인 후 병합함.
	→ 그래서 다음에 무엇을 하게 됐나 : 실제 미니어처 사진을 촬영하여 데이터셋을 수집하고 라벨링 단계에 착수함.

3. 데이터 수집, 라벨링 가이드라인 정립 및 1차 학습
	- 스마트폰으로 촬영한 데이터셋 74장(245MB, 가로 12장 · 세로 8장 등) 수집.
	- 라벨링 가이드라인 정립 : 비스듬한 촬영 각도로 인해 주차선에 사각형을 맞추기 어려웠음. 주차선을 따라가지 않고 차체 외곽만 감싸는 반듯한 직사각형 박스로 라벨링하도록 기준 정리 (YOLO 포맷 `0 x y w h`, 단일 클래스 0). 비뚤어진 차량으로 인한 걸침 오판정 문제는 향후 걸침 임계값 재설정 단계로 분리.
	- 20장 수동 라벨링 완료 후 GPU 서버(A6000)에서 1차 학습 진행 (잡당 약 9분 소요).
	- 4장 홀드아웃 평가 (차 78대 실측) :
	  - 시점 증강 : 놓친 차 0대 · 오탐 6개 · 재현율 100% · 정밀도 92.9% · mAP50-95 0.53
	  - 기본 증강 : 놓친 차 0대 · 오탐 2개 · 재현율 100% · 정밀도 97.5% · mAP50-95 0.69
	  - 기본 증강 모델이 회전 증강 모델보다 차체에 꼭 맞는 박스를 학습함을 확인하고 기본 증강 모델 채택.
	- 1차 모델로 나머지 54장에 대해 초안 박스 1,197개 자동 생성. 직접 전수 검수한 결과 차량 누락 0건 확인, 화면 가장자리 손 및 배경 잡물 박스 6개만 삭제 완료 (1,188개 유지).
	→ 그래서 다음에 무엇을 하게 됐나 : 74장 전체 데이터셋으로 정밀 교차검증을 돌리고 엣지 배포 엔진으로 변환하기로 함.

4. 74장 시계열 교차검증 및 배포 엔진(TensorRT) 변환
	- 74장 전체 데이터셋에 대해 시계열 5-fold 교차검증 수행 (36분 소요) :
	  - 무작위 셔플 배제 : 연달아 촬영한 사진이 학습과 검증에 겹치면 점수가 부풀려지므로 촬영 순서대로 5묶음 분할 (2번 묶음은 세로 회전 사진 포함).
	  - 5-fold 교차검증 실측 (차 1,600대) :
	    - 기본 증강 : 놓친 차 3대 · 오탐 37개 · 재현율 99.8% · 정밀도 97.7% · mAP50-95 0.834
	    - 시점 증강 : 놓친 차 4대 · 오탐 54개 · 재현율 99.7% · 정밀도 96.7% · mAP50-95 0.789
	    - 기본 증강 모델이 5개 묶음 모두에서 일관되게 우수함을 확인하고 최종 가중치(`best.pt`) 도출.
	- 엣지 보드(Jetson Orin NX) 상에서 TensorRT FP16 엔진 변환 :
	  - 입력 해상도 640, 변환 소요 359초, 엔진 크기 9.1MB.
	  - 추론 속도 실측 : 원본 PyTorch p50 24.5ms (37.5 FPS, p95 37.4ms) → TensorRT 엔진 p50 22.5ms (44.6 FPS, p95 22.9ms)로 단축. 1초 1회 판정 주기 여유 있게 충족.
	  - 정확도 유지 검증 : 74장 라벨 대조 시 놓친 차 2대로 원본과 동일, 신뢰도 하위 오탐 14개가 걸러져 오탐 25건 → 11건으로 감소.
	- 로컬 테스트 645개 통과 및 CI 검증 통과(1분 1초).
	→ 그래서 다음에 무엇을 하게 됐나 : 단독 검출기 측정을 넘어 실제 엣지 보드에서 파이프라인 전체를 통합 시험함.

5. Jetson 격리 E2E 통합 파이프라인 검증 및 런타임 결함 수정
	- 시연용 배포본과 분리된 별도 격리 환경에서 새 검출 엔진 탑재 후 90사이클(94초) E2E 파이프라인 실기 가동.
	- 실측 결과 : 실행 오류 0건, 25칸 중 23칸 점유, 위반 4건 정상 분석.
	- 메모리 실측 : VLM+LLM 상주 상태에서 초기 11.2GB → 피크 12.4GB, 최소 2.9GB 여유 메모리 확보 (전체 15.6GB, 메모리 고갈 위험 해소). VLM 문장 생성은 건당 5.5 ~ 6.5초 소요되나 백그라운드 비동기 처리로 1초 판정 주기를 막지 않음.
	- 결함 발견 및 수정 : VLM 근거 문장이 흰 테이프 주차선을 "노란 선"으로 오인하거나 바닥 인쇄 번호를 읽어 "주차칸 16" 등 내부 번호를 노출하는 결함 확인. 프롬프트 지시어 수정, 칸 번호 정규식 필터링, 재질의 피드백 로직 추가, 시간대 누락(`+09:00`) 및 빈 전용 칸 집계 결함 수정.
	- 코드 리뷰 9개 지적 사항(숫자 필터 과잉 차단 완화, 선 · 색상 표현 세분화 등) 반영 후 로컬 테스트 667개 통과, 최종 CI 통과(1분 4초) 및 병합.

# 트러블슈팅
## 1. 매트 국소 왜곡 오탐 결함
- 현상 : 칸 재정렬 도구(`realign_slots.py`) 시험 중 매트 중앙의 종이 띠 한 줄만 밀린 상황에서 특징점 매칭이 '정렬 성공'을 반환함.
- 원인 : 전체 화면 기준 호모그래피 매칭은 국소 영역 왜곡을 단일 평면으로 뭉개어 인식함.
- 해결 : 칸별 이미지 패치 유사도(정상 0.77 이상, 왜곡 0.08 이하)를 검증하는 단계를 추가하여 0.4 임계값 미만인 밀린 9개 칸(B01 ~ B09)을 짚어내고 재정렬을 거부하도록 안전장치 구축.
- 결과 : 국소 왜곡 발생 시 조용히 왜곡된 좌표를 저장하지 않고 해당 칸을 정확히 짚어내며 재정렬 거부 확인.

## 2. 시점 증강 모델의 박스 헐렁임 결함
- 현상 : 회전 · 원근을 추가한 시점 증강 모델이 기본 증강 모델보다 박스 정확도(mAP50-95)가 떨어짐 (1차 4장 평가 : 0.53 vs 0.69, 74장 교차검증 : 0.789 vs 0.834).
- 원인 : 회전된 이미지에서 축 정렬 바운딩 박스를 칠 때 차체 외곽 주위의 빈 배경 영역이 넓어져 박스가 헐렁하게 학습됨.
- 해결 : 시점 증강 대신 기본 증강(상하 · 좌우 반전, 크기 변화, 색상 변화)을 표준 학습 파이프라인으로 채택.
- 결과 : 5개 교차검증 묶음 전체에서 재현율 99.8%, 정밀도 97.7%, mAP 0.834로 일관된 성능 우위 확보.

## 3. VLM 위반 설명의 환각 및 내부 정보 노출
- 현상 : VLM 위반 설명 문장에 실제 존재하지 않는 "노란 선" 표현이 등장하거나 바닥 인쇄 번호를 읽어 "주차칸 16" 등 내부 번호가 노출됨.
- 원인 : 기본 프롬프트가 일반 도로 주차장 기준 표현을 포함하고 있었고 OCR 성격의 번호 판독이 필터링 없이 문장에 반영됨.
- 해결 : 프롬프트 지시어를 '주차칸 · 통로'로 구체화하고 칸 번호 정규식 필터링을 구축하여 감지 시 거부 사유 피드백과 함께 재질의하도록 로직 보강.
- 결과 : 1회차 오판 시 거부 이유를 전달받아 2회차에서 정상 문장("차량이 주차칸 경계를 넘어섰다.") 도출 확인.

# 결과
- 숫자로 (전 → 후) :
  - 검출률 : 기존 zero-shot 탑뷰 미니카 0% (0/11대) → 자체 데이터셋 74장 5-fold 교차검증 재현율 99.8% (1,600대 중 3대 놓침), 정밀도 97.7%, mAP50-95 0.834 달성.
  - 엣지 추론 속도 : PyTorch 원본 p50 24.5ms (37.5 FPS) → TensorRT FP16 p50 22.5ms (44.6 FPS, 8.2% 단축), 오탐 25건 → 11건으로 14건 감소 (놓친 차 2대 동일 유지).
  - 런타임 안정성 : 격리 E2E 90사이클 94초 무오류 가동, 메모리 피크 12.4GB (최소 여유 2.9GB / 15.6GB 확보), 1.5° 회전 및 18px 이동 시 0.1px 미만 복원.
- 아직 안 된 것 / 다음에 할 것 :
  - 고정 웹캠 도착 후 미니어처 판 위 최종 위치 고정 및 빈 판 기준점 설정.
  - 실제 웹캠 입력 환경에서 칸 점유 정확도(목표 95% 이상) 및 걸침 30케이스 재실측.
  - 최종 실측 검증 후 배포 모델 설정 교체.

# 배운 점
- 도메인 특화 환경(미니카 탑뷰)에서는 범용 zero-shot 모델에 기대지 말고 소량 수동 라벨링과 자체 점진적 학습으로 전환하는 편이 훨씬 빠르고 확실함.
- 시점 변화에 대응할 때 모델 학습 증강에만 의존하면 박스가 헐렁해지는 부작용이 생기므로 런타임 호모그래피 역투영처럼 시스템 레벨에서 프레임을 정렬하는 기하학적 보정이 더 견고함.
