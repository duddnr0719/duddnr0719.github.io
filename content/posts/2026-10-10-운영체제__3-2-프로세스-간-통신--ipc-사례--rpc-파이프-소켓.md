> IPC는 공유 메모리(빠르지만 동기화는 직접)와 메시지 패싱(커널 경유, 안전) 두 갈래. 메시지 패싱은 직접/간접, 블로킹/논블로킹, 버퍼 용량으로 나뉘고, 실제 구현으로 POSIX shm, Mach, Windows LPC, RPC, 파이프, 소켓이 있다.
### IPC 개요
- 프로세스끼리 데이터를 주고받는 메커니즘. 커널이 시스템 호출 형태로 도구를 제공
- 협력 프로세스를 구현하려면 반드시 필요 (정보 공유, 계산 가속, 모듈성, 편의성)
| | 메시지 패싱 | 공유 메모리 |
|---|---|---|
| 방식 | 커널을 거쳐 send/receive | 같은 메모리 영역을 직접 읽고 씀 |
| 커널 개입 | 매번 | 처음 영역 설정 때만 |
| 속도 | 느림 | 빠름 (모드 전환 비용 없음) |
| 동기화 | 커널이 처리 | 프로그래머가 직접 (동시 접근 시 데이터 깨짐) |
### 생산자-소비자 (복습)
- 버퍼가 꽉 차면 생산자 대기, 비면 소비자 대기, 동시에 접근하면 충돌 위험 → 해결: 공유 메모리/메시지 패싱 + 세마포어/모니터
- 공유 메모리 버전은 원형 큐: `in == out`이면 빔, `(in + 1) % SIZE == out`이면 가득 (한 칸은 비워둠 → SIZE − 1개 사용)
### POSIX 공유 메모리
- `shm_open(name, O_CREAT | O_RDWR, 0666)`: 세그먼트 생성 (이미 있으면 그걸 엶)
- `ftruncate(fd, 4096)`: 크기 설정
- `mmap()`: 프로세스 주소 공간에 매핑 → 이후 포인터로 읽고 씀
- 간단하지만 동기화는 직접 해야 함
```c
/* producer.c — 공유 메모리 "OS"에 "HelloWorld!" 쓰기 */
#include <stdio.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/mman.h>
#include <sys/stat.h>

int main() {
    const int SIZE = 4096;
    const char *name = "OS";
    const char *message_0 = "Hello";
    const char *message_1 = "World!";

    int shm_fd = shm_open(name, O_CREAT | O_RDWR, 0666);   /* 생성 */
    ftruncate(shm_fd, SIZE);                                /* 크기 */
    char *ptr = mmap(0, SIZE, PROT_WRITE, MAP_SHARED, shm_fd, 0);

    sprintf(ptr, "%s", message_0);  ptr += strlen(message_0);
    sprintf(ptr, "%s", message_1);  ptr += strlen(message_1);
    return 0;
}
```
```c
/* consumer.c — 읽고 나서 삭제 */
#include <stdio.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <sys/stat.h>

int main() {
    const int SIZE = 4096;
    const char *name = "OS";
    int shm_fd = shm_open(name, O_RDONLY, 0666);
    char *ptr = mmap(0, SIZE, PROT_READ, MAP_SHARED, shm_fd, 0);
    printf("%s\n", ptr);
    shm_unlink(name);              /* 공유 메모리 객체 제거 */
    return 0;
}
```
- 실행: `gcc producer.c -o prod -lrt && gcc consumer.c -o cons -lrt && ./prod && ./cons` → `HelloWorld!`
- 슬라이드 원본엔 `<sys/mman.h>`, `<unistd.h>`가 빠져 있어서 추가함. `void *`에 `+=`는 GCC 확장이라 `char *`로 바꿈
### 메시지 패싱
- 통신 링크 구현
  - 물리적: 공유 메모리, 하드웨어 버스, 네트워크
  - 논리적: 직접/간접, 동기/비동기, 자동/명시적 버퍼링
- **직접 통신**: 상대 이름을 명시 `send(P, msg)`, `receive(Q, msg)`
  - 링크 자동 설정, 정확히 한 쌍에 하나의 링크, 보통 양방향
- **간접 통신**: 메일박스(포트)를 거침 `send(A, msg)`, `receive(A, msg)`
  - 메일박스마다 고유 ID, 메일박스를 공유해야 통신 가능
  - 한 메일박스에 여러 프로세스, 두 프로세스가 여러 메일박스 공유 가능, 단방향 또는 양방향
  - 연산: 생성, 송수신, 삭제
  - 문제: P1이 A에 보내고 P2, P3가 동시에 receive하면 누가 받나?
    - 링크를 최대 2개 프로세스로 제한 / 한 번에 하나의 receive만 허용 / 시스템이 임의로 고르고 발신자에게 알림
- **동기화**
  - 블로킹 send: 상대가 받을 때까지 대기 / 블로킹 receive: 메시지 올 때까지 대기
  - 논블로킹 send: 보내고 바로 진행 / 논블로킹 receive: 있으면 받고 없으면 null
  - 블로킹 send + 블로킹 receive = **랑데부(rendezvous)**
- 생산자-소비자가 아주 간단해짐: 생산자는 `send(next_produced)`, 소비자는 `receive(next_consumed)` 반복
- **버퍼링** (링크에 붙은 메시지 큐)
  - 0 용량: 큐 없음 → 랑데부 (발신자는 수신까지 대기)
  - 유한 용량: 최대 n개, 차면 발신자 대기
  - 무한 용량: 발신자는 절대 대기 안 함
### IPC 사례
- **Mach** (macOS의 기반 마이크로커널): 모든 게 메시지, 시스템 호출조차 메시지
  - 태스크는 생성 시 커널 메일박스 + 알림 메일박스 2개로 시작, 추가 포트는 `port_allocate()`
  - 시스템 호출은 `msg_send()`, `msg_receive()`, `msg_rpc()` 3개뿐
  - 메일박스가 가득 찼을 때 옵션: 무한 대기 / n ms 대기 / 즉시 반환 / 커널에 임시 캐싱
- **Windows LPC** (Local Procedure Call): 같은 시스템 내 통신, 포트 사용
  1. 클라이언트가 서버의 연결 포트를 엶
  1. 연결 요청 전송
  1. 서버가 통신 포트 2개를 만들고 하나를 클라이언트에 반환
  1. 각자의 포트로 메시지·콜백 교환
  - 작은 메시지(256B 이하)는 포트의 메시지 큐로, 큰 메시지는 공유 섹션 객체로 전달
### RPC (원격 프로시저 호출)
- 네트워크 너머 프로세스의 함수를 로컬 함수처럼 호출
- **스텁(stub)**: 양쪽의 프록시
  - 클라이언트 스텁: 서버를 찾고 매개변수를 네트워크 표준 형식으로 변환(**마샬링**)
  - 서버 스텁: 메시지를 받아 복원(**언마샬링**)하고 실제 함수 호출
  - Windows는 MIDL로 스텁 생성
- 실패가 많음(타임아웃, 서버 크래시) → 전달 의미론: **최대 한 번** vs **정확히 한 번**(보장 어려움)
- 포트 찾기: 클라이언트 → 커널 → **matchmaker(랑데부 데몬)** 에 "RPC X의 포트?" → 포트 P 응답 → 커널이 P로 RPC 전송 → 서버 데몬 처리 → 결과 반환
### 파이프
- 한 프로세스에서 다른 프로세스로 데이터를 흘려보내는 가상의 관
  - 기본은 한쪽 방향(half duplex), 양방향이면 파이프 2개
  - 보낸 순서대로 받음, 용량 제한이 있어 가득 차면 쓰기 대기
- 셸의 `|`: 앞 명령의 stdout → 뒤 명령의 stdin (커널이 일반 파이프 생성)
  - `ps -ef | grep python`, `ls -l | wc -l`, `cat file.txt | sort | uniq`, `who | sort`
- **일반 파이프**: 만든 프로세스 밖에선 접근 불가 → 부모가 만들고 fork한 자식과 통신 (Windows: 익명 파이프)
  1. `pipe(fd)`: `fd[0]` 읽기용, `fd[1]` 쓰기용
  1. `fork()`: 자식도 fd를 복사받음
  1. 안 쓰는 끝 닫기: 부모 `close(fd[0])`, 자식 `close(fd[1])`
  1. 부모가 `fd[1]`에 쓰고 자식이 `fd[0]`에서 읽음
```c
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>
#define READ_END 0
#define WRITE_END 1

int main() {
    char write_msg[] = "hello world";
    char read_msg[32];
    int fd[2];
    if (pipe(fd) == -1) { fprintf(stderr, "Pipe failed"); return 1; }

    pid_t pid = fork();
    if (pid > 0) {                          /* 부모: 쓰기 */
        close(fd[READ_END]);
        write(fd[WRITE_END], write_msg, strlen(write_msg) + 1);
        close(fd[WRITE_END]);
        wait(NULL);
    } else {                                /* 자식: 읽기 */
        close(fd[WRITE_END]);
        read(fd[READ_END], read_msg, sizeof(read_msg));
        printf("read %s\n", read_msg);      /* read hello world */
        close(fd[READ_END]);
    }
    return 0;
}
```
| | 일반 파이프 | 명명된 파이프 (FIFO) |
|---|---|---|
| 방향 | 단방향 | 양방향 가능 (UNIX FIFO는 반이중, Windows는 전이중) |
| 관계 | 부모-자식 필수 | 아무 프로세스나 |
| 접근 | fd | 파일 이름 (`/tmp/myfifo`) |
| 수명 | 프로세스 종료 시 사라짐 | 명시적으로 지울 때까지 |
| 생성 | `pipe(fd)` | `mkfifo()` / `CreateNamedPipe()` |
### 소켓
- 네트워크 통신의 끝점(endpoint) = **IP 주소 + 포트 번호**. 두 소켓 사이에서 통신
- 포트는 OS가 제공하는 추상 개념. 상대 위치에 독립적 (로컬 `127.0.0.1` 루프백도, 원격도 가능)
  - 예: 호스트 146.86.5.20:1625 ↔ 웹 서버 161.25.19.8:80
- Java 소켓: `Socket`(TCP, 연결형, 신뢰성), `DatagramSocket`(UDP, 비연결, 빠름), `MulticastSocket`(여러 수신자에게 동시에)
```java
import java.net.*;
import java.io.*;

public class DateServer {
    public static void main(String[] args) {
        try {
            ServerSocket sock = new ServerSocket(6013);
            while (true) {                                  /* 연결 대기 */
                Socket client = sock.accept();
                PrintWriter pout = new PrintWriter(client.getOutputStream(), true);
                pout.println(new java.util.Date().toString()); /* 날짜 전송 */
                client.close();
            }
        } catch (IOException ioe) {
            System.err.println(ioe);
        }
    }
}
```
- 테스트: `java DateServer` 실행 후 다른 터미널에서 `nc localhost 6013` → 현재 날짜 출력
