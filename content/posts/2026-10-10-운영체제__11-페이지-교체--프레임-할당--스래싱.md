> 빈 프레임이 없으면 희생자를 골라 내보낸다. FIFO(15) > LRU(12) > OPT(9) 순으로 폴트가 적고, 현실에선 LRU를 참조 비트로 흉내 낸 클락 알고리즘을 쓴다. 프로세스에 프레임이 너무 적으면 교체만 하다 멈추는 스래싱 → 작업 집합·PFF로 프레임 수를 조절.
### 페이지 교체가 필요한 이유
- 예: 프레임 40개, 프로세스 6개(각 10페이지, 평소엔 5페이지만 씀) → 평소엔 30개로 충분하지만, 다들 10페이지가 필요해지는 순간 프레임 부족 (과다 할당)
- 커널, I/O 버퍼도 메모리가 필요 → 어디에 얼마나 줄지가 쟁점
- 해결: 실제로 안 쓰는 페이지를 디스크로 내보내는 **페이지 교체**. 목표는 폴트 수 최소화, 같은 페이지가 들락날락하면 최악
- **수정(dirty) 비트**: 올라온 뒤 바뀌었는지 표시 → 안 바뀐 페이지는 디스크에 다시 쓸 필요 없이 그냥 덮어씀 (I/O 절반)
### 기본 페이지 교체
1. 디스크에서 원하는 페이지 위치를 찾음
1. 빈 프레임 확보: 있으면 사용, 없으면 교체 알고리즘으로 **희생자(victim)** 선정 → 수정됐으면 디스크에 기록 → 그 페이지 테이블 항목을 i로
1. 원하는 페이지를 읽어와 프레임·페이지 테이블 갱신 (v로)
1. 중단된 프로세스 재개
- 빈 프레임이 없으면 폴트 한 번에 디스크 I/O가 2번(쓰기 + 읽기)
### 알고리즘 평가
- 결정해야 할 것 두 가지: 프로세스마다 프레임 몇 개(프레임 할당), 누구를 내보낼지(페이지 교체)
- **참조 문자열**: 메모리 접근 순서를 페이지 번호로만 나열. 바로 이어서 같은 페이지를 다시 참조하면 폴트가 나지 않으니 하나로 봄
- 그 문자열에서 폴트 수를 세서 비교. 보통 프레임이 늘면 폴트가 줄어듦
- 공통 예: `7 0 1 2 0 3 0 4 2 3 0 3 0 3 2 1 2 0 1 7 0 1`, 프레임 3개
### FIFO
- 가장 먼저 들어온 페이지를 내보냄 (FIFO 큐)
- 예제: **15번** 폴트
- **Belady의 모순**: 프레임을 늘렸는데 폴트가 오히려 늘어나는 현상
  - `1 2 3 4 1 2 5 1 2 3 4 5` → 프레임 3개: 9번, 프레임 4개: **10번**
### 최적 (OPT)
- **앞으로 가장 오랫동안 안 쓰일** 페이지를 내보냄
- 예제: **9번** (최소, Belady 모순 없음)
- 미래를 알아야 해서 구현 불가 → 다른 알고리즘의 성능 비교 기준(벤치마크)으로 사용
### LRU (Least Recently Used)
- OPT가 미래를 본다면 LRU는 과거를 봄: **가장 오랫동안 안 쓰인** 페이지를 내보냄 (지역성: 최근에 안 쓴 건 앞으로도 안 쓸 것)
- 예제: **12번** (FIFO보다 좋고 OPT보다 나쁨)
- 위 Belady 예에서도 프레임 3개 10번 → 4개 8번으로 단조 감소
- 구현
  - 카운터: 페이지 테이블 항목마다 마지막 참조 시각을 기록, 교체할 때 가장 작은 값 검색 → 매번 전체 탐색
  - 스택: 페이지 번호의 이중 연결 리스트, 참조할 때마다 맨 위로 이동(포인터 최대 6개 갱신) → 맨 아래가 희생자라 탐색은 필요 없음
  - 둘 다 메모리 참조마다 갱신이 필요해 하드웨어 지원 없이는 너무 느림
- LRU와 OPT는 **스택 알고리즘**(프레임 n개일 때의 페이지 집합 ⊂ n + 1개일 때의 집합) → Belady 모순이 생기지 않음
### LRU 근사
- **참조 비트**: 페이지마다 1비트(처음 0), 참조되면 하드웨어가 1로. 0인 페이지부터 교체. 하지만 1인 것끼리의 순서는 모름
- **두 번째 기회(클락) 알고리즘**: FIFO + 참조 비트, 포인터가 원형 큐를 돌며
  - 비트 0 → 교체
  - 비트 1 → 0으로 바꾸고 한 번 봐줌, 다음 페이지로
  - 한 바퀴 돌아 다시 오면 0이니 교체 (모두 1이면 결국 FIFO)
- **향상된 두 번째 기회**: (참조 비트, 수정 비트)로 4등급
| (참조, 수정) | 의미 | 우선순위 |
|---|---|---|
| (0, 0) | 최근에 안 썼고 안 바뀜 | 1순위 교체 (쓰기 없이 바로) |
| (0, 1) | 최근엔 안 썼지만 바뀜 | 2순위 (디스크 기록 필요) |
| (1, 0) | 최근에 썼고 안 바뀜 | 곧 다시 쓸 듯 |
| (1, 1) | 최근에 썼고 바뀜 | 마지막 |
- **카운팅**: 참조 횟수로 — LFU(가장 적게 쓴 것 교체), MFU(가장 많이 쓴 것 교체). 구현 비용이 크고 OPT에 잘 근접하지 못해 흔하지 않음
- **페이지 버퍼링**: 빈 프레임 풀을 항상 n개 이상 유지 → 폴트가 나면 바로 빈 프레임에 읽어오고, 희생자는 풀에 넣었다가 한가할 때 디스크에 기록
### 응용 프로그램과 교체
- DB 같은 프로그램은 자기 접근 패턴을 OS보다 잘 앎
- OS도 I/O 버퍼에 사본을 두고 앱도 자체 버퍼에 같은 데이터를 두면 **이중 버퍼링**으로 메모리 낭비
- 해결: 파일 시스템·OS 버퍼를 거치지 않는 **raw 디스크 모드**로 직접 블록 I/O
### 프레임 할당
- 예: 프레임 128개, OS가 35개 → 93개 사용 가능. 순수 요구 페이징이면 93개가 차고 94번째 폴트부터 교체
- 프로세스 P1(86페이지), P2(92페이지)에 몇 개씩 줄까?
- **고정(정적) 할당**: 시작할 때 정하고 실행 중엔 안 바꿈
  - 균등 할당: 크기와 상관없이 똑같이 (93개를 46개씩, 1개는 버퍼 풀)
  - 비례 할당: 크기에 비례 (A 6페이지, B 3, C 9 → 4, 2, 6개). 큰 프로그램이 오면 작은 프로그램이 거의 못 받음
- **동적 할당**: 실행 중 요구와 다중 프로그래밍 정도에 따라 조절
  - 작업 집합 모델: 최근 일정 기간 참조한 페이지들을 메모리에 유지 (아래)
  - **PFF(페이지 부재 빈도)**: 프로세스별 폴트율을 측정 → 상한을 넘으면 프레임 추가, 하한보다 낮으면 회수
### 전역 교체 vs 지역 교체
| | 전역 (global) | 지역 (local) |
|---|---|---|
| 희생자 후보 | 모든 프로세스의 모든 프레임 | 자기에게 할당된 프레임만 |
| 장점 | 처리량이 좋아 흔히 사용 | 다른 프로세스 영향 없음, 성능 일관 |
| 단점 | 다른 프로세스 때문에 실행 시간이 들쭉날쭉, 프레임을 뺏긴 쪽에서 스래싱 연쇄 가능 | 자주 쓰는 페이지도 자기 안에서만 돌려써야 해서 메모리를 덜 효율적으로 씀 |
### NUMA
- CPU와 메모리가 여러 보드에 나뉘어 있고 버스로 연결 → 같은 보드의 메모리가 훨씬 빠름
- 최적화: 스레드가 도는 CPU 근처 메모리를 할당, 스레드를 가능한 한 같은 보드의 CPU에서 스케줄링
### 스래싱 (Thrashing)
- 프로세스가 실행보다 **페이지 교체(스왑 인/아웃)에 대부분의 시간**을 쓰는 상태
- 원인: 실행에 필요한 최소 프레임을 못 받음
  1. 폴트 → 페이지를 가져오려고 기존 프레임을 내보냄
  1. 내보낸 페이지가 곧바로 다시 필요해짐 → 또 폴트 …
  - `a[i]`에서 폴트, `a[i + 1]`에서 또 폴트. 메모리는 꽉 찼는데 CPU 이용률은 20%
- 악순환: CPU 이용률이 떨어짐 → OS는 다중 프로그래밍 정도를 높이려고 프로세스를 더 넣음 → 프레임이 더 부족 → 더 심해짐
- 다중 프로그래밍 정도 vs CPU 이용률 그래프: 올라가다가 어느 순간 **급락**
### 지역성 모델과 작업 집합
- 프로세스는 함께 쓰는 페이지 묶음(**지역성**)을 쓰다가 다른 지역성으로 옮겨감. 지역성끼리 겹칠 수 있음
- 스래싱은 **모든 프로세스의 지역성 크기 합 > 물리 메모리**일 때 발생
- **작업 집합 윈도우 Δ**: 최근 참조 Δ개 (예: 10,000번)
  - WS(t): 시점 t에서 최근 Δ 동안 참조된 페이지들의 집합, WSSᵢ = 그 크기
  - 작업 집합 안의 페이지는 곧 다시 쓰일 것, 밖으로 밀려난 페이지는 안 쓰일 것이라 가정
  - Δ가 너무 작으면 지역성을 다 못 담고, 너무 크면 여러 지역성이 섞임
- 예: 참조열 `… 2 6 1 5 7 7 7 5 1 6 2 3 4 1 2 3 4 4 4 3 4 3 4 4 4 1 3 2 3 4 4 4 3 4 4 4 …`, Δ = 10
  - WS(t₁) = {1, 2, 5, 6, 7} (5개)
  - WS(t₂) = {3, 4} (2개)
- 활용: D = Σ WSSᵢ (전체 요구량)가 가용 프레임 수를 넘으면 프로세스 하나를 중단(스왑 아웃)시켜 스래싱을 막고, 여유가 있으면 새 프로세스를 들임
