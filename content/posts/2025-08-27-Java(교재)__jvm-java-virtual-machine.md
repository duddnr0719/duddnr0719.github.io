# JVM(Java Virtual Machine)
<callout>
💡JVM(Java Virtual Machine)<br><br>- 자바 프로그램을 실행하기 위한 가상 머신. 이를 통해 자바로 작성된 프로그램을 특정 운영 체제에 종속되지 않고 실행할 수 있도록 한다.
</callout>

### JVM 동작 과정

<column ratio="50">
<callout>

</callout>

1. 컴파일(Compile)
<callout>
- 자바 프로그램을 실행하는 시점에 자바 소스 코드(.java)를 컴파일러(javac)를 통해 바이트 코드(.class)로 변환을 수행한다.<br><br>- 변환된 바이트 코드는 플랫폼에 대해 독립적이며 JVM이 실행할 수 있는 언어로 변환을 한다.<br>- 해당 과정은 Java Source File(java) \> (Java Compiler) \> Java Byte Code(class)에서 수행한다.
</callout>

1. 클래스 로딩(Class Loading)
<callout>
- JVM에 컴파일된 바이트 코드를 읽고 메모리에 로드를 수행한다.<br><br>- 해당 메모리가 로드되는 시점은 파일을 실행(Runtime)할 때이며 Runtime Data Area를 로드한다.<br>- 해당 과정은 Java Byte Code(Class) \> Class Loader에서 수행한다.
</callout>

<details>
<summary>💡 메모리를 로딩한다는 것은 무엇일까?</summary>
→ JVM이 자바 프로그램을 실행하기 위해 필요한 클래스와 객체들을 메모리에 옮기는 과정.
이를 통해 자바 프로그램이 실행될 때 필요한 데이터와 코드가 메모리에 준비되어 실행될 수 있게 된다.
</details>

1. 메모리 할당(Memory Allocation)
<callout>
- 메모리에 로딩되어 온 데이터나 코드들에 대해 Runtime Data Area의 크기에 맞게 메모리를 할당 및 부여하는 것을 수행한다.<br><br>- 메모리 할당은 주로 힙 영역에 객체나 배열이 생성될 때 객체의 크기에 맞게 힙 영역에 메모리를 할당한다.<br>- 해당 과정은 Class Loader \> Runtime Data Area에서 수행된다.
</callout>

1. 바이트 코드 해석 및 실행(Byte Code Interpretation and Runtime)
<callout>
- JVM의 클래스 파일의 바이트 코드를 해석하여 명령어를 수행하는 역할.<br><br>- 해당 역할을 Execution Engine의 Interpreter와 JIT(Just-In-Time)가 수행을 하며 네이티브 코드에 대한 해석은 Native Method Interface, Native Method Library에서 수행한다.<br>- 이때 JVM은 스택 기반의 가상머신으로 동작하여 스택 프레임을 사용하여 메소드 호출과 반환을 관리한다.<br>- JVM 내에서 Runtime Data Area와 Execution Engine(JIT, Interpreter)에서 수행한다.
</callout>

4.1 인터프리터(Interpreter)의 바이트 코드 수행 및 실행 과정
<callout>
💡 인터프리터(Interpreter) : Java 프로그램을 싱행하기 위해 바이트 코드를 한 줄씩 해석하는 도구<br>→ 이를 통해 Java 소스 코드를 컴파일하여 생성된 바이트 코드를 실행<br><br>💡 인터프리터 수행 과정<br><br>1. 이전에 생성하고 할당된 메모리를 기반으로 바이트 코드를 읽어온다<br><br>2. 인터프리터를 통해 바이트 코드를 한 줄씩 읽고 해석한다.<br><br> 3. 바이트 코드를 해석하는 동안 인터프리터는 필요한 메모리 및 리소스를 할당하고 해당 바이트 코드에 따라 실행한다.<br><br>4. 바이트 코드가 실행되는 동안 인터프리터는 필요한 경우에 따라 라이브러리 및 다른 클래스를 로드하고 사용한다.<br><br>5. 인터프리터는 바이트 코드를 순차적으로 해석하면서 프로그램을 실행한다.
</callout>

4.2 JIT(Just-In-Time)의 바이트 코드 수행 및 실행 과정
<callout>
💡 JIT(Just-In-Time) : Java 프로그램을 싱행하고 실행 패턴을 분석하고 최적화하는 동적 컴파일 기술.<br>→ 해당 기술은 프로그램을 실행하는 동안 실시간으로 바이트 코드를 기계어로 변환 ⇒ 성능 향상.<br>→ 코드를 인터프리터 방식으로 실행하는 것보다 더 빠른 실행 속도를 제공할 수 있다.<br><br>💡 JIT 수행 과정<br><br>1. 이전에 생성하고 할당된 메모리를 기반으로 바이트 코드를 읽어온다.<br><br>2. JIT 컴파일러는 실행 중인 프로그램을 모니터링하면서 빈번하게 실행되는 코드 블록을 식별하나.<br><br>3. 해당 코드 블록은 인터프리터에 의해 실행될 때마다 JIT 컴파일러에 의해 기계어로 변환된다.<br><br>4. JIT 컴파일러는 변환된 기계어 코드를 캐시에 저장한다.<br><br>5. 이후 동일한 코드 블록이 다시 호출되면, 캐시에 저장된 기계어 코드를 실행하여 인터프리터에 비해 훨씬 바른 실행 속도를 제공한다.
</callout>

1. 가비지 컬렉션(GC, Garbage Collection)
<callout>
- JVM에서 더 이상 사용되지 않은 객체를 자동으로 감시하고 메모리에서 자동으로 해제하는 역할을 수행한다.<br>     → 이를 통해 메모리 관리를 최적화할 수 있다.<br><br>- JVM 내에서 Execution Engine(Garbage Collection)에서 수행한다.
<br>💡가비지 컬렉션의 동작 과정<br><br>1. Marking(표시) : 가비지 컬렉터는 모든 객체를 스캔하고 참조되는 객체들을 표시한다. <br>→ 이 과정에서 도달 가능한 객체들은 표시된다.<br><br>2. Sweeping(정리) : 가비지 컬렉터는 표시되지 않은 객체들을 메모리에서 제거한다.<br>→ 이러한 객체들은 도달할 수 없는 객체로 간주되며 가비지로 처리된다.<br><br>3. Compacting(압축) : 가비지 컬렉터는 메모리에서 제거된 객체들로 인해 생긴 빈 공간을 모아서 압축한다.<br>→ 이렇게 함으로써 메모리의 단편화를 최소화하고, 연속된 메모리 공간을 확보한다.
</callout>

1. 예외 처리(Exception Handling)
<callout>
- 프로그램 실행 도중 발생하는 예기치 않은 상황.<br>     → 예외가 발생하면 JVM은 해당 예외를 적절히 처리하고 예외 상황에 대한 적절한 조치를 취한다.<br><br>- JVM은 예외 처리를 위해 예외 핸들러를 사용한다.
     → 예외가 발생했을 때 해당 예외를 처리할 수 있는 예외 핸들러를 찾아 처리한다.<br><br>💡예외 처리 과정<br><br>1. 예외 발생 : 프로그램이 실행 중에 예외가 발생<br><br>2. 예외 객체 생성 : 예외가 발생하면 JVM은 해당 예외를 나타내는 예외 객체를 생성한다.
이 객체는 예외의 유형, 메세지 및 예외가 발생한 위치 정보를 포함한다.

3. 예외 처리 : JVM은 예외를 적절히 처리하기 위해 예외 처리기(Exception Handler)를 찾는다.
예외 처리기는 예외를 처리하는 코드 블록 ⇒ 예외를 처리하는 방법을 정의한다.

4. 예외 전파 : 예외 처리기가 발견되지 않거나 처리하지 못한 경우 예외는 현재 실행 중인 메소드에서 호출한 메소드로 전파된다.
이 과정은 메소드 호출 스택을 따라 올라간다.

5. 예외 처리기 찾기 : 예외는 예외를 전파한 메소드의 호출자에게 전달된다.
JVM은 호출자 메소드에서 예외 처리기를 찾는데, 이 과정은 호출자 메소드의 호출자로 계속해서 진행된다.

6. 예외 처리 : 예외 처리기가 발겨노디면 예외 처리기의 코드 블록이 실행된다.
예외 처리기는 예외를 처리하거나 예외를 다시 던지는 등의 작업을 수행할 수 있다.

7. 예외 체인 : 예외 처리기가 에외를 다시 던지는 경우 예외는 다시 호출자로 전파되며 이 과정은 호출자 메소드의 호출자로 계속해서 진행된다.
→ 이렇게 예외가 여러 단계로 전파되는 구조를 예외 체인(Exception Chaining)이라고 한다.
</callout>

1. 프로그램 종료(End of Program)
<callout>
- 프로그램 실행이 완료되거나 명시적으로 종료되면 JVM은 사용한 메모리를 반환하고 자원을 정리한다.<br><br>💡프로그램 종료 과정<br><br>1. 정리 작업 : 프로그램이 종료되기 전에 필요한 정리 작업을 수행한다. ⇒ 열려 있는 파일을 닫고, 할당된 리소스를 해제하는 등의 작업이 포함될 수 있다.<br><br>2. 종료 코드 반환 : 프로그램이 완전히 종료 되었을 때 종료 코드를 반환한다. 종료 코드는 프로그램이 성공적으로 종료 되었는지 또는 오류로 종료 되었는지를 나타내는 값이다.<br><br>3. 자원 해제 : 프로그램이 사용한 모든 자원을 해제한다. ⇒ 할당된 메모리의 해제, 열려 있는 연결의 닫힘 등이 포함될 수 있다.
</callout>
