> 화소 하나하나를 바꾸는 처리. 반복문 대신 NumPy·룩업테이블·OpenCV 함수로 한 번에 처리하고, 밝기는 더하기(포화 연산), 대비는 곱하기, 치우친 분포는 히스토그램 스트레칭·평활화로 펼친다. 색으로 물체를 고를 땐 RGB보다 HSV의 H 채널이 편하다.
### 화소 접근
- 영상 처리 = 2차원 배열의 원소 값을 원하는 대로 바꾸기 → 접근·수정·생성이 기본
```python
mat[i, j]            # 읽기 (mat[i][j]도 되지만 느림)
mat[i, j] = k * 2    # 쓰기
mat.item(i, j)       # 파이썬 스칼라로 읽기
# mat.itemset((i, j), v)  ← NumPy 2.0에서 삭제됨 (AttributeError). mat[i, j] = v 로
```
- 반전(255 − 화소) 다섯 가지 방법 속도 비교
| 방법 | 슬라이드 | 직접 측정 (300×400, NumPy 2.4) |
|---|---|---|
| 이중 for + 인덱싱 | 586.93 ms | 39.5 ms |
| 이중 for + `item()` | 65.21 ms | 30.0 ms |
| 룩업테이블 `lut[image]` | 0.68 ms | 0.48 ms |
| `cv2.subtract(255, image)` | 0.19 ms | 3.0 ms(첫 호출 포함) |
| `255 - image` | 0.16 ms | 0.29 ms |
  - 절대값은 컴퓨터마다 다르지만 결론은 같음: **파이썬 반복문은 수십~수백 배 느림**. 배열 연산(벡터화)이나 OpenCV 함수 사용
  - **룩업테이블(LUT)**: 0~255 각 입력에 대한 출력을 미리 계산해 두고 `lut[image]` 또는 `cv2.LUT(image, lut)`로 한 번에 치환 → 어떤 화소별 변환이든 빠름
### 그레이스케일과 화소값
- 0 = 검정, 255 = 흰색, 그 사이는 회색 (관습적으로 "흑백 영상"이라 부르지만 정확히는 명암도 영상)
```python
image1 = np.zeros((50, 512), np.uint8)
image1[:] = np.arange(512) // 2              # 0→255 부드러운 그라데이션
image2 = np.zeros((50, 512), np.uint8)
image2[:] = np.arange(512) // 20 * 10        # 20칸마다 10씩 계단
```
- 관심 영역(ROI): 좌표는 `(x, y, w, h)`, 배열 접근은 `image[y:y+h, x:x+w]` (**행 먼저**)
```python
(x, y), (w, h) = (180, 37), (15, 10)
roi_img = image[y:y + h, x:x + w]       # 어두운 곳 50대, 밝은 곳 200대 값이 보임
cv2.rectangle(image, (x, y, w, h), 255, 1)
```
### 밝기와 대비
- 밝기: 모든 화소에 상수를 더하기/빼기
| 방식 | 250 + 100 | 사용 |
|---|---|---|
| **포화(saturation)** | 255 | `cv2.add`, `cv2.subtract` |
| **모듈로(modulo)** | 350 % 256 = **94** | NumPy `+`, `-` |
  - 슬라이드는 104로 적었지만 350 − 256 = 94. 모듈로 방식은 밝은 곳이 갑자기 검게 되는 얼룩이 생김
  - `cv2.subtract(255, image)`처럼 스칼라를 앞에 써도 동작
- 합성: dst = img1·α + img2·β
```python
add_img1 = cv2.add(image1, image2)                          # 단순 합: 쉽게 255로 포화
add_img2 = np.clip(image1 * 0.6 + image2 * 0.7, 0, 255).astype('uint8')
add_img3 = cv2.addWeighted(image1, 0.6, image2, 0.7, 0)     # 위와 같은 결과
```
  - α + β = 1이면 평균 밝기 유지 (α + β > 1이면 밝아짐)
- **대비**: 곱하기 → 밝은 곳은 더 밝게, 어두운 곳은 더 어둡게 (1보다 크면 대비 증가)
  - 단순히 곱하면 전체 밝기도 같이 변함 → 평균을 기준으로: dst = α·src + (1 − α)·평균
```python
avg = cv2.mean(image)[0] / 2.0
dst3 = cv2.addWeighted(image, 0.5, noimage, 0, avg)    # 0.5배 + 평균/2 → 대비 감소, 밝기 유지
dst4 = cv2.addWeighted(image, 2.0, noimage, 0, -avg)   # 2배 − 평균/2 → 대비 증가
# 이 식은 정확히 평균을 고정하는 건 아님 (2배 − 평균/2면 평균이 1.5배가 됨), 정확히는 α·x + (1 − α)·mean
```
### 히스토그램
- 화소값별 개수(도수분포)를 그래프로. 가로 = 계급(bin), 세로 = 빈도
- 예: 4×4 영상 → 값 0: 1개(6%), 1: 2개(13%), 2: 4개(25%), 4: 3개(19%), 5: 1개(6%), 6: 5개(31%)
- `cv2.calcHist(images, channels, mask, histSize, ranges)` — **리스트로** 감싸서 전달
```python
hist = cv2.calcHist([image], [0], None, [32], [0, 256])      # 32계급 (계급 폭 8)
hist2, bins = np.histogram(image, np.arange(0, 257, 8))      # 같은 결과 (NumPy)
# 직접 구현: for v in (image // 8).flat: hist[v] += 1
```
  - ranges의 끝 256은 **포함 안 됨** ([0, 256) → 0~255)
- 그래프 그리기: `cv2.normalize(hist, hist, 0, 높이, cv2.NORM_MINMAX)`로 높이에 맞춘 뒤 막대 사각형을 그리고, 영상은 y가 아래로 커지므로 `cv2.flip(img, 0)`으로 뒤집기
- 색상(Hue) 히스토그램: HSV의 H 채널을 `ranges=[0, 180]`(OpenCV는 0~360°를 절반으로 저장)로 계산하고, 막대를 해당 색으로 칠함
### 히스토그램 스트레칭
- 분포가 좁게 몰린(대비 낮은) 영상을 0~255로 잡아 늘림
- **새 값 = (화소 − low) / (high − low) × 255** (low, high = 실제 최소·최대)
```python
hist = cv2.calcHist([image], [0], None, [64], [0, 256])
# 값이 있는 첫 계급·마지막 계급으로 low, high 결정 → 예: low = 52, high = 180
idx = np.arange(256, dtype=np.float32)
idx = (idx - low) / (high - low) * 255
idx[:int(low)] = 0
idx[int(high) + 1:] = 255
dst = cv2.LUT(image, idx.astype('uint8'))
```
  - 같은 결과: `cv2.normalize(image, None, 0, 255, cv2.NORM_MINMAX)`
  - 한계: 극단값 하나만 있어도(0과 255가 한 점씩) 아무 효과가 없음 → 상하위 일부를 잘라서 쓰거나 평활화
### 히스토그램 평활화
- 분포를 **누적분포 기준으로 재배치**해 고르게 → 많이 몰린 구간은 넓게 펼쳐지고 드문 구간은 좁아짐
1. 히스토그램 → 2. 누적합 → 3. 전체 화소 수로 나눠 정규화 → 4. × 최대값(반올림)
| 화소값 | 0 | 1 | 2 | 3 | 4~6 | 7 |
|---|---|---|---|---|---|---|
| 빈도 | 1 | 5 | 6 | 3 | 0 | 1 |
| 누적 | 1 | 6 | 12 | 15 | 15 | 16 |
| 정규화 누적 | 0.0625 | 0.375 | 0.75 | 0.9375 | 0.9375 | 1.0 |
| × 7 | 0.44 | 2.63 | 5.25 | 6.56 | 6.56 | 7.0 |
| 결과 | 0 | 3 | 5 | 7 | 7 | 7 |
- 4×4 입력 [[0, 2, 2, 1], [1, 2, 3, 2], [1, 2, 3, 2], [1, 3, 1, 7]] → [[0, 5, 5, 3], [3, 5, 7, 5], [3, 5, 7, 5], [3, 7, 3, 7]] (직접 계산으로 확인)
```python
hist = cv2.calcHist([image], [0], None, [256], [0, 256])
accum = np.cumsum(hist)
lut = np.round(accum / accum[-1] * 255).astype('uint8')
dst1 = cv2.LUT(image, lut)
dst2 = cv2.equalizeHist(image)        # 같은 일 (OpenCV는 최소 누적값을 빼서 계산해 약간 다를 수 있음)
```
  - 컬러 영상은 B, G, R 각각 평활화하면 색이 틀어짐 → YCrCb의 Y(밝기)만 평활화. 지역별로 하려면 CLAHE(`cv2.createCLAHE`)
### 컬러 공간
- 가시광선 약 380~780nm. **컬러 공간** = 색을 3차원 좌표로 표현하는 체계 → 목적에 맞는 공간을 쓰면 색으로 물체 분리, 검색 등이 쉬워짐
- **RGB**: 빛의 3원색, **가산 혼합**(섞을수록 밝아짐), 디스플레이 기본. 직관적이지만 밝기와 색이 섞여 있음
| RGB | 색 | RGB | 색 |
|---|---|---|---|
| 0, 0, 0 | 검정 | 255, 255, 255 | 흰색 |
| 128, 128, 128 | 회색 | 192, 192, 192 | 은색 |
| 255, 255, 0 | 노랑 | 255, 0, 255 | 마젠타 |
| 0, 255, 255 | 시안 | 255, 165, 0 | 주황 |
| 128, 128, 0 | 올리브 | 0, 128, 128 | 청록(teal) |
| 0, 0, 128 | 남색(navy) | 75, 0, 130 | 인디고 |
  - 슬라이드 표는 (0, 0, 0)을 white, (255, 255, 255)를 black으로 뒤바꿔 적었고, (0, 128, 128)을 olive로 적었는데 olive는 (128, 128, 0). OpenCV에 넣을 땐 순서를 **BGR**로 뒤집어야 함
- **CMY(K)**: 인쇄용 3원색, **감산 혼합**(섞을수록 어두워짐). C = 255 − R, M = 255 − G, Y = 255 − B (RGB의 보색), K는 검정
- **HSI / HSV**: H 색상(0~360°), S 채도(순수한 정도), I/V 밝기 → **색과 밝기가 분리**돼 조명이 바뀌어도 색으로 물체를 찾기 쉬움
  - HSI: θ = cos⁻¹[((R − G) + (R − B))/2 / √((R − G)² + (R − B)(G − B))], H = θ (B ≤ G) 또는 360 − θ, S = 1 − 3·min(R, G, B)/(R + G + B), I = (R + G + B)/3
  - OpenCV HSV: V = max(R, G, B), S = (V − min)/V, H = 60(G − B)/(V − min) (V = R), 120 + 60(B − R)/(V − min) (V = G), 240 + 60(R − G)/(V − min) (V = B)
    - 슬라이드 식은 세 경우 모두 (G − B)이고 S로 나누는데, 위처럼 경우마다 차이 항이 다르고 분모는 V − min (OpenCV 문서 기준)
  - 8비트 영상에선 **H를 2로 나눠 0~179**, S·V는 0~255: 초록 (B, G, R) = (0, 255, 0) → H = 60, 파랑 → 120 (직접 확인)
```python
HSV_img = cv2.cvtColor(BGR_img, cv2.COLOR_BGR2HSV)
hue = HSV_img[:, :, 0].copy()
_, result = cv2.threshold(hue, th2, 255, cv2.THRESH_TOZERO_INV)   # th2 초과는 0
cv2.threshold(result, th1, 255, cv2.THRESH_BINARY, result)       # th1 초과만 255
# → th1 < H ≤ th2 인 화소만 흰색 (예: 50~130이면 초록~파랑 계열). cv2.inRange(hue, lo, hi)도 같은 용도
```
- **YCbCr**: Y = 0.299R + 0.587G + 0.114B, Cb = (B − Y)·0.564 + 128, Cr = (R − Y)·0.713 + 128. 사람 눈이 둔한 색차(Cb, Cr)를 낮은 해상도로 → JPEG·MPEG 압축의 기본
- **YUV**: 아날로그 TV(PAL)용. Y·U·V로 밝기·색차 분리
  - 슬라이드의 Y = 0.2160R + 0.7152G + 0.0722B는 BT.709 계수(0.2126)의 오기. 참고로 `cv2.COLOR_BGR2YUV`는 BT.601(0.299, 0.587, 0.114)을 사용
- **Lab**: 사람이 느끼는 색 차이가 거리와 비례하도록 만든 공간 (L 밝기, a 초록↔빨강, b 파랑↔노랑)
- 그레이 변환 `COLOR_BGR2GRAY`도 Y와 같은 가중치 (초록이 가장 큼 = 사람 눈이 초록에 가장 민감)
### 이진화
- `cv2.threshold(src, thresh, maxval, type)` → (사용된 임계값, 결과)
| type | 결과 |
|---|---|
| `THRESH_BINARY` | src > thresh ? maxval : 0 |
| `THRESH_BINARY_INV` | src > thresh ? 0 : maxval |
| `THRESH_TOZERO` | src > thresh ? src : 0 |
| `THRESH_TOZERO_INV` | src > thresh ? 0 : src |
| `THRESH_TRUNC` | src > thresh ? thresh : src |
