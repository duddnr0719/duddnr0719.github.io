> 스레드 = 프로세스 안의 실행 흐름. 코드·데이터·파일은 공유하고 스택·레지스터만 따로 가져서 가볍다. 사용자 스레드를 커널 스레드에 어떻게 매핑하느냐(다대일/일대일/다대다)가 모델이고, 요즘은 스레드 풀·OpenMP·GCD처럼 런타임이 알아서 관리한다.
### 스레드
- 하나의 프로세스 안에서 여러 실행 흐름을 가능하게 하는 기본 단위
- 현대 앱은 대부분 멀티스레드: UI 갱신, 데이터 수신, 맞춤법 검사, 네트워크 요청을 동시에. OS 커널도 멀티스레드
- 다중 스레드 서버: 요청이 오면 스레드를 만들어 처리시키고 서버는 바로 다음 요청을 기다림 → 응답성↑, 프로세스 생성보다 가벼움
- 단일 vs 다중 스레드 프로세스
  - 공유: 코드, 데이터, 열린 파일
  - 스레드별: 레지스터, 스택 (+ PC)
- 이점
  - 응답성: 한 스레드가 막혀도 다른 스레드가 계속 → UI가 안 멈춤
  - 자원 공유: 같은 메모리를 쓰니 별도 메시지 전달 불필요
  - 경제성: 생성 비용과 전환 오버헤드가 프로세스보다 작음
  - 확장성: 멀티코어에서 실제 병렬 실행
### 멀티코어 프로그래밍
- 과제: 작업 분할(병렬 가능한 단위로 나누기), 균형(코어에 고르게), 데이터 분할, 데이터 의존성, 테스트·디버깅(훨씬 어려움)
- **동시성(concurrency)**: 단일 코어에서 시분할로 여러 작업이 '진행 중'인 것처럼
- **병렬성(parallelism)**: 멀티코어에서 여러 작업이 '실제로 동시에' 실행
- 병렬 처리 방식
  - 데이터 병렬: 데이터를 쪼개 각 코어에서 **같은 작업** (배열 합을 코어별 구간으로)
  - 작업 병렬: 코어마다 **다른 작업**
- 하드웨어 스레드: 코어 하나가 여러 스레드를 동시에 유지 (Oracle SPARC T4: 8코어 × 코어당 8 하드웨어 스레드)
### Amdahl의 법칙
- 직렬 부분 S, 코어 수 N일 때 **speedup ≤ 1 / (S + (1 − S)/N)**
- S = 0.25(75% 병렬화 가능)면
  - N = 2: 1 / (0.25 + 0.375) = **1.6배**
  - N = 4: 약 2.29배
  - N → ∞: 1 / 0.25 = 4배가 한계
- 코어를 아무리 늘려도 직렬 부분이 상한을 정함
### 사용자 스레드 vs 커널 스레드
- 사용자 스레드: 사용자 수준 라이브러리가 관리
- 커널 스레드: OS가 직접 관리 (Windows, Linux, macOS, Solaris 모두 지원)
- 라이브러리: POSIX Pthreads, Windows 스레드, Java 스레드
### 멀티스레딩 모델
| 모델 | 매핑 | 장점 | 단점 | 예 |
|---|---|---|---|---|
| 다대일 | 사용자 여럿 → 커널 1 | 관리 단순 | 하나가 블록되면 전부 블록, 멀티코어 병렬 불가 | Solaris Green Threads, GNU Portable Threads (현재 거의 안 씀) |
| 일대일 | 사용자 1 → 커널 1 (생성 시 같이 생성) | 동시성 좋음, 하나가 막혀도 나머지 실행 | 커널 스레드 생성 오버헤드, 개수 제한 | Windows, Linux, Solaris 9+ |
| 다대다 | 사용자 여럿 → 커널 여럿 | OS가 필요한 만큼 커널 스레드 생성 | 구현 복잡 | Solaris 9 이전, Windows ThreadFiber |
| 2단계 | 다대다 + 특정 스레드를 커널 스레드에 바인딩 | 세밀한 제어 | — | IRIX, HP-UX, Tru64, Solaris 8+ |
### 스케줄러 활성화
- 다대다·2단계 모델은 커널 스레드를 몇 개 둘지 정해야 함
- **LWP(경량 프로세스)**: 사용자 스레드와 커널 스레드 사이 중간 구조. 앱 입장에선 가상 프로세서, 각 LWP는 커널 스레드 하나에 연결
- 스케줄러 활성화: 커널이 스레드 라이브러리에 **업콜(upcall)** 로 이벤트(블록 등)를 알려줘서, 앱이 적정 수의 커널 스레드를 유지
### Pthreads
- POSIX 표준(IEEE 1003.1c) 스레드 생성·동기화 API. **명세**이지 구현이 아님 (구현은 OS 몫). UNIX 계열에서 사용, 사용자·커널 수준 모두 가능
```c
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>

int sum;                       /* 스레드들이 공유하는 전역 데이터 */
void *runner(void *param);

int main(int argc, char *argv[]) {
    pthread_t tid;             /* 스레드 ID */
    pthread_attr_t attr;       /* 스레드 속성 */
    if (argc != 2) { fprintf(stderr, "usage: a.out <integer value>\n"); return -1; }
    if (atoi(argv[1]) < 0) { fprintf(stderr, "%d must be >= 0\n", atoi(argv[1])); return -1; }

    pthread_attr_init(&attr);                      /* 기본 속성 */
    pthread_create(&tid, &attr, runner, argv[1]);  /* 스레드 생성 */
    pthread_join(tid, NULL);                       /* 종료 대기 */
    printf("sum = %d\n", sum);
}

void *runner(void *param) {    /* 새 스레드는 여기서 시작 */
    int i, upper = atoi(param);
    sum = 0;
    for (i = 1; i <= upper; i++) sum += i;
    pthread_exit(0);
}
```
- 실행: `gcc thread.c -o thread -pthread && ./thread 10` → `sum = 55`
- 여러 스레드 기다리기: `for (i = 0; i < NUM_THREADS; i++) pthread_join(workers[i], NULL);`
- join 없이 main이 끝나면 자식 스레드도 함께 종료됨
### Windows 스레드
- `CreateThread(보안속성, 스택크기, 함수, 인자, 플래그, &ThreadId)` → `WaitForSingleObject(handle, INFINITE)` → `CloseHandle(handle)`
- 스레드 함수 형태: `DWORD WINAPI Summation(LPVOID Param)`
### Java 스레드
- JVM이 관리, 보통 OS 스레드 모델 위에 구현
- 생성 방법: ① `Thread` 상속 후 `run()` 오버라이드 ② `Runnable` 구현 후 `Thread`에 전달 (②가 일반적)
```java
class Summation implements Runnable {
    private int upper; private Sum sumValue;
    public Summation(int upper, Sum sumValue) { this.upper = upper; this.sumValue = sumValue; }
    public void run() {
        int sum = 0;
        for (int i = 0; i <= upper; i++) sum += i;
        sumValue.setSum(sum);
    }
}
// main: Thread thrd = new Thread(new Summation(upper, sumObject));
//       thrd.start();  thrd.join();  → sumObject.getSum()
```
### 암묵적 스레딩
- 스레드가 많아지면 직접 관리가 어려움 → 컴파일러·런타임이 생성·관리
- **스레드 풀**: 미리 만들어 둔 스레드에 작업을 맡기고 재사용
  - 새로 만드는 것보다 빠름, 풀 크기로 스레드 수 제한, 작업 생성과 실행을 분리해 유연한 스케줄링
- **OpenMP**: C/C++/FORTRAN용 컴파일러 지시문. 공유 메모리 병렬화
  - `#pragma omp parallel`: 코어 수만큼 스레드를 만들어 블록 실행
  - `#pragma omp parallel for`: for 루프를 코어들에 나눔 (`c[i] = a[i] + b[i]`)
```c
#include <omp.h>
#include <stdio.h>
int main() {
    /* 순차 코드 */
    #pragma omp parallel
    {
        printf("I am a parallel region.\n");
    }
    /* 순차 코드 */
    return 0;
}
```
- 실행: `gcc -fopenmp omp.c -o omp && ./omp` → 코어 수만큼 출력
- **GCD (Grand Central Dispatch)**: Apple(macOS, iOS). 코드를 블록 `^{ }`으로 감싸 디스패치 큐에 넣으면 스레드 풀이 실행
```c
dispatch_queue_t queue = dispatch_get_global_queue(DISPATCH_QUEUE_PRIORITY_DEFAULT, 0);
dispatch_async(queue, ^{ printf("I am a block."); });
```
  - 직렬 큐: FIFO로 하나씩 (프로세스마다 메인 큐, 추가 생성 가능)
  - 동시 큐: FIFO로 꺼내되 여러 개 동시 실행. 시스템 전역 큐는 low/default/high 우선순위
### 스레드 취소
- 끝나기 전에 스레드를 종료시키는 것 (대상 = target thread)
  - 비동기 취소: 즉시 종료 → 자원·공유 데이터가 어중간한 상태로 남을 수 있음
  - 지연 취소: 스레드가 주기적으로 확인하다가 안전한 지점(취소점)에서 종료 → 더 안전
```c
pthread_t tid;
pthread_create(&tid, 0, worker, NULL);
/* ... */
pthread_cancel(tid);   /* 취소 '요청' — 실제 종료는 스레드 상태에 따름 */
```
| 모드 | 상태 | 유형 |
|---|---|---|
| Off | Disabled | — |
| Deferred (기본) | Enabled | Deferred |
| Asynchronous | Enabled | Asynchronous |
- Linux는 시그널로 스레드 취소를 구현
