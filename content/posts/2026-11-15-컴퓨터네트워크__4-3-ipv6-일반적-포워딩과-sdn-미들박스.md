> 4장(네트워크 계층: 데이터 평면)의 마지막 3부에서는 32비트 IPv4 주소 고갈에 대응하기 위해 128비트 주소와 40바이트 고정 헤더를 도입한 IPv6의 구조 및 터널링 전환 방식을 다룬다. 이어서 목적지 IP만 보던 방식에서 벗어나 여러 헤더 필드로 패킷을 처리하는 일반적인 포워딩(Generalized Forwarding)과 이를 구현하는 SDN(Software Defined Network) · OpenFlow의 매치+처리(match+action) 추상화를 정리한다. 마지막으로 방화벽 · IDS(Intrusion Detection Service) · 부하 분산기 등 부가 서비스를 제공하는 미들박스(Middleboxes)가 소프트웨어 기반 및 SDN 제어 구조와 결합하는 흐름까지 살펴본다.

### 4장 전체 목차와 다루는 범위
- **4장 전체 구성(`4장. 네트워크 계층: 데이터 평면`)**
  - **4.1 네트워크 계층 개요** = 데이터 평면 · 제어 평면
  - **4.2 라우터 내부에는 무엇이 있을까?**
  - **4.3 인터넷 프로토콜(IP)** = 데이터그램 형식 · 단편화 · IPv4 주소체계 · 네트워크 주소 변환 · **IPv6**
  - **4.4 일반적인 포워딩 및 소프트웨어 기반 네트워크(SDN)** = 매치 · 액션 · match-plus-action 작업의 OpenFlow 예
  - **미들박스(Middleboxes)**
- **이번 범위(`3/3`)의 초점** = **4.3절**의 마지막 주제인 **IPv6**, **4.4절**의 **일반적인 포워딩 및 소프트웨어 기반 네트워크(SDN)**, 그리고 **미들박스**를 다룸
- **다음 장과의 연결(Question & Answer)**
  - **Question** = 포워딩 테이블(목적지-기반 포워딩) 또는 플로우 테이블(일반적인 포워딩)은 어떻게 계산되는가?
  - **Answer** = **제어 평면**에 의해 계산됨(다음 장에서 다룸)

### IPv6 도입 동기와 데이터그램 포맷
- **초기 개발 동기** = **32비트** IP 주소 공간이 빠른 속도로 고갈되어 가고 있어 **128비트**의 확장된 주소 공간을 도입함
- **부가적인 동기**
  - 빠른 처리와 포워딩을 지원하는 헤더 포맷
  - **QoS(Quality of Service)**가 용이한 헤더
- **IPv6 데이터그램 포맷의 핵심 특징**
  - **고정 길이 헤더** = 고정된 길이의 **40바이트** 헤더를 사용함
  - **단편화 미허용** = **단편화(fragmentation)**를 허용하지 않음
- **IPv6 주요 헤더 필드와 IPv4 대비 제거 항목**
  - **우선순위(priority) · 트래픽 클래스(traffic class)** = "같은 종류의 패킷이다"를 명시해 흐름(flow) 중인 데이터그램들 사이에 우선순위를 부여함(예: 같은 웹페이지의 HTTP)
  - **흐름 라벨(flow label)** = 같은 흐름의 데이터그램을 구분하는 `0x12345`(**20bit** 필드, 예: 유튜브 비디오 패킷)
    - 흐름의 의미는 아직 잘 정의되지 않았으며, 라벨링은 되지만 "어떻게 관리할지"가 미정이라 아예 흐름(flow)을 쓰지 않는 경우도 많음
  - **다음 헤더(next header)** = 데이터그램의 데이터가 전달될 상위 계층 프로토콜을 구분함
  - **제거된 IPv4 헤더 필드** = IPv4의 체크섬 · 단편화 · 옵션 등 헤더가 제거됨

### IPv4에서 IPv6로의 전환: 터널링과 보급 현황
- **전환의 제약** = 모든 라우터들을 동시에 업그레이드할 수 없고 하루아침에 모두 IPv6로 변경하는 것이 불가능함
- **터널링(tunneling)과 캡슐화(Tunneling and Encapsulation)**
  - IPv4와 IPv6가 혼합된 네트워크를 운영하는 방식
  - IPv4 라우터들이 IPv6 데이터그램을 **IPv4 데이터그램의 페이로드**로써 운반함
- **IPv6 보급 현황**
  - **Google** = 전체 클라이언트의 ~30%가 IPv6를 통해 서비스에 접근함
  - **NIST** = 미국 정부 도메인의 1/3이 IPv6 적용 가능함
  - **긴 보급 소요 시간** = 보급되어 사용되는 데 너무 많은 시간이 소요되어 **25년째** 보급 중임
  - **응용 레벨과의 대비** = WWW · 소셜 미디어 · 스트리밍 미디어 · 게임 · 화상 회의 같은 응용 레벨은 지난 **20년** 간 급속한 변화를 겪은 반면, IPv6는 존재만 알려져 있고 이미 많이 쓰이고 있다는 점은 잘 드러나지 않음

### 일반적인 포워딩: 매치와 처리(Match plus Action)
- **플로우 테이블과 매치-액션**
  - 각 라우터에는 포워딩 테이블(플로우 테이블이라고도 함)이 포함됨
  - **매치와 처리(match plus action)** = 도착하는 패킷의 비트를 비교하고 일치(매치)하면 처리 동작을 수행함
- **목적지-기반 포워딩 vs 일반적인 포워딩**
  - **목적지-기반 포워딩(destination-based forwarding)** = 목적지 IP 주소에 기반하여 포워딩함
  - **일반적인 포워딩(generalized forwarding)** = 여러 헤더 필드가 처리 동작을 결정함
    - **처리 동작 예** = `drop` · `copy` · `modify` · `log packet` 등 여러 처리 동작을 수행함

### 소프트웨어 정의 네트워크(SDN)와 플로우 테이블
- **SDN(Software Defined Network, 소프트웨어 정의 네트워크)**
  - 소프트웨어로 네트워크 경로 설정 · 제어 및 운용 관리를 처리함
  - 라우터의 **제어 부분**을 **데이터 전송 부분**과 분리하고 개방형 인터페이스를 외부에 제공함
  - 네트워크 장비는 단순히 패킷만 전달하는 스위치 역할을 함
- **SDN 등장 배경**
  - 네트워크 환경의 변화와 트래픽 패턴 변화
  - 트래픽이 **데이터 센터**를 중심으로 전환됨
  - **가상화(가상 머신)**의 보편화로 호스트의 빈번한 이동이 발생함
  - **네트워크 관리** 요구가 커짐
- **일반적인 포워딩과 SDN 동작 구조**
  - 각 라우터는 논리적인 중앙 집중형 제어기가 계산하고 배포한 **플로우 테이블(flow table)**을 내장함
  - 패킷의 **흐름(flow)**은 헤더에 의해 정의되며, 제어기가 계산하고 배포한 플로우 테이블에는 라우터의 **매치+처리 규칙(match+action rules)**이 정의됨
- **플로우 테이블의 패킷 처리 규칙(packet-handling rules) 4가지 요소**
  - **패턴(pattern)** = 패킷의 헤더 값과 일치 여부를 비교함
  - **처리(action)** = 일치하는 패킷을 삭제(`drop`) · 전달(`forward`) · 수정(`modify`) · 제어기에 전송함
  - **우선순위(priority)** = 애매모호하게 중첩되는 패턴을 구분함
  - **통계(counters)** = 트래픽 양을 패킷 수와 바이트 수로 표시함

### OpenFlow 프로토콜과 통합 추상화
- **OpenFlow 프로토콜**
  - SDN을 위한 제어 평면과 데이터 평면 간의 표준 인터페이스 기술로 **ONF(Open Networking Foundation)**에서 관리함
  - 소프트웨어 정의 포워딩(software defined forwarding)이자 일반적인 포워딩(generalized forwarding)을 구현함
- **매치+처리(match+action) 추상화를 통한 여러 네트워크 장비 통합 적용**
  - **라우터** = 매치: 가장 긴 목적지 IP 주소의 프리픽스 → 처리: 링크로 포워딩
  - **스위치** = 매치: 목적지 MAC 주소 → 처리: 포워딩 또는 브로드캐스트(`flood`)
  - **방화벽(firewall)** = 매치: IP 주소나 TCP/UDP 포트 번호 → 처리: 접근 허용 또는 거부
  - **NAT** = 매치: IP 주소와 포트 번호 → 처리: 주소와 포트 번호를 재구성
- **OpenFlow 협력 동작 예**
  - 각 장비의 플로우 테이블들이 협력하여 네트워크 단위의 동작을 형성함
  - 예: 호스트 `h5` · `h6`의 데이터그램이 `s1`을 경유하여 `s2`의 `h3` · `h4`로 전송됨

### 미들박스(Middleboxes)와 지능적 미들박스
- **미들박스(Middlebox)의 개념과 구현 변화**
  - IP 패킷의 포워딩 및 라우팅을 제외한 부가적인 서비스를 제공하는 네트워크 장비로 기관 · 회사 · ISP 등에서 널리 사용됨
  - 초기에는 하드웨어 장치였으나 최근에는 **매치+처리** 기법의 소프트웨어로 구현됨
- **미들박스 제공 서비스**
  - **방화벽**
  - **IDS(Intrusion Detection Service, 침입 탐지 시스템)**
  - **NAT**
  - **부하 분산기(load balancer)**
  - **WAN 가속기 및 각종 성능 향상을 위한 프락시**
- **지능적 미들박스**
  - SDN의 중앙 집중화된 컨트롤러 구조와 소프트웨어 기반 처리 능력을 결합하여 네트워크 상황에 맞춰 지능적으로 미들박스 정책을 적용함
