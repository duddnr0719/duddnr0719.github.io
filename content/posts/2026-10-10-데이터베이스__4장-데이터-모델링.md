> 현실 세계 → (개념적 모델링, E-R 모델) → 개념 세계 → (논리적 모델링, 관계 모델) → DB. E-R 다이어그램의 기호와 관계 유형이 핵심.
### 2단계 데이터 모델링
- 개념적 모델링(정보 모델링): 현실 세계의 중요 데이터를 추출해 개념 세계로 옮김
- 논리적 모델링(데이터 모델링): 개념 세계의 데이터를 DB에 저장할 구조로 표현
- 코끼리 예: 현실의 코끼리 → "발이 네 개, 코가 김, 1톤 이상, 코로 물건을 잡음"(개념) → 번호 붙인 항목(논리)
### 건축 vs DB 설계
| 단계 | 건축 | DB 설계 |
|---|---|---|
| 1. 요구사항 분석 | 건축주 요구·부지 조사 | 저장할 데이터, 사용자, 시스템 목적 정의 |
| 2. 개념적 설계 | 조감도·기본 설계도 | 엔티티와 관계 추출 → ER 다이어그램 (DBMS 무관) |
| 3. 논리적 설계 | 배관·배선 포함 상세 도면 | 테이블로 변환 + 정규화로 중복 제거 |
| 4. 물리적 설계·구현 | 실제 시공 | 특정 DBMS에 맞춰 타입·저장 구조 결정, DDL 실행 |
| 5. 유지보수 | 인테리어·보수 | 인덱스, 쿼리 튜닝, 성능 모니터링 |
- 논리 설계 예: 고객(고객ID PK, 이름, 연락처), 주문(주문ID PK, 고객ID FK, 주문일, 총금액), 상품(상품ID PK, 상품명, 가격)
```sql
CREATE TABLE 고객 (
    고객ID INT PRIMARY KEY,
    이름 VARCHAR(50),
    연락처 VARCHAR(50)
);
```
### 데이터 모델링
- 정의: 데이터의 구조·관계·제약조건을 시각화하고 정의하는 과정 = 현실 데이터를 정리해 DB 구조를 설계하는 작업
- 목적: 데이터 구조 이해, 일관성 확보(중복·모순 없음), 효율적 설계, 개발자·분석가·사용자 간 커뮤니케이션
- 단계: 개념적 → 논리적 → 물리적
- 장점: 중복 최소화, 무결성 확보, 요구사항 이해로 개발 비용 감소, 유지보수·확장 용이
### 데이터 모델
- 데이터 모델링 결과물을 표현하는 도구
  - 개념적 데이터 모델: 사람이 이해하기 쉬운 개념 구조 → **E-R 모델**
  - 논리적 데이터 모델: DB의 논리 구조 → **관계 데이터 모델**
- 구성: 데이터 구조, 연산, 제약조건
- 학사 예: 학생(학번, 이름, 학년, 학과) —m— 수강(성적) —n— 과목(과목코드, 과목명, 학점수) → 논리 모델에선 수강 릴레이션(학번, 과목코드, 성적)이 학생·과목을 참조
### E-R 모델
- 피터 첸(Peter Chen)이 제안한 개념적 데이터 모델. 핵심 요소: **개체, 속성, 관계**. 그림으로 그린 게 E-R 다이어그램.
### 개체와 속성
- 개체(entity): 조직 운영에 꼭 필요하고 저장할 가치가 있는, 다른 것과 구별되는 사람·사물·사실·사건·개념 (서점: 고객, 책). **사각형**
- 속성(attribute): 개체나 관계의 고유 특성, 의미 있는 데이터의 가장 작은 논리 단위. 파일 구조의 필드에 대응. **타원**
- 용어
  - 개체 타입: 이름과 속성들로 정의한 것 (고객(이름, 주소, 연락처, 적립금)) ↔ 레코드 타입
  - 개체 인스턴스(어커런스): 속성이 실제 값을 가진 개체 (`<정소화, 서울시 동작구, 02-111-1111, 1000>`) ↔ 레코드 인스턴스
  - 개체 집합: 한 개체 타입의 인스턴스 모음
### 속성의 분류
| 분류 | 종류 | 예 | 표기 |
|---|---|---|---|
| 값 개수 | 단일 값 | 이름, 적립금 | 타원 |
| | 다중 값 | 연락처, 책의 저자 | 이중 타원 |
| 분해 가능성 | 단순 | 적립금, ISBN, 가격 | 타원 |
| | 복합 | 주소(도/시/동/우편번호), 생년월일(연/월/일) | |
| 기타 | 유도 | 판매가격(가격×할인율), 나이(출생연도로 계산) | 점선 타원 |
- 널 속성: 널 값을 허용하는 속성. 널 = 아직 결정 안 됨 / 모름 / 존재하지 않음. 공백이나 0과 다름 → 집계할 때 주의
```sql
SELECT AVG(comm) FROM emp;          -- NULL인 행은 빼고 평균
SELECT AVG(NVL(comm, 0)) FROM emp;  -- NULL을 0으로 보고 평균
```
- 키 속성: 각 인스턴스를 식별하는 속성(값이 모두 달라야 함). 여러 속성 조합도 가능(고객아이디 대신 (이름, 주소)). **밑줄**
### 관계
- 개체 간의 의미 있는 연관성 = 개체 집합 사이의 매핑. "고객은 책을 구매한다". **마름모**
- 관계도 속성을 가질 수 있음 (구매일자, 결제방식)
- 참여 개체 타입 수
  - 이항: 학생 —지도— 교수
  - 삼항: 납품업자 —공급— 제품, 창고
  - 순환: 직원이 자기 자신과 (상사—부하)
- 매핑 카디널리티
  - 1:1: 남편—혼인—아내
  - 1:n: 부서—소속—사원 (부서 하나에 사원 여럿, 사원은 부서 하나)
  - n:m: 고객—구매—책
- 참여 특성
  - 필수적(전체) 참여: 모든 인스턴스가 반드시 참여 (모든 고객은 반드시 책을 구매). **이중선**
  - 선택적(부분) 참여: 일부만 참여해도 됨 (안 팔린 책도 있음)
- 종속성
  - 약한 개체: 다른 개체(오너 개체)의 존재에 의존. 보통 오너와 1:n, 필수 참여, 오너의 키를 포함해 키 구성
  - 예: 직원(오너) — 부양 — 부양가족(약한 개체)
  - 약한 개체는 **이중 사각형**, 그 관계는 **이중 마름모**
### E-R 다이어그램 정리
- 사각형 = 개체, 마름모 = 관계, 타원 = 속성, 링크 = 연결, 레이블 = 1:1 / 1:n / n:m
- 서점 예: 고객(고객아이디(키), 고객명, 적립금) —n— 구매(구매일자, 결제방식) —m— 책(ISBN, 제목, 저자, 가격) —n— 공급 —1— 출판사(출판사번호, 이름, 위치, 전화번호)
- 영화예매 예
  - 영화 —1— 상영 —m— 상영스케쥴(상영시간)
  - 상영관 —1— 배정(요금) —n— 상영스케쥴
  - 상영스케쥴 —1— 존재(이중 마름모) —n— 예매좌석(약한 개체)
  - 예매좌석 —m— 예매(예매일시, 금액) —1— 회원(회원번호, 이름, 휴대전화, 등급, 할인율, 카드)
### 논리적 데이터 모델
- E-R 다이어그램의 개념 구조를 DB에 저장할 형태로 표현한 논리 구조 = DB 스키마
- 관계 데이터 모델: 가장 널리 쓰임. 논리 구조가 2차원 **테이블**, 데이터와 메타데이터 모두 테이블로 저장. Codd가 창안. (구조·제약조건은 5장, 연산은 6장)
- 계층 데이터 모델: **트리** 구조
  - 루트 개체 존재, 사이클 없음, 부모-자식은 1:n만
  - 두 개체 사이에 관계 하나만, n:m 직접 표현 불가
  - 구조가 복잡해지기 쉽고 삽입·삭제·수정·검색이 어려움
  - 사라졌다가 객체지향 모델로 환생
- 네트워크 데이터 모델: **그래프** 구조
  - 오너-멤버 간 1:n만, 두 개체 사이 여러 관계 가능(이름으로 구별)
  - n:m 직접 표현 불가, 구조 복잡, 조작 어려움
  - 지금은 사라짐
