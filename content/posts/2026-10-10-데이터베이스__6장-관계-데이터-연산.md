> 관계 대수 = 처리 순서를 적는 절차적 언어(집합 연산 4개 + 관계 연산 4개), 관계 해석 = 원하는 것만 적는 비절차적 언어. SQL은 둘로 표현 가능한 질의를 모두 표현할 수 있어 '관계적으로 완전'하다.
### 관계 데이터 연산
- 데이터 모델 = 구조 + 제약조건 + **연산**. 릴레이션은 투플의 집합이므로 주로 집합 연산 (릴레이션은 R, S로 표기)
- 관계 대수(절차적): 결과를 얻는 처리 과정을 순서대로 기술
- 관계 해석(비절차적): 원하는 데이터가 무엇인지만 기술
- 역할: 데이터 언어의 유용성 검증 기준. 둘로 기술 가능한 모든 질의를 기술할 수 있으면 **관계적으로 완전**(예: SQL)
- 질의(query) = 데이터에 대한 처리 요구
### 관계 대수
- 릴레이션을 처리하는 연산자 모임. 대표 연산자 8개
| 분류 | 연산자 | 기호 | 의미 |
|---|---|---|---|
| 일반 집합 | 합집합 | R ∪ S | R 또는 S에 속한 투플 |
| | 교집합 | R ∩ S | R과 S 모두에 속한 투플 |
| | 차집합 | R − S | R에만 있는 투플 |
| | 카티션 프로덕트 | R × S | R과 S 투플의 모든 조합 |
| 순수 관계 | 셀렉트 | σ조건(R) | 조건을 만족하는 투플(행) |
| | 프로젝트 | π속성(R) | 지정한 속성(열)만 |
| | 조인 | R ⋈ S | 공통 속성으로 투플 연결 |
| | 디비전 | R ÷ S | S의 모든 투플과 관련된 R의 투플 |
- **폐쇄 특성**: 피연산자도 결과도 릴레이션 → "릴레이션은 관계대수 연산에 대해 닫혀 있다" → 연산을 중첩할 수 있음
- Codd의 기본 연산자 6개: ∪, −, ×, σ, π, ρ(이름 바꾸기). 교집합은 **R ∩ S = R − (R − S)** 로 만들 수 있어서 기본 연산자가 아님
### 일반 집합 연산자
- 피연산자 릴레이션 2개 필요
- ∪, ∩, −는 **합병 가능**해야 함: 차수가 같고, 대응 속성의 도메인이 같아야 함 (×는 상관없음)
  - 고객(번호 INT, 이름 CHAR(20), 나이 INT) vs 직원(번호 INT, 이름 CHAR(20), 직위 CHAR(20)) → 세 번째 도메인이 달라 불가
- 예: R = {100 정소화, 200 김선우, 300 고명석}, S = {100 정소화, 101 채광주, 102 김수진}
| 연산 | 결과 | 차수 | 카디널리티 | 교환·결합 |
|---|---|---|---|---|
| R ∪ S | 5개 투플 (중복 100 제거) | 같음 | ≤ \|R\|+\|S\| | O |
| R ∩ S | 100 정소화 | 같음 | ≤ min | O |
| R − S | 200, 300 | 같음 | ≤ \|R\| | X |
| S − R | 101, 102 | 같음 | ≤ \|S\| | X |
| R × S | 9개 투플 (R.번호, R.이름, S.번호, S.나이) | 차수 합 | 카디널리티 곱 | O |
### 셀렉트 σ
- 하나의 릴레이션에서 조건을 만족하는 투플만 선택 → 결과는 **수평적 부분집합**
- 표기: `σ조건식(릴레이션)` 또는 `릴레이션 where 조건식`
- 조건식(프레디킷): 비교 연산자(>, ≥, <, ≤, =, ≠) + 논리 연산자(∧, ∨, ¬)
- 예 6-1 `σ등급='gold'(고객)` → apple 김현준, carrot 원유선
- 예 6-2 `σ등급='gold' ∧ 적립금≥2000(고객)` → carrot 원유선
- 교환적: `σ조건1(σ조건2(R)) = σ조건2(σ조건1(R)) = σ조건1∧조건2(R)`
```sql
SELECT * FROM (SELECT * FROM emp WHERE deptno = 10) WHERE sal > 2500;
SELECT * FROM (SELECT * FROM emp WHERE sal > 2500) WHERE deptno = 10;
SELECT * FROM emp WHERE deptno = 10 AND sal > 2500;   -- 세 결과 동일
```
### 프로젝트 π
- 선택한 속성만으로 결과 구성 → **수직적 부분집합**. 중복 투플은 자동 제거
- 표기: `π속성리스트(릴레이션)` 또는 `릴레이션[속성리스트]`
- 예 6-3 `π고객이름, 등급, 적립금(고객)` → 4행
- 예 6-4 `π등급(고객)` → gold, vip, silver (gold 중복 제거)
- 결합: `π고객이름(σ등급='gold'(고객))` → 김현준, 원유선
### 조인 ⋈
- 두 릴레이션의 공통 속성(조인 속성) 값이 같은 투플끼리 연결
  - 고객.고객아이디 = 주문.주문고객 → 주문이 없는 orange 고객은 결과에서 빠짐
  - 조인 속성이 (B1, B2)처럼 여러 개일 수도 있음
- 자연 조인 `R ⋈N S`: 조인 속성을 한 번만 남김
- 세타 조인 `R ⋈AθB S`: θ ∈ {>, ≥, <, ≤, =, ≠}. 결과 차수 = 두 차수의 합
- 동일 조인(equi-join): θ가 `=`인 세타 조인. 조인 속성이 둘 다 남음 (고객 6 + 주문 … → 차수 8)
- 비동일 조인 예: 급여가 등급 구간에 들어가는 행끼리 연결
```sql
SELECT e.ename, e.sal, s.grade
FROM emp e, salgrade s
WHERE e.sal BETWEEN s.losal AND s.hisal;   -- SMITH 800 → 1, KING 5000 → 5
```
### 디비전 ÷
- `R ÷ S`: S의 **모든** 투플과 관련 있는 R의 투플. R이 S의 속성을 모두 포함해야 가능. 표준 SQL엔 연산자가 없음
- 직관: 12 ÷ 2 = (6 × 2) ÷ 2 = 6
- 예: 주문내역 ÷ {진짜우동, 그대로만두} → 둘 다 주문한 (apple, 한빛식품)
- 공식 (A, B는 a, b의 속성 집합)
  - **a ÷ b = π(A−B)(a) − π(A−B)((π(A−B)(a) × b) − a)**
  - π(A−B)(a) × b: 모든 후보 × 모든 조건 조합
  - 거기서 a를 빼면: 실제로는 없는 조합 → 조건을 다 못 채운 후보
  - 전체 후보에서 그 후보들을 빼면 정답
- SQL로: 모든 부품을 공급하는 공급자 (결과 HONG)
```sql
SELECT DISTINCT S.SNAME
FROM S
WHERE NOT EXISTS (
  (SELECT P# FROM P)
  MINUS
  (SELECT SP.P# FROM SP WHERE SP.S# = S.S#)
);
```
- 원리: 전체 부품 목록에서 그 공급자가 공급하는 부품을 뺐을 때 공집합이면 모든 부품을 공급하는 것
### 확장 연산자
- 세미 조인 `R ⋉ S`: 조인 속성만 프로젝트한 S와 조인 → 불필요한 속성을 미리 제거해 비용 절감. 교환 X. 결과는 "주문한 적 있는 고객 정보"
- 외부 조인 `R ⋈+ S`: 자연 조인에서 빠지는 투플도 포함, 짝이 없는 속성은 NULL (주문 없는 orange도 나옴)
```sql
-- Oracle (+) 문법: 사원이 없는 40번 OPERATIONS 부서도 출력
SELECT ename, dname
FROM emp, dept
WHERE emp.deptno(+) = dept.deptno;
-- ANSI: FROM emp RIGHT OUTER JOIN dept ON emp.deptno = dept.deptno
```
### 질의 표현 예
- 6-5 gold 고객의 이름·나이: `π고객이름, 나이(σ등급='gold'(고객))` → (김현준, 20), (원유선, 28)
- 6-6 원유선의 등급과 주문제품·수량: `π등급, 주문제품, 수량(σ고객이름='원유선'(고객 ⋈ 주문))` → (gold, 맛있는파이, 5)
- 6-7 수량 10개 미만 주문 삭제: `주문 − σ수량<10(주문)` → 1001, 1003만 남음
