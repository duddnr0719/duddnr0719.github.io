> 머신러닝 = 데이터로 y = f(x)를 근사하는 것. 정답(레이블)이 있으면 지도 학습(회귀·분류), 없으면 비지도 학습(군집화), 보상으로 배우면 강화 학습.
### 머신러닝 vs 전통적 프로그래밍
- 전통적 방식 = 명시적 프로그래밍: 원하는 절차를 사람이 직접 코드로 작성
  - 강아지/고양이 구별처럼 사람에겐 쉬워도 알고리즘으로 적기 어려운 문제가 많음
- 머신러닝: 사진을 잔뜩 주고 "이건 강아지, 이건 아님"만 알려줌
| | 전통적 프로그래밍 | 머신러닝 |
|---|---|---|
| 입력 | 데이터 + 프로그램 | 데이터 + 정답(출력) |
| 결과 | 출력 | 프로그램(모델) |
- AI(1950~70) ⊃ 머신러닝(1980~2000) ⊃ 딥러닝(2010~)
- 역사: 1957 퍼셉트론 → 1985 역전파 → 1995 SVM → 1998 필기체 인식 → 2012 AlexNet ImageNet 우승
### 머신러닝의 종류
- 지도 학습
  - 회귀: Linear, Polynomial
  - 분류: KNN, Trees, Logistic Regression, Naive Bayes, SVM
  - 의사결정 트리, 랜덤 포레스트
- 비지도 학습: 클러스터링(K-means), 차원 축소(SVD, PCA)
- 강화 학습
- 신경망은 이 모든 분야에서 쓰일 수 있음
### 기본 용어
- **머신러닝 == 함수 근사(function approximation)**: 입력을 받아 출력을 내는 y = f(x)를 학습
- 특징(feature): 모델에 넣는 입력. 스팸 필터라면 "검찰" 포함 여부(yes/no), "광고·선물 교환권·이벤트 당첨" 포함 여부, '★' 같은 특수 기호 개수(정수)
- 레이블(label): y. 농작물 가격, 사진 속 동물 종류 등 무엇이든 가능
- 샘플(예제): x. 레이블 있는 샘플과 없는 샘플이 있음 (지도 학습엔 레이블 필요)
- 학습: 모델을 만드는 과정 / 예측: 학습된 모델을 레이블 없는 샘플에 적용해 y′를 얻는 것
### 지도 학습
- 정답을 알려주는 '교사'가 있는 학습
- **회귀**: 입력·출력 모두 연속적인 실수
  - (1, 10), (2, 20), (3, 30), (4, 40) → x = 5면 y = 50
  - 아파트 면적 → 가격: 점들을 가장 잘 지나는 직선을 찾고, 데이터가 늘면 기울기를 조정 → 이게 회귀에서의 학습
  - "이 광고를 클릭할 확률은?"
- **분류**: 출력 y가 이산적 → 입력을 2개 이상의 클래스로 나눔 (인식 문제라고도 함)
  - 스팸 필터(정상/스팸), 강아지/고양이, 과일(크기·색상·모양 → 사과, 체리, 바나나, 포도)
  - 이진 분류 / 다중 클래스 분류
  - 대표 알고리즘: 신경망, kNN, SVM, 의사결정 트리
- 실습: Teachable Machine(`teachablemachine.withgoogle.com/train`) → Image Project → 강아지·고양이 사진 3장씩 → Train Model → 새 이미지로 테스트
### 비지도 학습 / 강화 학습
- 비지도 학습: 레이블 y 없이 컴퓨터가 스스로 데이터의 상관도를 분석해 비슷한 것끼리 모음
  - 대표: 클러스터링(군집화) = 데이터 간 거리를 계산해 몇 개 그룹으로 나눔 (K-means)
- 강화 학습: 행동할 때마다 외부에서 보상이나 처벌
  - 알파고 최종 버전(흑 승리 → 보상, 백 승리 → 처벌), Frozen Lake 같은 게임
  - 어려운 점: **지연 보상**. 행동의 결과가 즉시 나타나지 않을 수 있음
### 머신러닝 과정 (콜라 vs 주스 예)
1. 데이터 수집: 특징으로 색상(파장, nm)과 산성도(pH) 선택
   | 색상(nm) | 산성도(pH) | 레이블 |
   |---|---|---|
   | 610 | 3.8 | 오렌지주스 |
   | 380 | 2.5 | 콜라 |
   | 390 | 2.6 | 콜라 |
   - 행 = 샘플, 열 = 특징
1. 데이터 정제
1. 모델 선택 + 학습
   - 특징이 2개뿐이니 가장 간단한 선형 모델 **y = m·x + b** (m 기울기, b 절편)
   - W, b를 임의로 초기화 → 예측 → 정답과 비교 → 더 정확해지도록 W, b 조정 (반복)
1. 평가: 학습에 안 쓴 테스트 데이터로. 보통 훈련:테스트 = **80:20 또는 70:30**
1. 예측: "색상 600nm, 산성도 1.5인 음료는?" → 학습된 경계에 따라 콜라/주스
- 학습 결과로 만들어진 판별 시스템이 '모델', 모델을 만드는 과정이 '학습(train)'
### 성능 평가
- **정확도 = 올바르게 분류한 샘플 수 / 전체 샘플 수**
- 혼동 행렬: 앞의 True/False는 예측이 맞았는지, 뒤의 Positive/Negative는 예측한 값
| | 예측 긍정 | 예측 부정 |
|---|---|---|
| 실제 긍정 | TP | FN |
| 실제 부정 | FP | TN |
- **민감도(재현율) = TP / (TP + FN)**: 실제 긍정 중 잡아낸 비율
- **특이도 = TN / (TN + FP)**: 실제 부정 중 걸러낸 비율
- 실습: Keras.js 데모 — MNIST 손글씨 숫자 분류, ResNet-50으로 개 품종 추론
### 어디에 쓰나
- 규칙이 너무 복잡해 프로그램으로 쓰기 어려울 때: 영상·음성 인식
- 데이터 특성이 계속 바뀌어 프로그램을 계속 고쳐야 할 때: 주식, 에너지 수요, 쇼핑 추세
- 광고 클릭 예측, 넷플릭스 추천, 자율주행, OCR, 얼굴 인식, 개인 비서
- 경우의 수가 너무 많아 명시적 알고리즘 설계가 어렵거나 불가능할 때
### 프로그래머에게 주는 가치
1. 개발 시간 단축: 맞춤법 교정기를 규칙으로 짜는 대신 예제로 학습
1. 맞춤형 제품 확장: 한국어 교정기를 30개 언어로 → 언어별 예제만 있으면 됨
1. 알고리즘이 떠오르지 않는 문제 해결: 얼굴 인식처럼 전문 지식이 필요한 문제도 예제로 해결
