> 메서드 = 객체의 행위. static이면 클래스로, 아니면 인스턴스로 호출. 이름이 같아도 매개변수가 다르면 오버로딩, 생성자는 반환형 없이 클래스 이름 그대로, 필드는 private으로 숨기고 속성(get/set)으로 노출. 기본 자료형은 값이, 클래스는 참조가 복사된다.
### 메서드 기본
- 매개변수를 받아 처리하고 결과를 반환하는 '함수 상자'
- `[접근 제한자] [반환형] [이름]([매개변수]) { … }`, 반환할 게 없으면 `void`
```csharp
class Test
{
    public int Power(int x) { return x * x; }
    public int Multi(int x, int y) { return x * y; }
    public void Print() { Console.WriteLine("Print() 메서드가 호출되었습니다."); }
}

Test test = new Test();
Console.WriteLine(test.Power(10));      // 100
Console.WriteLine(test.Multi(52, 273)); // 14196
test.Print();
```
- 반환 패턴: 결과 변수를 만들고 → 계산 → return
```csharp
public int Sum(int min, int max)
{
    int output = 0;
    for (int i = min; i <= max; i++) output += i;
    return output;
}
// Sum(1, 100) → 5050
public long Multiply(int min, int max)   // 곱은 금방 커지니 long 권장
{
    long output = 1;
    for (int i = min; i <= max; i++) output *= i;
    return output;
}
// Multiply(1, 10) → 3628800
```
- 자주 쓰는 기능을 메서드로 떼어내 코드를 정리하는 작업 = **리팩토링**
- 반환값은 하나지만, 튜플 `(int, int) MinMax(...)`나 `out` 매개변수로 여러 값을 돌려줄 수도 있음
### 클래스 메서드 (static)
- 인스턴스 없이 `클래스이름.메서드()`. `Main()`도 static
```csharp
class MyMath
{
    public static int Abs(int input) { return input < 0 ? -input : input; }
}
Console.WriteLine(MyMath.Abs(-273));   // 273
```
- static 멤버는 프로그램 시작 시점에 준비되므로, static 메서드 안에서는 **인스턴스 변수·메서드를 쓸 수 없음** (어느 인스턴스의 것인지 모름)
```csharp
class Program
{
    public int instanceVariable = 10;
    static void Main(string[] args)
    {
        Console.WriteLine(instanceVariable);   // 오류! → 변수를 static으로 만들거나 인스턴스를 생성해서 사용
    }
}
```
### 오버로딩
- **같은 이름, 다른 매개변수**(개수나 자료형)로 여러 메서드 선언
```csharp
public static int Abs(int input)       { return input < 0 ? -input : input; }
public static double Abs(double input) { return input < 0 ? -input : input; }
public static long Abs(long input)     { return input < 0 ? -input : input; }
// Abs(-273) → 273, Abs(-32.103) → 32.103, Abs(-21474836470) → 21474836470
```
- **반환형만 다른 건 오버로딩 불가** (컴파일 오류)
- 상속에서 메서드를 재정의하는 **오버라이딩**과는 다른 개념
- 어느 버전이 불리나: 리터럴의 자료형에 가장 잘 맞는 것
```csharp
static int Test(int A)    { return 10; }
static int Test(long A)   { return 20; }
static int Test(float A)  { return 30; }
static int Test(double A) { return 40; }
Console.WriteLine(Test(52273));    // 10 (정수 리터럴 = int)
Console.WriteLine(Test(52.273));   // 40 (실수 리터럴 = double)
```
### 접근 제한자
- `public`: 어디서나 / `private`: 같은 클래스 안에서만 (**생략하면 private**)
- `Main`은 기본 private → 다른 클래스에서 `Program.Main(...)` 호출 불가. 단, Program 안의 중첩 클래스나 Program의 다른 메서드에선 가능
- 그 밖에 `protected`(자식 클래스까지), `internal`(같은 어셈블리)
### 생성자
- 인스턴스를 만들 때 자동 호출, 주로 필드 초기화
- 이름 = 클래스 이름, 보통 public, **반환형을 쓰지 않음**(void도 없음)
- 생성자를 하나도 안 만들면 매개변수 없는 **기본 생성자**가 자동으로 생김
- `this`: 자기 자신. `this.name = name;`은 필드 name ← 매개변수 name
```csharp
class Product
{
    public static int counter = 0;
    public int id;
    public string name;
    public int price;

    public Product(string name, int price)
    {
        Product.counter = counter + 1;
        this.id = counter;
        this.name = name;
        this.price = price;
    }
}

Product productA = new Product("감자", 2000);
Product productB = new Product("고구마", 3000);
Console.WriteLine(productA.id + ":" + productA.name);   // 1:감자
Console.WriteLine(productB.id + ":" + productB.name);   // 2:고구마
Console.WriteLine(Product.counter + "개 생성되었습니다."); // 2개 생성되었습니다.
```
- **private 생성자**: 외부에서 `new` 금지 → static 멤버만 있는 유틸 클래스(Math처럼), 팩토리 메서드로만 생성하게 할 때
- **정적 생성자** `static Sample() { … }`: static 필드 초기화용. 접근 제한자·매개변수 없음, 클래스를 처음 쓸 때 **한 번만** 자동 호출
- **소멸자** `~Product() { … }`: 가비지 컬렉터가 인스턴스를 수거할 때 호출. C++과 달리 **언제 불릴지 정해져 있지 않음** (자원 정리는 보통 `IDisposable`/`using`으로)
- 상속 시 생성자는 부모 → 자식 순, 소멸자는 자식 → 부모 순 (`new B()` → A의 생성자, B의 생성자, … B의 소멸자, A의 소멸자)
- `const`: 컴파일 시점에 고정되는 상수 (`public const double PI = 3.141592;`, 메서드 안에서도 가능)
- `readonly`: 선언할 때나 **생성자 안에서만** 값을 정할 수 있고 그 뒤로는 변경 불가 (인스턴스마다 다른 고정값, 예: id)
### 속성 (Property)과 캡슐화
- 필드가 public이면 밖에서 너비에 −10 같은 잘못된 값을 넣을 수 있음 → **private으로 숨기고** 검증하는 통로만 공개 = 캡슐화
- 예전 방식: 게터 `GetWidth()`, 세터 `SetWidth(int)`
- C# **속성**: 게터·세터를 필드처럼 쓰는 문법. `set`에 들어온 값은 `value`, 속성 이름은 대문자로
```csharp
class Box
{
    private int width;
    public int Width
    {
        get { return width; }
        set
        {
            if (value > 0) width = value;
            else Console.WriteLine("너비는 자연수를 입력해주세요.");
        }
    }

    private int height;
    public int Height
    {
        get { return height; }
        set
        {
            if (value > 0) height = value;
            else Console.WriteLine("높이는 자연수를 입력해주세요.");
        }
    }

    public Box(int width, int height)
    {
        Width = width;      // 속성을 거치므로 검증됨
        Height = height;
    }

    public int Area() { return width * height; }
}

Box box = new Box(10, 10);
box.Width = -5;             // "너비는 자연수를 입력해주세요." (값은 그대로 10)
```
- 검증이 필요 없으면 **자동 구현 속성**: `public int Width { get; set; }` (컴파일러가 숨은 필드를 만들어 줌). `{ get; private set; }`처럼 한쪽만 제한도 가능
- VS 코드 조각: `prop` + Tab Tab → 자동 속성, `propfull` + Tab Tab → 필드 + 속성 전체
### 값 복사 vs 참조 복사
- **값 형식**(int, double, bool, char, struct): 변수에 값 자체 → 넘기면 값이 복사됨
- **참조 형식**(class 인스턴스, 배열, string): 변수에 힙에 있는 객체의 주소 → 넘기면 주소가 복사되어 **같은 객체**를 가리킴
```csharp
static void Change(int input) { input = 20; }
int a = 10;
Change(a);
Console.WriteLine(a);            // 10 (복사본만 바뀜)

class Test { public int value = 10; }
static void Change(Test input) { input.value = 20; }
Test test = new Test();
Change(test);
Console.WriteLine(test.value);   // 20 (같은 객체를 수정)
```
- `int a = test.value; test.value = 20;` 후 `a`는 여전히 10 (값을 꺼내 복사했으므로) → `20 10`
- 값 형식도 참조로 넘기려면 `ref`/`out` 키워드
### 재귀와 메모화
- 재귀: 자기 자신을 호출하는 메서드. **종료 조건** 필수
```csharp
class Fibonacci
{
    private static Dictionary<int, long> memo = new Dictionary<int, long>();

    public static long Get(int i)
    {
        if (i <= 0) return 0;          // 종료 조건
        if (i == 1) return 1;
        if (memo.ContainsKey(i)) return memo[i];   // 이미 계산했으면 바로 반환
        long value = Get(i - 2) + Get(i - 1);
        memo[i] = value;
        return value;
    }
}
Console.WriteLine(Fibonacci.Get(40));    // 102334155
```
- 메모화 없는 재귀는 같은 값을 반복 계산해 호출 수가 지수적으로 늘어남(Get(40)만 해도 수억 번 호출) → 계산 결과를 저장해 두는 **메모화**로 O(n)
- 주의: 교재에서 `Get(100)`의 결과로 나오는 `3736710778780434371`은 사실 **long 오버플로가 난 값**
  - 실제 피보나치(100) = 354224848179261915075 (long 최댓값 약 9.2 × 10¹⁸을 넘음)
  - long으로 정확히 구할 수 있는 건 Get(92) = 7540113804746346429까지. 그 이상은 `System.Numerics.BigInteger`를 써야 함
### 윈도 폼에서 메서드
- 디자이너에서 Button, TextBox, Label 배치 → 속성 창 번개 아이콘(이벤트) → `Click` 더블클릭 → 이벤트 메서드 자동 생성
```csharp
private void button1_Click(object sender, EventArgs e)
{
    textBox1.Text += "+";
    label1.Text += "+";
}
```
- `sender`: 이벤트를 일으킨 객체 (버튼 여러 개를 한 메서드에 연결했을 때 누가 눌렸는지 구분)
```csharp
private void Button1_Click(object sender, EventArgs e)
{
    Button self = (Button)sender;
    self.Text = "처음 클릭했습니다!";
}
```
- `e`: 이벤트 관련 추가 정보 (마우스 좌표, 닫힘 이유 등 이벤트마다 다른 EventArgs 파생형)
- **Timer**: 화면에 안 보이는 구성 요소. `Enabled`(동작 여부), `Interval`(ms, 1000 = 1초), `Tick` 이벤트(주기마다 발생)
```csharp
private int elapsedTime = 0;
private void timer1_Tick(object sender, EventArgs e)
{
    elapsedTime++;
    textBox1.Text = elapsedTime + "초 경과";
    label1.Text = elapsedTime + "초 경과";
}
```
### 연습문제 포인트
- 반환할 게 없으면 `void` (null 아님)
- 같은 이름 + 다른 매개변수 = 오버**로딩** (오버라이드 아님)
- private 생성자도 가능
- 관례: 필드(변수)는 소문자, 속성은 대문자로 시작
- 클래스 메서드는 `static`, 소멸자는 `~클래스이름()`, 어디서나 접근은 `public`
- 기본 자료형은 **값 복사**
