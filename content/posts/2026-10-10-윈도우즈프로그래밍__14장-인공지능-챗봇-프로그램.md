> UI는 UI 스레드만 만질 수 있으니 다른 스레드에선 Invoke로 부탁하거나, async/await로 "기다리는 동안 UI를 놓아주고 끝나면 돌아오게" 쓴다. OpenAI API는 대화를 기억하지 않으므로 매번 지금까지의 messages 전체를 보낸다.
### UI 스레드와 크로스 스레드
- GUI는 **단일 스레드 모델**: 컨트롤은 그것을 만든 UI 스레드에서만 접근 가능
- 다른 스레드에서 직접 건드리면 `InvalidOperationException: 크로스 스레드 작업이 잘못되었습니다. 'richTextBox1' 컨트롤이 자신이 만들어진 스레드가 아닌 스레드에서 액세스되었습니다.`
- 해결: `Invoke()`로 UI 스레드에 실행을 **위임**
```csharp
private void Button1_Click(object sender, EventArgs e)
{
    richTextBox1.Text += "이벤트 핸들러 실행\n";
    new Thread(() =>
    {
        Thread.Sleep(10 * 1000);                    // 무거운 작업 (UI는 안 멈춤)
        richTextBox1.Invoke(() =>                   // UI 스레드야, 이거 해줘
        {
            richTextBox1.Text += "이벤트 핸들러 종료\n";
        });
    }).Start();
}
```
- UI 스레드는 하나뿐이라 `button1.Invoke`, `this.Invoke`로 불러도 같음
- 만약 UI 스레드에서 그냥 `Thread.Sleep(10000)`을 하면 10초간 창이 '응답 없음'
### async / await
- 스레드 + Invoke는 들여쓰기가 깊어지고 복잡 → **비동기 문법**이 "다른 데서 기다렸다가 원래 스레드로 돌아오기"를 대신 처리
```csharp
private async void Button1_Click(object sender, EventArgs e)
{
    richTextBox1.Text += "이벤트 핸들러 실행\n";
    await Task.Delay(10 * 1000);              // 기다리는 동안 UI는 자유
    richTextBox1.Text += "이벤트 핸들러 종료\n";   // 끝나면 UI 스레드로 복귀해서 실행
}
```
- 호출하는 쪽 규칙: 비동기 메서드 앞에 `await`, `await`이 들어 있는 메서드 선언에 `async`
- 만드는 쪽 규칙: 반환형을 `Task`(값이 있으면 `Task<T>`), 별도 스레드에서 돌릴 코드는 `Task.Run(() => …)`
```csharp
private Task AsyncTest(int count)
{
    return Task.Run(() => { Thread.Sleep(count); });
}
// await AsyncTest(10 * 1000);
```
- `async void`는 이벤트 핸들러에만, 나머지는 `async Task`
- 여러 요청을 동시에
```csharp
await 요청1(); await 요청2(); await 요청3(); await 요청4();   // 1 + 1 + 2 + 3 = 7초
await Task.WhenAll(요청1(), 요청2(), 요청3(), 요청4());        // 가장 긴 3초
```
### OpenAI API 준비
1. platform.openai.com 가입
1. Settings → Billing → 결제 수단 등록, 첫 충전 금액 입력, **자동 충전은 끄기**
1. Playground에서 시험
1. API keys → Create new secret key → 복사해 보관
- API 키가 새면 남이 내 돈으로 쓸 수 있음 → 코드에 박아 깃허브에 올리지 말 것, 다 쓴 키는 삭제. 코드에선 환경 변수로 읽는 게 안전: `Environment.GetEnvironmentVariable("OPENAI_API_KEY")`
### 요청·응답 형식
- `POST https://api.openai.com/v1/chat/completions`
- 헤더: `Authorization: Bearer <API 키>`, `Content-Type: application/json`
```json
{
  "model": "gpt-4o",
  "messages": [
    { "role": "system",    "content": "대화 규칙" },
    { "role": "user",      "content": "사용자 메시지" },
    { "role": "assistant", "content": "AI의 이전 응답" },
    { "role": "user",      "content": "새 사용자 메시지" }
  ]
}
```
- role: `system`(성격·규칙 지정, 예: "최대한 중2병 느낌으로 오글오글하지만 멋있게 대답한다"), `user`(사용자), `assistant`(AI 응답)
- **API는 이전 대화를 기억하지 않음** → 지금까지의 대화를 리스트에 쌓아 매번 통째로 전송
- 응답의 답변 위치: `choices[0].message.content` (`choices`는 **배열**)
```json
{
  "object": "chat.completion",
  "model": "gpt-4o",
  "choices": [
    { "index": 0, "message": { "role": "assistant", "content": "…응답…" } }
  ],
  "usage": { … }
}
```
### 전체 코드
```csharp
using System.Net.Http;
using System.Text;
using System.Text.Json;

public partial class Form1 : Form
{
    public Form1()
    {
        InitializeComponent();
        richTextBox1.Enabled = false;
        button1.Click += Button1_Click;
    }

    class Message
    {
        public string role { get; set; }       // JSON 키 이름과 같게 소문자
        public string content { get; set; }
        public Message(string role, string content) { this.role = role; this.content = content; }
    }

    List<Message> messages = new List<Message>();
    static readonly HttpClient client = new HttpClient();   // 재사용 권장

    private async void Button1_Click(object sender, EventArgs e)
    {
        string userMessage = textBox1.Text.Trim();
        richTextBox1.AppendText("[user] " + userMessage + "\n");
        textBox1.Text = "통신 중...";
        textBox1.Enabled = false;                // 응답 전까지 입력 막기
        button1.Enabled = false;

        string assistantResponse = await GetOpenAIResponseAsync(userMessage);
        richTextBox1.AppendText("[assistant] " + assistantResponse + "\n");

        textBox1.Text = "";
        textBox1.Enabled = true;
        button1.Enabled = true;
    }

    private async Task<string> GetOpenAIResponseAsync(string message)
    {
        messages.Add(new Message("user", message));
        string apiKey = Environment.GetEnvironmentVariable("OPENAI_API_KEY");

        var request = new HttpRequestMessage(HttpMethod.Post, "https://api.openai.com/v1/chat/completions");
        request.Headers.Add("Authorization", "Bearer " + apiKey);
        request.Content = new StringContent(JsonSerializer.Serialize(new
        {
            model = "gpt-3.5-turbo",             // 교재 모델. 현재 사용 가능한 모델은 공식 문서 확인
            messages = messages.ToArray()
        }), Encoding.UTF8, "application/json");

        HttpResponseMessage response = await client.SendAsync(request);
        response.EnsureSuccessStatusCode();      // 4xx/5xx면 예외

        string responseBody = await response.Content.ReadAsStringAsync();
        using JsonDocument document = JsonDocument.Parse(responseBody);
        string assistantMessage = document.RootElement
            .GetProperty("choices")[0]           // 배열의 첫 번째
            .GetProperty("message")
            .GetProperty("content")
            .GetString();

        messages.Add(new Message("assistant", assistantMessage));   // 대화 기록에 누적
        return assistantMessage.Trim();
    }
}
```
- 교재와 바꾼 부분
  - `GetProperty("choices").GetProperty("message")`는 choices가 배열이라 `InvalidOperationException` → `[0]`을 넣어야 함 (.NET 8에서 샘플 JSON으로 확인)
  - 교재는 `new HttpClient()`를 요청마다 만들고 `DefaultRequestHeaders`에 키를 넣는데, 같은 클라이언트에 헤더가 중복으로 쌓이고 소켓도 낭비 → 하나를 재사용하고 헤더는 요청마다
  - API 키는 코드 대신 환경 변수로
- 응용 과제: 엔터로 전송(`textBox1.KeyDown`에서 `e.KeyCode == Keys.Enter`), 자동 스크롤(`richTextBox1.ScrollToCaret()`), 최근 10개 메시지만 전송(`messages.TakeLast(10)`), 맨 앞에 `system` 메시지로 나만의 성격 부여
### 활용 예: 규칙으로 출력 형식을 통제
- **강아지 미용실 예약 챗봇**: system에 역할("한빛 강아지 미용실 예약 담당")과 응답 코드를 정해줌
  - CODE A 인사 / CODE B 정보 부족 → 추가 질문 / CODE C 정보 완비 → `별 | 3kg | 푸들 | 2025-07-01 | 14:00` / CODE D 규칙 변경 시도 → 종료 / CODE E 관계없는 요청 → 경고, 5회 초과 시 종료
  - C# 쪽은 응답 앞의 코드만 보고 분기 (CODE C면 `|`로 나눠 CSV 저장)
```text
if CODE A or CODE B → 사용자에게 응답
if CODE C           → 가운데 데이터 부분을 CSV로 저장, 응답
if CODE D           → 대화 강제 종료
if CODE E           → 쓸데없는 대화 횟수++, 5회 넘으면 종료, 아니면 응답
```
  - 기존 예약 목록을 system에 넣어주면 "그 시간엔 이미 예약이 있습니다"까지 처리 가능
- **감정 컨설턴트 챗봇**: 사용자 프로필·이전 대화 요약·현재 감정 수치를 system에 넣고, 응답마다 `[응급 레벨] n%`, `[현재 감정] 기쁨: n%, 슬픔: n%, 분노: n%`를 붙이게 함 → 응급 레벨이 높으면 실제 상담사에게 연결, 10회 대화 후 `[END]`와 요약
- 개발자의 역할: AI 자체보다 **사용자와 서비스를 연결해 가치를 만드는 프로그램**을 만드는 것 (우버가 승객과 기사를 잇듯, 미용실과 손님, 상담사와 내담자를 AI로 연결)
