> Codex를 지탱하던 관리형 하네스와 샌드박스 인프라를 단일 API로 꺼내 장기 실행 에이전트를 바로 구축할 수 있게 됨 !

# 개요
- 무엇 : OpenAI가 2026.09.10에 장시간 구동 에이전트 인프라인 Agents API 공개
- 한 줄 정의 : Agents API는 Codex 운영 노하우가 담긴 관리형 하네스와 샌드박스를 단일 엔드포인트로 제공하는 개발자용 API다.
- 원문 : [Introducing the Agents API](https://openai.com/index/introducing-the-agents-api)

# 그래서 도대체 뭔데 ?
- 복잡한 작업을 며칠 동안 수행하는 에이전트를 만들려면 신경 쓸 게 너무 많았음.
- 단순 프롬프트 호출을 넘어 세션 유지 · 샌드박스 환경 격리 · 컨텍스트 압축 · 하위 에이전트 조율을 백엔드에서 직접 짜야 했음.
- Agents API는 이 복잡한 제어 루프를 OpenAI가 완전 관리형(managed)으로 도맡아 처리함.
- 개발자는 작업 · 모델 · 도구 · 환경만 지정하면 API 호출 한 번으로 프로덕션 수준 에이전트를 바로 띄울 수 있음.
	- 💡 하네스(Harness) : 모델이 도구를 호출하고 컨텍스트를 유지하며 작업을 끝까지 완수하도록 감싸는 오케스트레이션 제어 틀
	- 💡 샌드박스(Sandbox) : 에이전트가 격리된 상태에서 안전하게 코드를 실행하고 파일을 편집하는 독립 연산 환경

# 어떻게 동작하나 ?
1. 세션 생성 및 환경 프로비저닝
	- 세션 생성 요청 시 작업에 필요한 샌드박스 연산 환경이 함께 준비됨.
	- OpenAI 자체 호스팅 샌드박스를 쓰거나 파트너 연동 인프라를 연결할 수 있음.
	→ 안전한 격리 환경에서 셸 명령 실행과 파일 아티팩트 생성이 가능해짐

2. 컨텍스트 자동 압축
	- 장기 세션 진행 도중 토큰 한계에 다다르면 서버 측 압축이 동작함.
	- 이전 대화 내역과 추론 상태를 암호화된 불투명 아이템으로 요약 보존함.
	→ 개발자가 수동 프루닝 로직을 짜지 않아도 긴 세션의 문맥이 이어짐

3. 도구 탐색 및 실행
	- 수많은 도구 정의를 매번 프롬프트에 전부 넣지 않고 필요한 시점에 탐색함.
	- 도구를 병렬로 실행하거나 결과를 코드 레벨에서 거른 뒤 필수 정보만 문맥에 올림.
	→ 모델 캐시를 보존하면서 불필요한 토큰 낭비를 줄임

4. 하위 에이전트 병렬 위임
	- 메인 에이전트가 큰 작업을 쪼개어 독립된 서브에이전트에게 전달함.
	- 각 서브에이전트는 자체 컨텍스트를 유지하며 병렬로 작업을 수행하고, 메인 에이전트가 결과를 합침.
	→ 단일 컨텍스트가 오염되는 것을 막고 분석이나 조사 속도를 단축함

# 기존이랑 뭐가 다른가 ?
- 이전 방식 : 하네스 제어 루프(도구 탐색 · 컨텍스트 압축 · 서브에이전트 조율)와 연산 샌드박스 인프라를 개발자가 직접 구축하고 관리해야 했음.
- 이번 방식 : 단 한 번의 API 호출로 인프라 프로비저닝부터 하네스 제어 루프까지 OpenAI 클라우드에서 일괄 처리함.
→ 인프라 구축과 예외 복구 비용이 줄어 도구 설계와 워크플로 최적화에만 집중할 수 있게 됨.

# 주의할 점 / 한계
- 현재 퍼블릭 베타 단계라 세부 기능과 인터페이스가 계속 바뀔 수 있음.
- 서브에이전트가 동일한 파일을 동시에 수정하면 충돌이 생길 수 있어 변경 순서 조율이 필요함.
- 짧은 단발성 작업이나 앞뒤 의존성이 강한 단계는 서브에이전트로 쪼개기보다 메인 에이전트에서 처리하는 편이 적합함.
- 벤치마크 정량 수치(속도 향상 비율, 성공률 수치 등)는 원문에 없음.

# 정리
- 수작업으로 때우던 에이전트 오케스트레이션과 샌드박스 운영을 인프라 레벨로 흡수한 API임.
- 복잡한 자율 코딩 · 대량 문서 교차 검토 · 다단계 조사 에이전트를 운영 인프라 고민 없이 띄우려는 개발자에게 유용함.
