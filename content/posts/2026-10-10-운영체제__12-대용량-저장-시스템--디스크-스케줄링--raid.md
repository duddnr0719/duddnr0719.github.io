> 디스크 접근 시간의 대부분은 탐색 시간 → 요청 순서를 바꿔 헤드 이동을 줄이는 게 디스크 스케줄링(FCFS 640 → SSTF·SCAN 236). 신뢰성은 RAID(미러링, 패리티)와 두 벌씩 쓰는 안정 저장소로.
### 대용량 저장장치
- **자기 디스크(HDD)**: 보조 저장장치의 주력
  - 회전 속도 초당 60~250회 (3,600~15,000 rpm)
  - 전송률: 드라이브 ↔ 컴퓨터 데이터 속도
  - **위치 결정 시간(임의 접근 시간)** = **탐색 시간**(암을 원하는 실린더로 이동) + **회전 지연**(원하는 섹터가 헤드 밑으로 올 때까지)
  - 헤드 충돌: 헤드가 표면에 닿음 → 치명적 손상
- **자기 테이프**: 백업, 잘 안 쓰는 데이터 보관, 시스템 간 이동
  - 스풀에 감긴 테이프가 헤드를 지나감. 원하는 위치까지 감는 건 느리지만 일단 도달하면 디스크급 전송률(140MB/s 이상)
  - 200GB~1.5TB (LTO-3/4/5, T10000)
### 디스크 구조
- 디스크 = 1차원 **논리 블록** 배열 (논리 블록 = 최소 전송 단위)
- 저수준 포맷이 물리 매체에 블록을 만들고, 논리 블록 → 섹터로 매핑
  - 섹터 0 = 가장 바깥 실린더의 첫 트랙 첫 섹터 → 그 트랙 → 같은 실린더의 다른 트랙 → 안쪽 실린더 순
- 매핑은 빠르고 단순해야 함. 불량 섹터는 건너뜀
- CAV(등각속도)에선 트랙마다 섹터 수가 다름 (CLV면 바깥 트랙에 섹터가 더 많음)
### 디스크 연결
- **호스트 연결**: I/O 포트로 로컬 버스에 직접
  - SCSI: 버스형, 케이블당 장치 최대 16개. initiator(요청) ↔ target(수행), target마다 LUN(논리 장치) 최대 8개
  - FC(Fibre Channel): 고속 직렬, 스위치드 패브릭, 24비트 주소 → SAN의 기반. 주소 = 버스 ID + 장치 ID + LUN
- **저장 어레이**: 컨트롤러 + 호스트 포트 + 메모리 + 제어 SW(일부 NVRAM), 디스크 수 개~수천 개
  - RAID, 핫 스페어, 핫 스왑 / 스냅샷, 클론, 씬 프로비저닝, 복제, 중복 제거
- **NAS**: 로컬 버스가 아니라 네트워크로 접근하는 **파일** 수준 저장소. 원격 파일 시스템을 마운트 (NFS, CIFS, IP 위의 RPC)
  - iSCSI: IP 네트워크로 SCSI 명령을 실어 **블록** 수준 원격 접근
- **SAN**: 여러 호스트와 여러 저장 어레이를 FC 스위치로 다대다 연결하는 전용 저장 네트워크 (대규모 환경의 사실상 표준)
  - LUN 마스킹: 특정 어레이를 특정 서버에만 보이게
  - 저장소 추가·제거, 호스트에 할당이 쉬움. 저장 트래픽과 통신 트래픽 분리
  - 추세: iSCSI, FCoE로 이더넷과 수렴
### 디스크 스케줄링
- 목표: 접근 시간 단축 + **대역폭** 극대화. 핵심은 **탐색 시간** 최소화 (탐색 거리에 비례)
- 디스크 대역폭 = 총 전송 바이트 / 첫 요청부터 마지막 전송 완료까지 걸린 시간
- I/O 요청이 드라이버에 넘기는 정보: 읽기/쓰기, 디스크 주소, 메모리 주소, 섹터 수. 디스크가 바쁘면 큐에 쌓이고, 쌓인 요청의 처리 순서를 고르는 게 스케줄링
- 예: 실린더 0~199, 헤드 53, 요청 큐 `98, 183, 37, 122, 14, 124, 65, 67`
| 알고리즘 | 방식 | 순서 | 이동 거리 |
|---|---|---|---|
| FCFS | 들어온 순서대로 | 98, 183, 37, 122, 14, 124, 65, 67 | **640** |
| SSTF | 현재 위치에서 가장 가까운 것 | 65, 67, 37, 14, 98, 122, 124, 183 | **236** |
| SCAN | 한쪽 끝까지 가며 처리, 끝에서 반전 (엘리베이터) | (0 쪽으로) 37, 14, **0**, 65, 67, 98, 122, 124, 183 | **236** |
| LOOK | SCAN인데 끝까지 안 가고 마지막 요청에서 반전 | 37, 14, 65, 67, 98, 122, 124, 183 | 208 |
| C-SCAN | 한 방향으로만 처리, 끝에 닿으면 처리 없이 반대쪽 끝으로 복귀 | (199 쪽으로) 65 … 183, **199**, (0으로 복귀), 14, 37 | 146 + 199 + 37 = 382 (복귀 포함) |
| C-LOOK | C-SCAN인데 마지막 요청에서 반대편 첫 요청으로 바로 점프 | 65 … 183 → 14, 37 | 130 + 169 + 23 = 322 (점프 포함) |
- LOOK·C-SCAN·C-LOOK 수치는 위 조건으로 직접 계산한 것 (복귀·점프 이동을 셀지 말지는 교재마다 다름)
- SSTF는 SJF 같은 것이라 **기아** 가능 (헤드 근처에 요청이 계속 오면 먼 요청은 영원히 대기). 그리고 최적도 아님
- SCAN은 헤드가 막 지나간 곳의 요청이 오래 기다림 → C-SCAN은 디스크를 원형으로 보고 한 방향으로만 처리해 **대기 시간을 더 고르게**
- 선택
  - SSTF가 흔하고 무난 (기본값)
  - 부하가 큰 시스템엔 SCAN, C-SCAN (기아 적음)
  - 성능은 요청의 수·종류, 파일 할당 방식(연속 할당이냐 등)에 좌우
  - 스케줄러는 OS의 별도 모듈로 두어 교체 가능하게. 기본 추천은 SSTF 또는 LOOK
### 디스크 관리
- **저수준(물리) 포맷**: 제조사가 빈 디스크에 섹터 구조를 기록. 섹터 = 헤더 + 데이터(보통 512B) + 트레일러, 헤더·트레일러에 섹터 번호, ECC
- OS의 준비 작업
  1. **파티셔닝**: 디스크를 하나 이상의 실린더 그룹으로 나눔
  1. **논리 포맷**: 파일 시스템 생성 (자료구조 기록)
- **부트 블록**: 부트스트랩 프로그램을 디스크의 정해진 위치에 둠
  - Windows: 첫 섹터 **MBR**(부트 코드 + 파티션 테이블) → 부트 파티션을 찾아 거기서 OS 로드
- **불량 블록**: 결함으로 못 쓰는 블록 → 예비 섹터로 매핑 테이블에서 대체(sector sparing), 또는 섹터 슬리핑(뒤 섹터들을 하나씩 밀어 공간 확보)
### 스왑 공간 관리
- 메모리가 부족할 때 페이지(또는 프로세스)를 내보내는 디스크상의 전용 영역
- 성능 영향이 커서 신중히 관리 (스왑이 잦으면 디스크 I/O 폭증 → 체감 성능 급락)
- 파일 시스템 위의 일반 파일로 둘 수도 있고(쉽지만 느림), 별도 raw 파티션으로 둘 수도 있음(빠름)
- Linux: 스왑 영역마다 페이지 슬롯 배열과 **swap_map**(슬롯마다 그 페이지를 쓰는 프로세스 수 카운터)으로 관리
### RAID
- **R**edundant **A**rray of **I**nexpensive(Independent) **D**isks: 여러 디스크를 묶어 중복성으로 신뢰성을, 병렬성으로 성능을 높임
- 신뢰성 지표
  - MTTF: 평균 고장 시간 / MTTR: 평균 복구 시간 / MTTDL: 데이터 손실까지 평균 시간
  - 미러링 + 독립 고장 가정: **MTTDL = MTTF² / (2 × MTTR)**
  - MTTF 100,000시간, MTTR 10시간 → 100,000² / 20 = **500 × 10⁶시간 ≈ 57,000년** (교재 예)
  - 슬라이드엔 MTTF가 1,300,000시간으로 적혀 있는데, 그 값으로 계산하면 약 8.45 × 10¹⁰시간이라 결과(500 × 10⁶)와 맞지 않음 → 100,000시간이 맞는 조건
| 레벨 | 방식 | 특징 |
|---|---|---|
| RAID 0 | 블록 스트라이핑 | 성능 최대, 중복 없음 (하나 고장 = 전체 손실) |
| RAID 1 | 미러링 (섀도잉) | 디스크마다 사본, 가장 직관적, 용량 2배 |
| RAID 4 | 블록 인터리브 + 전용 패리티 디스크 | 패리티 디스크가 병목 |
| RAID 5 | 블록 인터리브 + 분산 패리티 | 디스크 1개 고장 허용, 가장 흔함 |
| RAID 6 | 이중 패리티(P + Q) | 디스크 2개 동시 고장 허용 |
| RAID 0+1 / 1+0 | 스트라이프를 미러 / 미러를 스트라이프 | 성능 + 신뢰성 (1+0이 고장에 더 강함) |
- **핫 스페어**: 할당 안 하고 대기하다 고장 나면 자동 교체·재구성
- 어레이 자체 고장에 대비해 어레이 간 자동 복제도 일반적
### 안정 저장소 (Stable Storage)
- 쓰기 전 로그(write-ahead logging) 같은 기법은 **어떤 고장에도 잃지 않는 저장소**가 있다고 전제
- 구현: 서로 독립적으로 고장 나는 비휘발성 매체 2개 이상에 복제 + 고장이 나도 복구 가능하게 순서를 통제한 갱신
- 디스크 쓰기의 결과 3가지: 성공 / 부분 실패(일부 섹터만 기록, 기록 중이던 섹터 손상) / 완전 실패(시작도 못 함, 이전 데이터 유지)
- 논리 블록 하나당 물리 블록 2개
  1. 첫 번째 블록에 씀
  1. 성공하면 두 번째에 같은 내용을 씀
  1. 두 번째까지 성공해야 완료
  - 복구: 두 블록을 비교 → 하나가 깨졌으면 다른 쪽으로 덮어쓰고, 둘 다 멀쩡한데 내용이 다르면 첫 번째로 두 번째를 덮어씀
  - 두 블록 중 하나를 NVM(비휘발성 메모리)에 두어 빠르게
- **ZFS**: 파티션 대신 **풀(pool)** 에서 볼륨을 malloc/free처럼 동적으로 할당, 모든 데이터·메타데이터에 체크섬
