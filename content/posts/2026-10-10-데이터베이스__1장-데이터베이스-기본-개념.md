> 데이터베이스 = 여러 사용자가 공유하도록 통합해서 저장한 운영 데이터의 집합. 위치가 아니라 내용으로 찾는다.
### 과목 개요
- 정보처리 교과 단계: 프로그래밍 언어·기법 → 자료구조·파일구조 → **데이터베이스**(최상위)
- 설계부터 응용 프로그램 작성까지 다루는 실무 과목. 교재: 데이터베이스 개론(김연희, 한빛아카데미)
- 진도: 기본 개념 → DBMS → DB 시스템 → 데이터 모델링 → 관계 데이터 모델 → 관계 연산 → (중간) → DB 설계(개념/논리) → 정규화 → 회복 → 병행 제어
### 데이터, 정보, 지식
- 데이터: 현실에서 관찰·측정해 모은 사실이나 값. 메타데이터(데이터에 대한 데이터, "~에 관한")도 포함.
- 정보: 의사 결정에 쓸 수 있게 데이터를 처리한 결과. **무결성(정확성)**이 중요.
  - 비유: 원유(데이터) → 가공(정보 처리) → 가공 우유(정보)
- 정보 처리: 데이터에서 정보를 뽑는 과정
  - 예: 쇼핑몰 주문 내역(데이터) → 제품별·분기별 총 판매액(정보)
- 지식: 빅데이터에서 경험적으로 뽑은 도움 되는 사항. **가치**가 중요.
  - 예: "에어컨은 여름 전에 판매량이 늘어난다"
### 정보 시스템과 DB
- 정보 시스템: 조직 운영에 필요한 데이터를 모아 저장했다가 필요할 때 정보를 만들어 주는 수단 (MIS, DSS 등)
- DB는 그 안에서 데이터를 저장·제공하는 핵심 (Data Cabinet)
- 흐름: 현실 세계 → 데이터 → 정보 시스템(처리 ↔ DB) → 정보 → 의사 결정자
### 파일 시스템 vs DB 시스템
- 파일: 특정 응용 목적의 데이터 집합 (인사, 총무, 성적 데이터)
- DB: 여러 응용 파일의 집합. 1963년 Bachman이 제안.
- DB 시스템의 목적: 다중 사용자 대상, 데이터 통합, 정보 공유, 효율적·체계적 관리
- 파일 시스템: 부서마다 따로 파일을 가짐 → 공유 어려움, 데이터 불일치, 보안 문제, **중복**
- DB 시스템: 모든 부서가 DBMS를 통해 하나의 통합 DB에 접근. 프로그래머(응용 프로그램)도 일반 사용자(질의어)도 같은 DB 사용.
### DB의 정의 (4가지 키워드)
- **통합 데이터**(integrated): 최소한의 중복, 통제 가능한 중복만 허용
- **저장 데이터**(stored): 컴퓨터가 접근 가능한 매체에 저장
- **공유 데이터**(shared): 조직의 여러 사용자가 함께 소유·이용
- **운영 데이터**(operational): 조직의 기능 수행에 지속적으로 꼭 필요
### DB의 특성
- 실시간 접근(real-time accessibility): 요구에 실시간 응답
- 계속 변화(continuous evolution): 삽입·삭제·수정으로 현재의 정확한 데이터 유지
- 동시 공유(concurrent sharing): 다른 데이터는 물론 같은 데이터도 동시에 사용
- 내용 기반 참조(contents reference): 주소·위치가 아니라 내용으로 참조
### 주소 기반 vs 내용 기반 참조
- 주소 기반: "메모리 1000번지 데이터 가져와"
- 내용 기반: "학번 1003인 학생 정보 가져와"
```sql
SELECT * FROM emp WHERE deptno = 10;
```
- 장점
  1. 저장 위치 몰라도 조건만 주면 검색
  1. 물리적 구조(디스크 어디에 있는지)에 독립적
  1. 추가·삭제·이동이 있어도 같은 조건으로 찾음
  1. 물리적 데이터 독립성 확보
### DB vs 빅데이터 분석
- DB: 운영 데이터 → 정보 처리 → 정보 / 빅데이터: 분석 데이터 → 데이터 분석 → 지식
| 구분 | DB(운영 데이터) | 빅데이터(분석 데이터) |
|---|---|---|
| 대상 | 현재 유지되는 중요 사실, 무결성 필수 | 현재·과거 데이터, 무결성보다 양과 의미 |
| 처리 | 관계 대수 등 수학적 기법, 효율성 중시 | 통계, 머신러닝, 활용성 중시 |
| 결과 | 오류 없는 정확한 정보 | 정확성보다 가치가 중요한 지식 |
| 크기 | GB~TB | PB~ZB, EB |
| 구성 | 레코드·테이블의 정형 데이터, Oracle·MySQL 같은 RDBMS | raw·비정형, Cassandra·MongoDB 같은 NoSQL |
| 아키텍처 | 중앙집중식, 정합성·무결성·보안 중요 | 분산 필수, 정합성·무결성은 덜 중요 |
| 출처 | ERP, CRM 등 온라인 트랜잭션 | SNS, 센서, 시청각, IoT |
| 방법 | 검색·비교 등 정형 연산 (사전 정제 필요) | 통계·ML로 유용한 지식 추출 |
- DB는 운영 데이터로 무결한 정보 처리, 데이터 웨어하우스는 분석 데이터를 보관해 지식 추출
