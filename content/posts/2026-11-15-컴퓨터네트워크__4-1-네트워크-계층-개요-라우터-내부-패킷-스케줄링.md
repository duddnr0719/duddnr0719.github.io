> 네트워크 계층은 로컬 라우터 내부의 포워딩을 담당하는 데이터 평면(Data Plane)과 종단 간 경로를 정하는 제어 평면(Control Plane)으로 구성되며, 인터넷은 단순한 구조의 최선의 노력 서비스(Best-Effort Service)를 기반으로 동작한다. 라우터 내부에서는 최장 프리픽스 대응 규칙(longest prefix matching rule)과 스위칭 구조를 거쳐 패킷을 전달하고, 입력 · 출력 포트 큐잉 지점마다 버퍼 관리와 패킷 스케줄링(FCFS · 우선순위 · 라운드 로빈 · WFQ(Weighted Fair Queuing))으로 전송 대상을 정한다.

### 4장 구성과 강의 목표
- **이번 강의 범위** = 4장(네트워크 계층: 데이터 평면) 총 3부 중 1부(`1/3`)로 **4.1 네트워크 계층 개요**(데이터 평면 · 제어 평면)와 **4.2 라우터 내부에는 무엇이 있을까?**를 다룸
  - 4장 전체 목차의 **4.3 인터넷 프로토콜(IP)**(데이터그램 형식 · 단편화 · IPv4 주소체계 · 네트워크 주소 변환 · IPv6)과 **4.4 일반적인 포워딩 및 소프트웨어 기반 네트워크(SDN)**(매치 · 액션 · match-plus-action 작업의 OpenFlow 예), 강의 목표의 **미들박스(middlebox)**는 본 자료(`1/3`) 범위에 미포함
- **강의 목표** = 데이터 평면을 중심으로 네트워크 계층 서비스의 동작 원리 파악
  - 핵심 주제 = 네트워크 계층 서비스 모델 · 포워딩과 라우팅 · 라우터 동작 방식 · 일반적인 포워딩(generalized forwarding) · 인터넷에서의 네트워크 계층 구현(IP 프로토콜 · NAT · 미들박스)

### 네트워크 계층 개요: 포워딩과 라우팅
- **네트워크 계층(Network Layer)** = 송신 호스트에서 수신 호스트까지 패킷 전달을 담당하는 계층으로 모든 호스트와 라우터에 프로토콜이 탑재됨
  - 송신 측 = 트랜스포트 계층 세그먼트를 **데이터그램(datagram)**으로 캡슐화함
  - 수신 측 = 수신한 데이터그램에서 세그먼트를 분리해 상위 트랜스포트 계층으로 올림
  - **라우터(router)** = 입력 링크에 도착한 IP 데이터그램의 헤더 필드를 판독해 알맞은 출력 링크로 내보내는 장치
- **네트워크 계층의 두 가지 핵심 기능**
  - **포워딩(forwarding, 전달)** = 개별 라우터 단위에서 입력 링크의 패킷을 적절한 출력 링크로 넘기는 동작
  - **라우팅(routing)** = **라우팅 알고리즘(routing algorithm)**을 통해 출발지 호스트부터 목적지 호스트까지의 이동 경로(path)를 산출하는 동작
  - **자가운전 여행 비유** = 라우팅은 출발지부터 목적지까지의 여정을 설계하는 일, 포워딩은 하나의 인터체인지를 통과해 나아가는 과정에 대응됨

### 데이터 평면과 제어 평면
- **데이터 평면(Data Plane)** = 라우터마다 독립적으로 작동하는 로컬(per-router) 기능으로 라우터 내부에 구현됨
  - 입력 포트로 유입된 데이터그램을 어느 출력 포트로 내보낼지 **포워딩 함수**로 판정
- **제어 평면(Control Plane)** = 네트워크 전체 범위의 로직으로, 데이터그램이 출발지부터 목적지까지 어떤 라우터 경로를 거쳐 이동할지 결정
- **제어 평면의 두 가지 구현 방식**
  - **라우터 당 제어 평면(Per-Router Control Plane)** = 각 라우터 내부의 개별 라우팅 알고리즘끼리 제어 평면상에서 상호작용해 경로를 정하는 전통적 방식
  - **논리적 중앙 집중형 제어 평면(SDN, Software-Defined Networking)** = 원격 서버의 중앙 제어기가 포워딩 테이블을 계산해 라우터 내부에 설치

### 네트워크 계층 서비스 모델
- 송신 · 수신 호스트 사이에서 데이터그램을 나르는 전송 채널이 제공할 수 있는 서비스 특성의 정의
- **개별 패킷(데이터그램) 대상 서비스**
  - 보장된 전달(guaranteed delivery)
  - 특정 지연 한도(예: 40ms) 이내의 보장된 전달
- **패킷 흐름(flow) 대상 서비스**
  - 순서화(in-order)된 패킷 전달
  - 보장된 최소 대역폭(minimum bandwidth)
  - 보장된 패킷 간 간격 = 송신 측 두 패킷 사이의 전송 간격이 수신 측에서도 유지되거나 변동 폭이 특정 기준을 넘지 않도록 보장
- **최선의 노력 서비스(Best-Effort Service)**
  - 단순한 구조 덕분에 인터넷이 광범위하게 채택된 핵심 배경이 됨
  - 고속 인터넷 확산으로 비디오 · 음성 통화 같은 실시간 응용에서도 대부분의 시간 동안 정상 작동함
  - 고객 네트워크 인접 지점에 연결된 다수의 애플리케이션 계층 분산 네트워크(데이터 센터 · CDN)가 여러 지점에서 서비스를 제공함
  - 신축성 있는 혼잡 제어가 동작을 보조함

### 라우터 구조와 목적지 기반 포워딩
- **라우터의 두 가지 핵심 역할**
  - RIP · OSPF · BGP 같은 라우팅 알고리즘 및 프로토콜 실행
  - 입력 링크로 들어온 패킷을 출력 링크로 포워딩
- **목적지 기반 포워딩**
  - 32비트 IP 주소 공간은 40억 개를 초과 → 목적지 주소마다 개별 엔트리를 두면 포워딩 테이블 규모가 과도해짐
  - 해결책 = **최장 프리픽스 대응 규칙(longest prefix matching rule)**을 적용해 가장 길게 일치하는 프리픽스 엔트리의 링크 인터페이스로 패킷을 보냄
- **TCAM(Ternary Content Addressable Memory)**
  - 최장 프리픽스 대응 규칙을 구현할 때 쓰는 연관 메모리(associative memory)
  - 비트 매칭 시 `'1'`과 `'0'`뿐 아니라 `'X'`(don't care) 상태를 함께 지원 → 테이블 규모와 무관하게 1클럭 사이클 안에 탐색 완료
  - **구현 예** = Cisco Catalyst 라우터는 1M개의 라우팅 테이블 엔트리를 TCAM에 적재

### 스위칭 구조
- **역할과 스위칭 속도** = 입력 버퍼의 패킷을 알맞은 출력 버퍼로 옮기는 내부 구조
  - **스위칭 속도** = 패킷이 입력에서 출력으로 전달되는 속도로, 입력 · 출력 라인 속도의 배수로 측정함
  - 입력 포트가 N개일 때 라인 속도의 N배 수준 스위칭 속도를 확보하는 편이 바람직함
- **세 가지 스위칭 구조**
  - **메모리를 통한 스위칭(Switching via Memory)** = CPU가 스위칭을 제어하는 1세대 라우터의 전통적 컴퓨터 방식
    - 패킷을 시스템 메모리에 복사해야 하므로 데이터그램 1개당 시스템 버스에 2회 접근 → 메모리 대역폭이 전체 속도를 제한함
  - **버스를 통한 스위칭(Switching via Bus)** = 입력 포트 메모리의 데이터그램을 공유 버스를 거쳐 출력 포트 메모리로 옮기는 방식
    - 버스 충돌(bus contention) 때문에 공유 버스 대역폭이 스위칭 속도의 상한을 결정함
    - **구현 예** = Cisco 5600은 32Gbps 버스를 채택해 접속 네트워크 · 기업 네트워크 라우터 용도에 충분한 속도를 냄
  - **인터커넥션을 통한 스위칭(Switching via Interconnection)** = 본래 멀티프로세서 시스템의 프로세서 간 연결에 쓰이던 크로스바(Crossbar) · Clos 네트워크에서 가져온 방식
    - **다단계 스위치(multistage switch)** = 소형 스위치들을 여러 단계로 엮은 n × n 구조로 병렬 처리를 수행해 버스 대역폭 제약을 해소함
    - 다수의 스위칭 평면으로 병렬화해 처리 성능과 확장성을 함께 높임
    - **구현 예** = Cisco CRS 라우터는 8개 스위칭 평면을 기본으로 두고 각 평면을 3-단계 인터커넥션 네트워크로 구성해 최대 100Tbps 스위칭 속도를 지원함

### 입력 · 출력 포트 큐잉과 버퍼 관리
- **입력 포트 큐잉(Input Port Queuing)**
  - 스위치 구조가 입력 포트에 도착하는 모든 패킷을 곧바로 넘길 만큼 빠르지 못할 때 발생함
  - 입력 버퍼가 넘치면 큐잉 지연 증가 → 패킷 손실로 이어짐
  - **HOL 블로킹(head-of-the-line blocking)** = 큐 선두의 데이터그램이 가로막혀 뒤따르는 다른 패킷의 전달이 지연되는 현상
- **출력 포트 큐잉(Output Port Queuing)**
  - 스위치 구조를 통과한 패킷의 도착 속도가 출력 링크의 전송 속도(라인 속도)를 웃돌면 버퍼링(큐잉)이 필요해짐
  - 네트워크 혼잡으로 버퍼 용량이 부족해지면 출력 버퍼 오버플로우 → 큐잉 지연과 패킷 손실 발생
  - 버퍼 포화 시 내보낼 패킷을 정하는 **폐기 정책(drop policy)**과 전송 순서를 결정하는 **스케줄링 규칙(scheduling discipline)**이 요구됨
- **버퍼링 용량(Buffering Capacity)**
  - **RFC 3439 규칙** = 버퍼 용량(B)은 링크 용량(C)과 전형적인 RTT(250msec)의 곱으로 산정: B = C × RTT
  - **계산 예** = C = 10Gbps 링크일 때 B = 0.25sec × 10Gbps = 2.5Gbit 버퍼 필요
  - **최근 이론** = 다수의 대용량 TCP 흐름(N)이 링크를 지날 때 링크 용량(C) · RTT · 흐름 수(N)를 변수로 버퍼링 용량을 산정(강의자료 텍스트상 수식 기호 일부 누락)
- **버퍼 관리(Buffer Management)**
  - **폐기(drop)** = 버퍼가 가득 찼을 때 어떤 패킷을 수용하고 버릴지 결정하는 정책
    - **꼬리 폐기(tail drop)** = 도착한 패킷을 버림
    - **우선순위(priority)** = 패킷 우선순위를 기준으로 폐기 · 제거 대상을 고름
  - **마킹(marking)** = ECN · RED 같은 혼잡 신호를 어느 패킷에 표시할지 결정

### 패킷 스케줄링
- **스케줄링(scheduling)** = 출력 링크로 내보내기 위해 큐에 쌓인 패킷 중 전송 대상을 고르는 절차
- **FCFS / FIFO(First In First Out) 스케줄링**
  - 큐에 먼저 들어온 패킷부터 순서대로 전송함
  - 큐 포화 상태에 대비한 패킷 폐기 정책(discard policy)이 함께 필요함
- **우선순위 스케줄링(Priority Scheduling)**
  - 패킷 헤더 정보를 바탕으로 트래픽을 분류해 클래스별 큐에 적재함
  - 대기 중인 클래스 큐 가운데 우선순위가 높은 패킷을 먼저 내보내며, 출력 포트에서는 최대 성능과 네트워크 중립성을 가져오는 패킷 선택 관점이 함께 제시됨
  - 동일 우선순위 클래스 큐 안에서는 FCFS 순서로 처리함
- **라운드 로빈 스케줄링(Round Robin Scheduling)**
  - 헤더 정보 기준으로 트래픽을 분류해 클래스별 큐에 나누어 저장함
  - 클래스 큐들을 조사해 각 클래스별로 패킷을 순서대로 전송함
- **WFQ(Weighted Fair Queuing)**
  - 라운드 로빈을 일반화해 각 클래스별로 패킷을 순서대로 전송하는 방식
  - 라운드 로빈과 달리 클래스마다 서비스 시간(가중치)을 차등 적용 → 트래픽 클래스별 최소 대역폭을 보장함
