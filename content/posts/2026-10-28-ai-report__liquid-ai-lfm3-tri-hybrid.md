> 단일 1.7B 백본에서 텍스트 · 비전 · 오디오 · 옴니 · 결정 모델까지 한 번에 파생시켜 엣지 환경에서 도구 호출과 실시간 추론을 처리한다 !

# 개요
- 무엇 : Liquid AI가 2026.10.27 LFM3 제품군 공개
- 한 줄 정의 : LFM3는 합성곱과 어텐션을 결합한 트라이 하이브리드 백본 기반으로 엣지 환경에 맞춘 멀티모달 및 결정 모델군이다.
- 원문 : [Build specialized multimodal models with LFM3](https://huggingface.co/blog/LiquidAI/lfm3)

# 그래서 도대체 뭔데 ?
- 1.73B 크기의 단일 공통 언어 백본(LFM3-1.7B-Base)에서 출발해 텍스트 · 비전 · 오디오 · 옴니 · 결정(d1) 모델 6종을 2B급 크기로 완성함.
- 4비트 양자화 시 메모리 약 1GB로 스마트폰이나 랩톱 등 엣지 기기에서 로컬 에이전트를 가동할 수 있게 설계됨.
- 256K 컨텍스트 윈도우와 도구 검색을 갖춰 온디바이스에서 긴 호흡의 도구 호출 루프를 지원함.
- 💡 트라이 하이브리드(Tri-hybrid) : 단기 합성곱, 슬라이딩 윈도우 어텐션, 글로벌 어텐션의 3가지 레이어를 섞어 긴 문맥에서도 연산량을 낮추는 구조.
- 💡 결정 모델(Decision Model) : 텍스트를 한 토큰씩 생성하지 않고 단일 순전파(forward pass)로 분류 · 점수 · 범위를 한 번에 산출하는 모델.

# 어떻게 동작하나 ?
1. 트라이 하이브리드 백본 레이어 배치
	- 24개 레이어 중 13개 게이트 단기 합성곱(커널 크기 7), 5개 슬라이딩 윈도우 어텐션(256 토큰 윈도우), 6개 글로벌 어텐션을 혼합 배치함.
	- 글로벌 어텐션에는 최고 주파수의 절반만 회전시키는 부분 RoPE와 헤드별 시그모이드 게이트를 적용해 양자화 안정성을 확보함.
	→ 8K 토큰 컨텍스트에서 LFM2-1.2B 대비 약 25% 빠른 추론 속도를 냄.

2. 2단계 사전학습과 4단계 사후학습
	- 사전학습은 웹 · 합성 데이터(약 15T 토큰)와 코드 · 수학 · 과학(3T 토큰)의 메인 사전학습 및 미드 트레이닝을 합쳐 총 22T 토큰을 진행함.
	- 마지막 3.5T 토큰은 에이전트 궤적과 도구 호출 중심의 미드 트레이닝으로 256K 컨텍스트를 완성함.
	- 지도 미세조정(SFT 1.75T 토큰) 후 혼합 강화학습, 6개 전문 RL 교사를 단일 모델로 증류하는 MOPD, 에이전트 하네스 환경 강화학습을 거침.
	→ 도구 호출과 구조화 출력 능력을 소형 가중치 안에 압축함.

3. 경량 비전 · 오디오 인코더 결합
	- 비전 모델(LFM3-VL-2B)은 164M 크기의 자체 인코더를 결합하고, 연속된 프레임 쌍을 1개 시간 슬라이스로 묶어 시퀀스 길이를 2분의 1로 줄임.
	- 오디오 모델(LFM3-Audio-2B)은 인과적 오디오 인코더와 LiquidCodec을 써서 발화 도중 프리필(TTFT 50ms)과 실시간 대비 87배 속도의 스트리밍 음성 합성을 수행함.
	→ 추가 연산 부담 없이 단일 GPU에서 도메인 데이터로 파인튜닝이 가능해짐.

4. 단일 순전파 기반 결정 엔진 (d1-2B)
	- LFM3-VL-2B 백본 위에서 동작하며, 상태 텍스트와 질문을 받아 토큰 생성 없이 확률과 범위를 뽑아냄.
	- 단일 결정(decision)에 대해 NVIDIA H100 기준 5.7ms, AMD MI325X 기준 3.8ms 지연으로 판단을 끝냄.
	→ 에이전트 파이프라인의 라우팅 · 분류 · 가드레일 병목을 낮춤.

# 기존이랑 뭐가 다른가 ?
- 이전 방식 : 모달리티마다 완전히 다른 백본을 쓰거나 파라미터가 커서 엣지 기기 탑재가 부담스러웠음. 긴 컨텍스트에서 어텐션 연산량이 급증함.
- 이번 방식 : 1.73B 단일 공통 백본을 공유하며, 합성곱과 윈도우 어텐션 비중을 높여 연산량을 줄임. 4비트 기준 약 1GB로 메모리 점유를 억제함.
→ 모델 크기를 줄이면서도 에이전트 및 멀티모달 작업 특화 구조로 파라미터당 능력을 끌어올림.

# 주의할 점 / 한계
- 파라미터가 1.73B로 작기 때문에 자체 지식만으로 답하는 작업보다는 RAG나 검색 도구 결합이 필요함.
- 복잡한 다단계 추론이나 고난도 코딩 작업에는 권장하지 않음.
- LFM3-VL-2B는 코딩이나 다회차 대화 용도로 권장하지 않음.
- d1-2B의 경우 입력 상태가 64K 토큰을 넘어가면 판단 정확도가 떨어질 수 있으며, 자유 수량 예측은 점수 분류에 비해 신뢰도가 낮음.
- 온디바이스 실행 엔진 지원 상황 : llama.cpp의 LFM3-VL 지원은 [PR 31252](https://github.com/ggml-org/llama.cpp/pull/31252) 검토 중으로 아직 비디오 입력은 지원하지 않음. SGLang 지원도 [PR 46858](https://github.com/sgl-project/sglang/pull/46858) 검토 중임.

# 정리
- 1.73B 언어 백본 하나로 텍스트부터 옴니 · 결정 모델까지 엣지 환경에 맞춰 정돈했음.
- 대규모 서버 인프라 없이 스마트폰 · 랩톱이나 단일 GPU 환경에서 로컬 에이전트를 구축하려는 개발자에게 유용함.
