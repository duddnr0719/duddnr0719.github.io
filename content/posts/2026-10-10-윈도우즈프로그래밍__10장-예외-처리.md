> 실행 중 오류 = 예외. 조건문으로 미리 막는 기본 처리와 try/catch/finally 고급 처리가 있고, catch를 여러 개 두어 종류별로 나누며, throw로 직접 던지고 Exception을 상속해 내 예외를 만든다.
### 예외란
- **컴파일(문법) 오류**: 빌드조차 안 됨 (`string[] a = new string();`, `Random r = Random();`)
- **예외(런타임 오류)**: 실행 중에 발생, 처리하지 않으면 프로그램이 **강제 종료** (`int.Parse("two")` → FormatException)
- **예외 처리**: 예외가 나도 프로그램이 죽지 않고 대응하게 하는 것 → 신뢰성
### 기본 예외 처리: 조건문으로 미리 막기
```csharp
string[] array = { "가", "나" };
Console.Write("숫자를 입력하세요: ");
int input = int.Parse(Console.ReadLine());

if (input < array.Length)
    Console.WriteLine("입력한 위치의 값은 '" + array[input] + "'입니다.");
else
    Console.WriteLine("인덱스 범위를 넘었습니다.");   // 52273 입력 시
```
- 조건문이 없으면 `IndexOutOfRangeException: 인덱스가 배열 범위를 벗어났습니다.` (음수 입력도 막으려면 `0 <= input &&` 추가)
### 고급 예외 처리: try / catch / finally
```csharp
try
{
    // 예외가 발생할 수 있는 코드
}
catch (Exception exception)
{
    // 예외가 나면 여기로
}
finally
{
    // 예외가 나든 안 나든 무조건 실행
}
```
- try는 필수, catch와 finally는 **둘 중 하나 이상**. 순서는 try → catch → finally (finally 뒤에 catch 불가)
```csharp
Console.Write("입력: ");
string input = Console.ReadLine();
try
{
    int index = int.Parse(input);
    Console.WriteLine("입력 숫자: " + index);
}
catch (Exception exception)
{
    Console.WriteLine("예외가 발생했습니다.");
    Console.WriteLine(exception.GetType());   // System.FormatException
    return;                                    // 메서드를 끝내도
}
finally
{
    Console.WriteLine("프로그램이 종료되었습니다.");   // finally는 실행됨
}
```
- catch에서 `return`·`break`로 빠져나가도 **finally는 실행** (finally 없이 아래에 쓴 문장은 실행 안 됨)
- finally 안에서는 `return`, `break`, `continue` 같은 이탈 키워드 사용 불가 (CS0157)
- catch 괄호 안에 `var` 불가
### 예외 객체
- catch 괄호의 변수. 예외에 대한 정보를 담음
  - `GetType()`: 예외 종류
  - `Message`: 설명 ("입력 문자열의 형식이 잘못되었습니다." — .NET 8 영문 환경에선 "The input string 'ㅇㅂㅇ' was not in a correct format.")
  - `StackTrace`: 어디서 발생했는지 호출 경로
### 예외 종류별로 나누기
```csharp
Console.Write("입력: ");
try
{
    string input = Console.ReadLine();
    int[] array = { 52, 273, 32, 103 };
    int index = int.Parse(input);
    Console.WriteLine("입력 숫자: " + index);
    Console.WriteLine("배열 요소: " + array[index]);
}
catch (FormatException exception)
{
    Console.WriteLine("FormatException 발생");              // "ㅇㅎㅇ" 입력
}
catch (IndexOutOfRangeException exception)
{
    Console.WriteLine("IndexOutOfRangeException 발생");     // 52273 입력
}
catch (Exception exception)
{
    Console.WriteLine("그 밖의 예외");                       // 나머지 전부
}
```
- 위에서부터 차례로 검사 → **구체적인 예외를 먼저, `Exception`은 맨 마지막** (Exception이 위에 있으면 아래 catch에 도달 못 해 컴파일 오류)
### 예외 던지기 (throw)
- `throw new Exception("메시지");` → 처리 안 하면 프로그램 종료, try 안에서 던지면 catch로
- 속성의 세터에서 잘못된 값을 출력만 하던 걸 예외로 바꾸면 호출한 쪽이 반드시 알게 됨
```csharp
class Box
{
    private int width;
    public int Width
    {
        get { return width; }
        set
        {
            if (value > 0) width = value;
            else throw new Exception("너비는 자연수를 입력해주세요.");
        }
    }
    // Height도 같은 방식
    public Box(int width, int height) { Width = width; Height = height; }
}

Box box = new Box(-10, -20);   // 처리되지 않은 예외: System.Exception: 너비는 자연수를 입력해주세요.
```
  - 실무에선 이런 경우 `ArgumentOutOfRangeException`처럼 의미가 맞는 기존 예외를 던지는 게 보통
- **사용자 정의 예외**: Exception을 상속하고 메시지는 `base(message)`로 부모에 전달
```csharp
class CustomException : Exception
{
    public CustomException(string message) : base(message) { }
}

try
{
    throw new CustomException("사용자 정의 예외");
}
catch (CustomException exception)
{
    Console.WriteLine(exception.Message);   // 사용자 정의 예외
}
```
### 연습문제 풀이
- `arr = new string[3]; arr[5]` → IndexOutOfRangeException
```csharp
try
{
    string[] arr = new string[3];
    Console.WriteLine(arr[5]);
}
catch (IndexOutOfRangeException exception)
{
    Console.WriteLine("인덱스 범위를 벗어났습니다: " + exception.Message);
}
```
- 파일 읽기 + 파일이 없을 때
```csharp
StreamReader reader = null;
try
{
    reader = new StreamReader(@"c:\test\none.txt");
    Console.WriteLine(reader.ReadToEnd());
}
catch (FileNotFoundException exception)
{
    Console.WriteLine("파일이 존재하지 않습니다: " + exception.FileName);
}
catch (Exception exception)
{
    Console.WriteLine("기타 오류: " + exception.Message);
}
finally
{
    reader?.Dispose();   // 열렸다면 닫기 (using을 쓰면 이 부분이 자동)
}
```
- O/X: IndexOutOfRange는 컴파일 오류 아님(X), 예외 처리는 조건문으로도 가능(X), return·break로 이탈해도 finally는 실행됨(X), finally 안에 return 불가(O), var로 모든 예외를 받을 수 없음(X → 모두 받으려면 `Exception`)
### 윈도 폼: 콤보 박스, 리스트 박스, 데이터 그리드 뷰
- 1차원 목록은 ComboBox·ListBox, 2차원 표는 DataGridView. 항목은 디자이너가 아니라 코드로 `DataSource`에 배열·리스트를 넣는 게 일반적
```csharp
var dataSource = new string[] { "고구마", "감자", "토마토" };
comboBox1.DataSource = dataSource;
listBox1.DataSource = dataSource;

comboBox1.SelectedIndexChanged += ComboBox1_SelectedIndexChanged;   // 선택이 바뀔 때

private void ComboBox1_SelectedIndexChanged(object sender, EventArgs e)
{
    label1.Text = comboBox1.SelectedIndex + " : " + comboBox1.SelectedItem;   // "1 : 감자"
}
```
- 객체 리스트를 쓸 땐 `DisplayMember`(화면에 보일 속성), `ValueMember`(`SelectedValue`로 꺼낼 속성)를 **DataSource보다 먼저** 지정
```csharp
class Product { public string Name { get; set; } public int Price { get; set; } }

var products = new List<Product>
{
    new Product() { Name = "고구마", Price = 500 },
    new Product() { Name = "감자", Price = 600 },
    new Product() { Name = "사과", Price = 700 },
};
listBox1.DisplayMember = "Name";
listBox1.ValueMember = "Price";
listBox1.DataSource = products;
listBox1.SelectedIndexChanged += (s, e) =>
{
    // SelectedItem은 object라 Product로 변환해야 Name에 접근
    label1.Text = listBox1.SelectedIndex + " : " + listBox1.SelectedValue
                + " : " + ((Product)listBox1.SelectedItem).Name;   // "2 : 700 : 사과"
};
```
  - 교재의 리스트 박스 이벤트 코드는 본문이 `comboBox1`을 그대로 참조하고 있어(복사 실수) 위처럼 `listBox1`로 고쳐야 리스트 박스 선택이 반영됨
- DataGridView: `dataGridView1.DataSource = products;` 한 줄이면 속성 이름(Name, Price)이 열 머리글이 된 표가 나옴
