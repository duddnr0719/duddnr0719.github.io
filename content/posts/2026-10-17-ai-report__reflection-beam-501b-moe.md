> 미국 AI 연구소 Reflection이 501B(활성 23B) 오픈 가중치 MoE 모델 Beam을 Apache 2.0 라이선스로 공개했음 — 하이브리드 어텐션으로 1M 컨텍스트 KV 캐시를 6분의 1로 줄이고 코딩 · 에이전트용 내장 파서와 학습 레시피까지 함께 제공하는 모델 !

# 개요
- 무엇 : 미국 AI 연구소 Reflection이 2026.10.16 첫 오픈 가중치 언어 모델 `Beam`(`Beam-1.0-501B-A23B`)과 전용 Rust 코딩 하네스 `Mirror`를 공개함 (BF16 · FP8 · NVFP4 체크포인트 배포).
- 한 줄 정의 : Beam은 총 501.3B 파라미터 중 토큰당 23.4B만 활성화해 23B급 연산 속도로 1M 토큰 문맥의 코딩 · 에이전트 추론을 수행하는 희소 전문가 혼합(Sparse MoE) 언어 모델이다.
- 원문 : [Welcome Beam: a 501B open model you can own, customize, and scale](https://huggingface.co/blog/reflection-beam)

# 그래서 도대체 뭔데 ?
- 프런티어급 코딩 · 에이전트 모델을 자체 하드웨어 · 인프라 · 클라우드에 직접 띄우고 용도에 맞게 커스터마이즈(SFT · RL)하려는 팀을 겨냥한 오픈 모델임 (Apache 2.0 라이선스로 증류 · 상업적 이용 · 재학습 제한 없음).
- 52개 레이어 중 43개를 직전 512 토큰만 보는 슬라이딩 윈도우로 두고 9개만 전체 문맥을 보게 설계해, 1M 토큰 풀 컨텍스트에서도 단일 시퀀스 KV 캐시를 36.08GiB로 줄임.
- 토크나이저에 응답 템플릿(`parse_response`)을 내장하고 전용 XML 스타일 도구 호출 문법을 사용해, 별도 정규식 없이도 추론 과정(`reasoning`) · 답변 · 도구 호출을 분리하고 도구 스키마에 선언된 타입으로 인자를 자동 변환함.
	- 💡 Sparse MoE (희소 전문가 혼합) : 신경망을 여러 전문가(Expert) 블록으로 쪼개고 토큰마다 일부만 선택해 연산하는 구조.
	- 💡 Scalable-Softmax Query Scaling : 위치 인코딩(RoPE) 없는 글로벌 어텐션에서 문맥이 길어질 때 소프트맥스가 평탄해지는 현상을 막기 위해 가시 토큰 수에 따라 완만하게 증가하는 스케일러를 쿼리에 곱하는 방식.
	- 💡 NVFP4 : NVIDIA Blackwell GPU에서 네이티브로 구동되는 4비트 사후 양자화(PTQ) 포맷 (정확도를 위해 일부 파라미터는 BF16 유지).

# 어떻게 동작하나 ?
1. 하이브리드 어텐션 (슬라이딩 윈도우 43개 + 글로벌 9개)
	- 52개 디코더 레이어(히든 크기 5,120) 중 43개는 직전 512 토큰만 보는 슬라이딩 윈도우(RoPE 적용)를 쓰고, 매 6번째와 마지막을 합친 9개만 전체 문맥을 보는 글로벌 어텐션으로 작동함.
	- 글로벌 레이어는 RoPE 대신 쿼리에 `(1 + (pos + 1) / 2048) ** 0.1` 스케일러를 곱해 긴 문맥에서 소프트맥스 정밀도가 무너지는 것을 막고, 모든 어텐션 블록은 GQA(쿼리 48개 · KV 8개, 헤드 차원 128)와 쿼리 · 키 RMSNorm 및 출력 프로젝션 전 학습된 시그모이드 게이트를 거침.
	→ 43개 레이어의 KV 캐시가 512 토큰에서 성장을 멈춰 메모리 증가율이 토큰당 208KiB에서 36KiB로 줄어듦.
2. 그룹 제한 라우팅 기반 256 전문가 MoE
	- 첫 3개 레이어는 Dense SwiGLU MLP를 쓰고, 나머지 49개 레이어는 각 39M 파라미터(중간 크기 2,560) 전문가 256개로 구성된 MoE 블록으로 대체함 (전체 가중치의 98.4%).
	- 공유 전문가 없이 256개 전문가를 32개씩 8개 그룹으로 나눈 뒤, 상위 2개 점수 합이 높은 4개 그룹 안에서 최종 8개 전문가만 골라 정규화된 가중합에 2.5배 스케일링을 적용함.
	→ 레이어마다 전문가 8개만 활성화해 전체 활성 연산량을 토큰당 23.4B 파라미터로 줄여 23B급 속도로 동작함.
3. 정적 스케일 잔차 스트림 (Residual Stream)과 서빙 최적화
	- 표준 트랜스포머가 서브레이어 출력을 가중치 1로 더해 깊어질수록 값이 커지는 것과 달리, 스텝 `k`마다 기존 스트림에 `sqrt((k-1)/k)`, 새 출력에 `1/sqrt(k)` 가중치(제곱합 1)를 부여하고 라우터 · SwiGLU 곱 · 정규화 · RoPE · 쿼리 스케일링 · 최종 로짓(`±30` tanh 소프트캡) 연산을 FP32로 고정함.
	- 추론 강도(`reasoning_effort`) 5단계와 턴 간 사고 유지(`preserve_thinking`), 소형 드래프터(`DFlash2`)가 최대 15 토큰을 제안하고 본 모델이 한 번의 포워드 패스로 검증하는 투기적 디코딩을 지원함.
	→ 104번의 덧셈 뒤에도 첫 레이어부터 마지막까지 은닉 상태 스케일과 각 레이어 출력 비중이 일정하게 유지되며, 스텝당 여러 토큰을 수락해 생성 속도를 높임.

# 기존이랑 뭐가 다른가 ?
- 이전 방식 : 52개 레이어 전체에 글로벌 어텐션을 쓰면 1M 컨텍스트 단일 시퀀스에만 208GiB KV 캐시가 필요하고, 표준 트랜스포머는 레이어가 깊어질수록 잔차 스트림 스케일이 커지며, 추론과 도구 호출을 나누려면 별도 정규식 파서를 붙여야 했음.
- 이번 방식 : 9개 글로벌 레이어만 전체 캐시를 유지해 1M 토큰 KV 캐시를 36.08GiB로 줄이고, 깊이별 가중치로 잔차 스트림 스케일을 고정했으며, NVFP4 양자화(약 280GB)와 내장 파서 · 사후 학습(TRL SFT · Miles GRPO) 레시피를 함께 공개함.
→ 가중치 공개에 그치지 않고 자체 클러스터에서 긴 문맥 에이전트 서빙과 강화학습 튜닝까지 바로 돌릴 수 있게 맞춘 점이 다름.

# 주의할 점 / 한계
- 메모리 상주 부담과 하드웨어 제약 : 활성 연산은 23.4B지만 256개 전문가 전체가 VRAM에 상주해야 해서 501B 규모의 메모리가 필요함. 약 280GB인 NVFP4 모델도 B200(180GB) 2장(360GB)에는 여유가 적어 긴 문맥 서빙에는 B200 4장(720GB)이나 B300 2 ~ 4장 · RTX Pro 6000 8장이 권장되며, H200 등 Blackwell 이전 세대(Hopper · Ampere) GPU는 NVFP4를 네이티브 지원하지 않아 FP8(H200 8장)이나 BF16(H200 16장)을 써야 함.
- 영어 중심 학습과 낮은 추론 강도 한계 : 주 개발 언어가 영어라 기본 모델은 다국어 추론 유지 평가에서 16개 중 3개만 통과해 별도 LoRA SFT가 필요했음. 또한 5개 과업 Vibe Evals에서 `reasoning_effort="low"` 설정 시 긴 문맥 코드 검색(1,613 토큰)은 코드 동작과 출처 인용 6개를 모두 맞혔으나 파서 포맷과 어긋났고(일부 프롬프트 모호성 영향) 수학 문제(829 토큰)는 정답만 내고 요청된 증명을 생략함 (`high` 설정 시 각각 5,007 토큰 · 2,809 토큰으로 통과).
- 벤치마크 조건 : 성능 수치는 모두 Reflection 팀이 자체 측정한 값(`temp=0.7` · `top_p=0.99`)이며 타사 모델과 동일 조건에서 직접 대조한 표는 포함되어 있지 않음.
- 아직 확인 안 된 것 : 사전학습 총 토큰 수와 학습 클러스터 규모 · DFlash2 투기적 디코딩의 실제 초당 토큰 가속 배율 · 예고된 상세 Technical Report 본문은 원문에 없음.

# 정리
- 501B MoE 구조에 하이브리드 어텐션(슬라이딩 43 + 글로벌 9)과 깊이 정규화 잔차 스트림을 결합해, 1M 토큰 문맥의 KV 캐시를 36.08GiB로 억제한 Apache 2.0 오픈 가중치 모델임.
- NVFP4 · FP8 체크포인트와 vLLM · SGLang · TRL · Miles(GRPO) 레시피가 함께 제공되므로, 멀티 노드 H200이나 Blackwell 클러스터에서 자체 코딩 · 에이전트 모델을 운영하고 강화학습으로 튜닝하려는 팀에게 적합함.
