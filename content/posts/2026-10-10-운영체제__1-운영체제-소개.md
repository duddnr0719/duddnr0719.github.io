> OS = 사용자와 하드웨어 사이의 중재자. 자원을 공정·효율적으로 나눠주고(자원 할당기), 프로그램이 잘못 쓰지 못하게 막는다(제어 프로그램). 그 핵심 수단이 인터럽트, 이중 모드, 타이머.
### 운영체제란
- 사용자와 하드웨어 사이에서 중재자 역할을 하는 프로그램 (Windows, macOS, Linux, iOS, Android)
- 목표: 하드웨어를 관리해서 사용자에게 서비스. 사용자 프로그램을 실행하고 문제 해결을 쉽게
- 두 관점
  - **자원 할당기**: 모든 자원을 관리하고, 충돌하는 요청 사이에서 효율적이고 공정하게 배분 (데스크톱은 성능 최대, 모바일은 성능을 조금 양보해도 배터리 우선처럼 목표가 다를 수 있음)
  - **제어 프로그램**: 프로그램 실행을 제어해 오류와 부적절한 사용을 방지
- 보편적 정의는 없음. 흔히 "항상 실행되는 프로그램" = **커널**
  - 시스템 프로그램: OS와 함께 제공 / 응용 프로그램: OS와 무관한 나머지
  - 모바일 OS = 커널 + **미들웨어**(DB, 멀티미디어, 그래픽 등 앱 개발자용 서비스)
- 구조: 사용자 → 응용 프로그램·유틸리티 → 사용자 인터페이스 → 커널 → 하드웨어. 응용 프로그램은 시스템 호출로 커널 모드에 들어감
### 컴퓨터 시작
- 전원을 켜면 **부트스트랩 프로그램** 실행. ROM/EPROM에 저장된 **펌웨어** (BIOS, UEFI를 떠올리면 됨)
- 연결된 장치가 다 있는지·고장 없는지 점검 → 시스템 초기화 → OS 커널을 로드해 실행 시작 (장치 권한을 OS에 넘김)
### 컴퓨터 시스템 구성
- CPU와 장치 컨트롤러들(디스크, USB, 그래픽)이 **공통 버스**로 공유 메모리에 접근
- CPU와 장치가 동시에 실행되며 메모리 사이클을 두고 경쟁. 장치 컨트롤러는 장치 유형마다 하나씩
- **장치 드라이버**: 컨트롤러의 I/O를 관리하고, 컨트롤러와 커널 사이에 균일한 인터페이스 제공
### 저장장치
- 메인 메모리(RAM): CPU가 **직접** 접근하는 유일한 대용량 매체, 랜덤 액세스, **휘발성**
- 보조 저장장치: 대용량 비휘발성
  - HDD: 자성 물질을 입힌 원판, 트랙·섹터 구조
  - SSD: HDD보다 빠름, 비휘발성
- 계층 구조: 위로 갈수록 빠르고 비싸고 휘발성 (레지스터 → 캐시 → 메인 메모리 → SSD → HDD)
- **캐싱**: 더 빠른 저장장치로 정보를 복사. 메인 메모리도 보조 저장장치의 캐시로 볼 수 있음
- 데이터 A의 이동: 디스크 → 메인 메모리 → 캐시 → 레지스터
  - 멀티태스킹: 계층 어디에 있든 **가장 최신 값**을 써야 함
  - 멀티프로세서: 하드웨어가 **캐시 일관성(cache coherency)** 을 보장해야 함
  - 분산 환경: 같은 데이터의 복사본이 여러 곳 → 더 복잡
### DMA (Direct Memory Access)
- 메모리 속도에 가까운 고속 I/O 장치용
- 장치 컨트롤러가 CPU 개입 없이 버퍼에서 메인 메모리로 **블록 단위**로 직접 전송
- 바이트마다가 아니라 **블록마다 인터럽트 1번** → 대량 전송 시 인터럽트 오버헤드 감소
### 시스템 아키텍처
- 단일 처리기: 대부분의 시스템. 키보드·USB 장치도 각자 작은 프로세서와 큐를 가진 컴퓨터라 볼 수 있음
- 멀티프로세서(병렬 시스템): 처리량↑, 규모의 경제, 신뢰성↑
  - 비대칭: 프로세서마다 특정 작업 담당
  - 대칭(SMP): 모든 프로세서가 모든 작업 수행
  - 멀티코어: 한 칩에 여러 코어 (멀티프로세서가 머리 2개라면 멀티코어는 좌뇌·우뇌)
- 클러스터: 여러 **시스템**이 함께 동작, 보통 SAN으로 저장장치 공유 → **고가용성**
  - 비대칭 클러스터링: 한 대는 동작, 한 대는 대기(핫 스탠바이)
  - 대칭 클러스터링: 둘 다 실행하며 서로 감시
  - 병렬화: 큰 계산을 여러 대가 나눠 처리 (Hadoop, 다중 GPU 학습). 같은 데이터를 동시에 건드리지 않도록 **분산 잠금 관리자(DLM)** 가 조정
### 멀티프로그래밍과 시분할
- 멀티프로그래밍: 사용자 하나로는 CPU와 I/O를 항상 바쁘게 못 함 → 여러 작업을 메모리에 올려두고, 하나가 I/O로 대기하면 다른 작업으로 전환 → CPU가 쉬지 않음
- 시분할(= 멀티태스킹): CPU가 작업을 아주 자주 전환해 사용자와 대화식 컴퓨팅. 응답 시간 **< 1초** 목표
- 가상 메모리: 메모리에 전부 올라오지 않은 프로세스도 실행 가능
### 인터럽트
- OS는 **인터럽트 구동** 방식 (폴링 대신 장치가 알려줌)
- 하드웨어 인터럽트: 장치가 발생
- 소프트웨어 인터럽트 = 예외(exception) / 트랩(trap)
  - 0으로 나누기 같은 오류
  - OS 서비스 요청(시스템 호출) = 사용자 모드에서 커널 모드로 바꿔달라는 '요청'
  - 무한 루프, 다른 프로세스나 OS를 건드리는 문제
  - 개념은 try ~ catch와 비슷하지만 CPU와 커널이 처리함
### 이중 모드와 타이머
- **사용자 모드 / 커널 모드**를 하드웨어가 제공하는 **모드 비트**로 구분 (커널 0, 사용자 1)
- **특권 명령어**는 커널 모드에서만 실행 가능
- 시스템 호출 → 커널 모드로 전환 → 처리 후 복귀하면서 사용자 모드로
- 요즘 CPU는 다중 모드도 지원 (예: 게스트 VM을 위한 VMM 모드)
- **타이머**: 무한 루프나 자원 독점 방지
  - OS가 카운터를 설정(특권 명령어) → 물리 시계에 따라 감소 → 0이 되면 인터럽트
  - 시간을 넘긴 프로그램에게서 제어권을 되찾음. 프로세스를 스케줄링하기 전에 설정
- 프로그램 vs 프로세스: 프로그램은 실행 전 파일(설치된 chrome.exe), 프로세스는 실행 중인 상태(크롬 창 2개 = 프로세스 2개)
### 메모리·저장장치 관리
- 프로그램을 실행하려면 명령어와 데이터(의 일부라도)가 메모리에 있어야 함
- 메모리 관리: 어느 부분을 누가 쓰는지 추적, 무엇을 언제 올리고 내릴지 결정, 공간 할당·해제 → CPU 활용률과 응답성 최적화
- 저장장치 관리: 물리적 특성을 **파일**이라는 논리 단위로 추상화해 균일한 뷰 제공
### 보호와 보안
- 보호(protection): OS 자원에 대한 프로세스·사용자의 접근을 제어하는 메커니즘
- 보안(security): 내부·외부 공격 방어 (서비스 거부, 웜, 바이러스, 신원·서비스 도용)
- 사용자 ID(보안 ID): 사용자당 하나, 그 사용자의 파일·프로세스와 연결되어 접근 제어
- 그룹 ID: 사용자 집합 단위로 권한 관리
- 권한 상승(privilege escalation): 더 높은 권한의 유효 ID로 잠시 바꿔 실행 (예: sudo, setuid)
