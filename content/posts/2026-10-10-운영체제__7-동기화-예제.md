> 동기화 도구를 종합적으로 써보는 3대 고전 문제. 유한 버퍼는 세마포 3개(mutex, empty, full), 독자-기록자는 첫 독자·마지막 독자만 rw_mutex를 건드리는 구조, 식사하는 철학자는 교착 상태를 피하는 전략과 모니터 해법.
### 유한 버퍼 문제
- n개 버퍼, 각 버퍼에 항목 하나. 생산자는 찬 버퍼를, 소비자는 빈 버퍼를 만듦
- 세마포
  - `mutex = 1`: 버퍼 접근 상호 배제
  - `empty = n`: 빈 칸 수 (n에서 감소)
  - `full = 0`: 찬 칸 수 (0에서 증가)
```c
/* 생산자 */
do {
    /* 항목 생산 */
    wait(empty);     /* 빈 칸 기다림 */
    wait(mutex);
    /* 버퍼에 추가 */
    signal(mutex);
    signal(full);    /* 소비자에게 알림 */
} while (true);

/* 소비자: 대칭 구조 */
do {
    wait(full);      /* 찬 칸 기다림 */
    wait(mutex);
    /* 버퍼에서 꺼냄 */
    signal(mutex);
    signal(empty);   /* 빈 칸 알림 */
    /* 항목 소비 */
} while (true);
```
- **`wait(empty)` → `wait(mutex)` 순서가 중요**: 거꾸로 하면 버퍼가 가득 찼을 때 생산자가 mutex를 쥔 채 empty를 기다리고, 소비자는 mutex를 못 얻어 꺼내지 못함 → 교착
- 실제 동작 확인 (POSIX 세마포 + pthread mutex)
```c
#include <pthread.h>
#include <semaphore.h>
#include <stdio.h>
#define N 5
#define ITEMS 20
int buffer[N], in = 0, out = 0;
sem_t empty, full;
pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;

void *producer(void *a) {
    for (int i = 1; i <= ITEMS; i++) {
        sem_wait(&empty); pthread_mutex_lock(&mutex);
        buffer[in] = i; in = (in + 1) % N;
        pthread_mutex_unlock(&mutex); sem_post(&full);
    }
    return NULL;
}
void *consumer(void *a) {
    long sum = 0;
    for (int i = 0; i < ITEMS; i++) {
        sem_wait(&full); pthread_mutex_lock(&mutex);
        int item = buffer[out]; out = (out + 1) % N;
        pthread_mutex_unlock(&mutex); sem_post(&empty);
        sum += item;
    }
    printf("consumed sum = %ld (expected %d)\n", sum, ITEMS * (ITEMS + 1) / 2);
    return NULL;
}
int main() {
    pthread_t p, c;
    sem_init(&empty, 0, N); sem_init(&full, 0, 0);
    pthread_create(&p, 0, producer, 0); pthread_create(&c, 0, consumer, 0);
    pthread_join(p, 0); pthread_join(c, 0);
}
```
- `gcc bb.c -o bb -pthread && ./bb` → `consumed sum = 210 (expected 210)`
### 독자-기록자 문제
- 독자(reader): 읽기만 / 기록자(writer): 읽고 씀
- 제약: 독자 여럿이 동시에 읽는 건 OK, 기록자는 한 번에 하나만 **독점**
- 변수: `semaphore rw_mutex = 1, mutex = 1; int read_count = 0;`
  - `rw_mutex`: 기록자와 (첫 번째) 독자가 공유하는 잠금
  - `mutex`: read_count 보호
```c
/* 기록자 */
do {
    wait(rw_mutex);
    /* 쓰기 */
    signal(rw_mutex);
} while (true);

/* 독자 */
do {
    wait(mutex);
    read_count++;
    if (read_count == 1)      /* 첫 독자가 기록자를 막음 */
        wait(rw_mutex);
    signal(mutex);

    /* 읽기 */

    wait(mutex);
    read_count--;
    if (read_count == 0)      /* 마지막 독자가 기록자를 풀어줌 */
        signal(rw_mutex);
    signal(mutex);
} while (true);
```
- 기록자가 쓰는 중이면: 독자 1명은 rw_mutex에서, 나머지 독자들은 mutex에서 대기
- 기록자가 `signal(rw_mutex)`를 하면 대기 큐엔 독자와 기록자가 섞여 있음 → 누굴 깨울지는 스케줄러가 결정
- 변형
  - 제1(독자 우선): 기록자가 기다려도 새 독자는 들어감 → 독자가 끊이지 않으면 기록자 기아
  - 제2(기록자 우선): 기록자가 준비되면 새 독자를 막고 최대한 빨리 씀 → 독자 기아
  - 둘 다 기아 가능
- **Reader-Writer Lock**: 세마포로 직접 짜는 대신 API 사용 (예: `pthread_rwlock_rdlock / wrlock / unlock`)
  - read 모드: 여럿 동시 / write 모드: 하나만
  - 읽기가 쓰기보다 훨씬 많은 상황에서 동시성↑
### 식사하는 철학자 문제
- 원탁에 철학자 5명, 젓가락 5개(양옆에 하나씩). 생각하다가 배고프면 양쪽 젓가락 2개를 다 들어야 먹음
- 잠금 순서, 교착 상태, 기아를 한 번에 보여주는 문제
- 세마포 해법: `semaphore chopstick[5]`(모두 1)
```c
/* 철학자 i */
do {
    wait(chopstick[i]);             /* 왼쪽 */
    wait(chopstick[(i + 1) % 5]);   /* 오른쪽 */
    /* 식사 */
    signal(chopstick[i]);
    signal(chopstick[(i + 1) % 5]);
    /* 생각 */
} while (true);
```
- 상호 배제는 되지만 **5명이 동시에 왼쪽을 들면 모두 오른쪽을 기다리며 교착**
- 교착 회피 아이디어
  1. 인원 제한: 최대 4명만 앉게 → 적어도 한 명은 양쪽을 들 수 있음
  1. 동시 획득: 양쪽이 모두 비어 있을 때만 집기 (임계구역 안에서 확인)
  1. 비대칭: 홀수 번호는 왼쪽 먼저, 짝수 번호는 오른쪽 먼저 → 순환 대기 고리가 생기지 않음
- 교착이 없다고 기아가 없는 건 아님 (양옆이 번갈아 계속 먹으면 가운데는 영원히 못 먹음)
### 모니터 해법
- 상태 `THINKING`, `HUNGRY`, `EATING` + 철학자마다 조건 변수 `self[i]`
- `test(i)`: 내가 HUNGRY이고 양옆이 EATING이 아니면 → EATING으로 바꾸고 `self[i].signal()`. 양쪽을 **한꺼번에** 확보하는 셈
```c
monitor DiningPhilosophers {
    enum { THINKING, HUNGRY, EATING } state[5];
    condition self[5];

    void pickup(int i) {
        state[i] = HUNGRY;
        test(i);
        if (state[i] != EATING)
            self[i].wait();          /* 양쪽 다 빌 때까지 대기 */
    }
    void putdown(int i) {
        state[i] = THINKING;
        test((i + 4) % 5);           /* 왼쪽 이웃이 이제 먹을 수 있나 */
        test((i + 1) % 5);           /* 오른쪽 이웃 */
    }
    void test(int i) {
        if (state[(i + 4) % 5] != EATING &&
            state[i] == HUNGRY &&
            state[(i + 1) % 5] != EATING) {
            state[i] = EATING;
            self[i].signal();
        }
    }
    initialization_code() {
        for (int i = 0; i < 5; i++) state[i] = THINKING;
    }
}

/* 철학자 i */
DiningPhilosophers.pickup(i);
/* 식사 */
DiningPhilosophers.putdown(i);
```
- 상호 배제 자동, 양쪽 다 쓸 수 있을 때만 식사 → **교착 없음**. 단, 기아는 여전히 가능
- 자원이 하나뿐이면 앞 강의의 ResourceAllocator 모니터(`acquire(time)` / `release()`)로 충분
### 대안적 접근
- 멀티코어·다중 스레드 환경에선 세마포·mutex만으로 안전하게 짜기 어려움 → thread-safe를 더 쉽게 만드는 방법들
- **트랜잭셔널 메모리**: 읽기·쓰기 묶음을 하나의 원자적 트랜잭션으로 실행
  - 잠금 없이 일단 실행하는 **낙관적** 방식, 충돌하면 롤백 후 재시도
  - 소프트웨어(STM) 또는 하드웨어(HTM)로 구현
- **OpenMP**: `#pragma omp parallel`로 병렬 영역, `#pragma omp critical`로 임계구역 보호 (C, C++, Fortran)
- **함수형 언어** (Erlang, Scala, Haskell, Python·Java 일부 기능)
  - 불변 상태: 값이 안 바뀌니 경쟁 상태가 원천적으로 없음
  - 부수 효과 없음: 공유 상태를 수정하지 않으니 잠금 불필요
