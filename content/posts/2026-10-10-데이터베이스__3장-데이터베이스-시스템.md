> DB 시스템 = 사용자 + 데이터 언어 + DBMS + DB. 핵심은 외부/개념/내부 3단계 구조와 그 사이 사상으로 얻는 데이터 독립성.
### 데이터베이스 시스템
- DBS: DB에 데이터를 저장·관리해 조직에 필요한 정보를 만들어 주는 시스템
- 구성: 사용자(관리자, 일반 사용자, 개발자) → 데이터 언어(DDL, DML, DCL) → DBMS → DB
### 스키마와 인스턴스
- 스키마: DB에 저장되는 데이터 구조와 데이터 간 연결 구조(제약조건)를 정의한 것. 한마디로 **DB 설계도**. (그리스어 σχῆμα = 형태, 구조)
- 인스턴스: 스키마에 따라 실제로 저장된 값
- 예: 고객(고객아이디 CHAR(20), 고객이름 CHAR(20), 나이 INT, 등급 CHAR(10) …)이 스키마, `(apple, 김현준, 20, gold, 학생, 1000)` 같은 행들이 인스턴스
- 학사관리 예: 학생(student_id PK …), 과목(course_id PK …), 수강(enrollment_id PK, student_id FK, course_id FK, grade …)
### 3단계 구조 (ANSI/SPARC)
- ANSI 산하 표준화 위원회 SPARC가 제안. 목적: 이해·이용을 쉽게 + **데이터 독립성 확보**
| 단계 | 관점 | 스키마 | 개수 |
|---|---|---|---|
| 외부 | 개별 사용자 | 외부 스키마(서브 스키마) | 여러 개 |
| 개념 | 조직 전체, 관리자 | 개념 스키마 | 1개 |
| 내부 | 물리 저장 장치 | 내부 스키마 | 1개 |
- 내부 → 외부로 갈수록 추상화 수준이 높아짐 (추상화 = 불필요한 세부를 숨기고 공통 특성만 드러냄)
- 아파트 비유: 집주인은 자기 집 구조만(외부), 관리인은 단지 전체 구조와 보안(개념), 건설사는 골조·배선·배관(내부)
- 도서관 비유: 검색 화면(외부) / 전체 도서 분류 체계(개념) / 실제 서가 배치 방법(내부)
### 각 단계 자세히
- 외부 스키마: 사용자마다 필요한 부분만 정의한 논리 구조 = 뷰(View)
  - 대학 예: 학생은 학번·과목명·성적, 교수는 과목명·학생명·성적, 행정직원은 학번·이름·등록금 납부 여부
  - 영화 예매 예: 관리자는 상영관·영화·시간표·회원 관리, 회원은 검색·예매·결제·발권
- 개념 스키마: DB 전체의 논리 구조. 어떤 데이터가 저장되고, 관계와 제약조건은 무엇인지 + 보안 정책·접근 권한까지. **이걸 정의하는 게 DB 설계의 핵심.**
  - 예: Oracle scott 계정의 EMP, DEPT, SALGRADE, BONUS (EMP.deptno → DEPT.deptno)
- 내부 스키마: 실제 저장 방법. 레코드 구조, 필드 크기, 접근 경로(인덱스) 등. 대부분 DDL로 구현.
  - 대학 예: 디스크 블록 단위 저장, 학번 인덱스, 등록금 데이터 압축 별도 파일
### 3단계 예시
- 외부: 고객 분석팀(성별, 나이, 직업), 배송팀(고객번호, 이름, 주소, 연락처)
- 개념: 고객(번호, 이름, 성별, 나이, 직업, 주소, 연락처)
- 내부: 레코드 길이 70바이트
| 필드 | 크기 | OFFSET | 인덱스 |
|---|---|---|---|
| 번호 | 4 | 0 | O |
| 이름 | 10 | 4 | |
| 성별 | 2 | 14 | |
| 나이 | 4 | 16 | |
| 직업 | 10 | 20 | |
| 주소 | 20 | 30 | |
| 연락처 | 20 | 50 | O |
### 사상과 데이터 독립성
- 외부/개념 사상 = 응용 인터페이스, 개념/내부 사상 = 저장 인터페이스. 미리 정의된 사상으로 원하는 데이터에 접근.
- 3단계 + 사상을 두는 궁극적 목적 = **데이터 독립성**: 하위 스키마가 바뀌어도 상위 스키마는 영향 없음 (일관된 뷰)
  - 논리적 독립성: 개념 스키마가 바뀌어도 외부 스키마(응용 프로그램)는 그대로. 외부/개념 사상만 고치면 됨.
  - 물리적 독립성: 내부 스키마가 바뀌어도 개념 스키마는 그대로. 응용 영향 없이 물리 구조 변경 가능.
### 데이터 사전 / 디렉토리
- 데이터 사전(= 시스템 카탈로그): 메타데이터(스키마, 사상 정보, 제약조건)를 담은 시스템 DB. DBMS가 스스로 생성·유지. 일반 사용자는 검색만 가능.
- 데이터 디렉토리: 데이터 사전의 데이터에 접근하기 위한 위치 정보 저장. 일반 사용자 접근 불가, 관리자 권한. (Oracle: 데이터 파일, 제어 파일, 리두 로그 정보)
- 사용자 DB: 사용자가 실제로 쓰는 일반 데이터
### DB 사용자
- **DBA**: DB 시스템 운영·관리, 주로 DDL·DCL 사용
  - 업무: 구성 요소 선정, 스키마 정의, 저장 구조·접근 방법 결정, 무결성 제약조건, 사용자 관리, 보안·권한 정책, 백업·회복, 시스템 DB 관리, 성능 감시·분석, 재구성
  - 데이터의 보안(누가 보나), 무결성(정확한가), 가용성(필요할 때 쓸 수 있나)을 책임. 은행이라면 권한 관리, 매일 백업, 장애 복구, 성능 개선 등.
- **최종 사용자**: 질의·변경·보고서 작성. DBMS 지식이 없어도 됨.
| 유형 | 예 | 이용 모습 |
|---|---|---|
| 캐주얼 | 회사 임원 | 필요할 때마다 매번 다른 정보 조회 |
| 초보 | 은행 창구 직원 | 정해진 프로그램으로 반복 업무 |
| 전문 | 데이터 분석가 | SQL로 복잡한 질의·분석 |
| 독자적 | 개인 사업자 | 엑셀·Access로 자기 DB 관리 |
  - 시험 포인트: 캐주얼 = 그때그때 다양한 조회, 초보 = 정해진 업무 반복
- **응용 프로그래머**: 호스트 언어 안에 DML을 넣어 응용 프로그램을 작성하는 개발자
  - 흐름: 사용자 → 응용 프로그램 → DBMS → DB. 덕분에 일반 사용자는 버튼 클릭만으로 DB 사용 (예: 인터넷뱅킹, 창구 조회 화면)
```csharp
OleDbCommand cmd = new OleDbCommand();
cmd.CommandText = "select table_name from user_tables"; // 테이블 목록
cmd.CommandType = CommandType.Text;
cmd.Connection = conn;
OleDbDataReader read = cmd.ExecuteReader();
while (read.Read())
    cmbTableList.Items.Add(read.GetValue(0));
read.Close();
```
### 데이터 언어
- 사용자 ↔ DBMS 통신 수단
  - DDL: 스키마 정의·수정·삭제
  - DML: 삽입·삭제·수정·검색
  - DCL: 내부 규칙·기법 정의 → 무결성, 보안(권한), 회복, 동시성 제어
- 절차적 vs 비절차적 DML
| 구분 | 절차적 | 비절차적(선언적) |
|---|---|---|
| 기술 | What + How (처리 절차) | What (결과만) |
| 이론 | 관계대수 | 관계해석 |
| 예 | PL/SQL, IMS DL/I, CODASYL DML | SQL |
| 실행 순서 | 사용자가 지정 | DBMS가 실행 계획 결정 |
  - 비유: "두부를 어디서 어떻게 사 와라"(절차적) vs "두부 사 와라"(비절차적)
```sql
-- SQL: 결과만 기술
SELECT 이름, 학년 FROM 학생 WHERE 학과 = '컴퓨터공학과';
```
```sql
-- PL/SQL: SQL에 변수·조건·반복 등 절차적 기능을 더한 확장 언어 (DML 자체는 아님)
DECLARE
  v_ename EMP.ENAME%TYPE;
  v_sal   EMP.SAL%TYPE;
BEGIN
  SELECT ENAME, SAL INTO v_ename, v_sal FROM EMP WHERE EMPNO = &no;
  DBMS_OUTPUT.PUT_LINE('사원 이름: ' || v_ename);
  DBMS_OUTPUT.PUT_LINE('급여: ' || v_sal);
END;
```
### CODASYL DML (망 DB, 1970~80년대)
- 레코드 사이를 직접 따라가며 탐색하는 절차적 언어
```
FIND STUDENT RECORD USING STUDENT-ID = 1001.
FIND FIRST COURSE WITHIN ENROLLMENT.
DO WHILE DB-STATUS = OK
  DISPLAY COURSE-NAME.
  FIND NEXT COURSE WITHIN ENROLLMENT.
END-DO.
```
- 추가 `STORE STUDENT ...`, 연결 `CONNECT STUDENT TO COURSE VIA ENROLLMENT` (레코드 간 Set을 직접 생성)
| 작업 | CODASYL | SQL |
|---|---|---|
| 검색 | FIND STUDENT … | SELECT * FROM STUDENT … |
| 다음 레코드 | FIND NEXT | DBMS가 자동 처리 |
| 연결 | CONNECT … VIA | INSERT / 외래키 |
| 방식 | 하나씩 따라가며 탐색 | 결과만 기술 |
### DBMS 구성
- 질의 처리기: 사용자 요구를 해석·처리
  - DDL 컴파일러, DML 프리 컴파일러(응용 프로그램 속 DML 추출), DML 컴파일러, 런타임 DB 처리기, 트랜잭션 관리자
- 저장 데이터 관리자: 디스크의 사용자 DB와 데이터 사전에 실제로 접근. OS 파일 관리 시스템의 도움을 받음.
- 흐름: DBA → DDL → DDL 컴파일러 / 최종 사용자 → DML → DML 컴파일러 → 런타임 처리기 / 응용 프로그램 → 프리 컴파일러 → DML 컴파일러 → … → 저장 데이터 관리자 → 데이터 사전·DB
