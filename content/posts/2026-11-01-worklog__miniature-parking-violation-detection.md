> 미니어처 주차장 시연 환경에서 저해상도 픽셀 한계와 원근 가림으로 발생하던 주차선 물기 오탐을 앞쪽 틈(front gap) 측정 및 가림 예외 처리로 해결하여 위반 판정을 안정화함.

# 배경 — 왜 하게 됐나 ?
- 미니어처 주차 관제 시스템의 최종 시연을 준비하던 상황.
- 기존 시스템은 통로 주차나 반 칸 이상 크게 벗어난 주차는 감지했으나, 실제 주차장에서 빈번하게 발생하는 주차선 물기(차선 밟음)와 이중주차를 제대로 가려내지 못했음.
- 시연 시나리오의 현실성을 확보하기 위해 주차선 침범과 이중주차를 정확하게 판별하여 알리는 기능이 필요했음.
- 목표 : 25칸 미니어처 주차장에서 정상 주차 차량의 오탐 없이, 주차선을 밟은 차량과 이중주차 차량을 검출하여 피에조 부저 2회 및 OLED 5초 디스플레이로 정확히 경고하는 것.

# 환경
- 엣지 컴퓨팅 디바이스 : 싱글보드 컴퓨터 (Jetson)
- 마이크로컨트롤러 : 아두이노 Uno
- 센서 및 액추에이터 : USB 웹캠, 피에조 부저, OLED 디스플레이 모듈 2대
- 대상 환경 : 사다리형 3개 열(S줄, T줄, U줄)로 배치된 25칸 미니어처 주차판
- 소프트웨어 : Python, OpenCV

# 진행 흐름

## 1. 흰 선 영역 매핑 시도와 라이브 실패
- 처음 계획 : 같은 줄에서 이웃한 두 칸 사이의 틈(흰 가로선)에 선 영역 22개를 정의하고, 차량 검출 박스 하단 40% 바닥면이 선 영역의 15% 이상을 덮으면 주차선 침범으로 판정하기로 함.
- 저장해 둔 정적 화면에서는 20:51 장면의 위반 5건을 모두 잡았고 정상 차 오탐도 0건이었음.
- 하지만 라이브 환경에 올리자 검출 박스가 1 ~ 5px 흔들리고 화면 위치 보정값(2.6px → 0px)이 바뀌면서 판정이 요동침.
  - U02 빨간 차(위반) : 선 덮임 비율이 0.28 → 0.08로 떨어지며 누락.
  - S07 초록 차(위반) : 선 덮임 비율이 0.22 → 0.04로 떨어지며 누락.
  - U08 초록 차(정상) : 선 덮임 비율이 0.07 → 0.27로 치솟으며 위반으로 오탐.
- 흰 선 두께가 6 ~ 12px에 불과한데 검출 박스가 늘 몇 px씩 흔들리기 때문에, 문턱을 어디에 두든 정상 차와 위반 차가 뒤섞이는 현상 확인.
→ 단순 박스 기하만으로는 선 물기를 안정적으로 구분할 수 없다고 판단하여 즉시 롤백함.

## 2. 저해상도 픽셀 한계 실측과 거치대 직립 시도
- 문제의 본질을 파악하기 위해 화면 픽셀 해상도와 기하 구조를 정밀 실측함.
- 실측 결과 미니어처 환경의 픽셀 해상도가 근본적으로 부족했음.
  - 웹캠 최대 해상도는 1280x720으로 제한됨 (1920x1080을 요청해도 1280x720으로 고정).
  - 카메라에서 먼 줄(T줄 등)은 칸 깊이가 15 ~ 28px에 불과하여 1px이 칸 깊이의 4 ~ 6.5%를 차지함.
  - 정상 주차 11대의 바퀴 접지선 위치 비율(0=앞선, 1=뒷선)을 측정하니 -0.07 ~ +0.21로 손으로 놓을 때 생기는 편차만 약 5px에 달함.
  - 선 물기 차량(S07 앞쪽 물기 -0.04 ~ +0.01, U02 뒤쪽 물기 +0.23 ~ +0.31)과 정상 차량의 차이가 불과 1px 수준이었음.
  - 차체 높이로 인해 정상 주차 차도 뒷선을 최대 81%까지 가려 픽셀 색상 판별도 실패함.
- 대안 검토 :
  - 바퀴 접점 키포인트 모델 도입 : 바퀴 약 2000개 라벨링이 필요하여 일정상 기각.
  - 거치대 각도 최대 직립 시도 : 수직에 가깝게 거치대를 세웠으나, 카메라 자체 높이가 낮아 T줄 빈 칸 깊이가 27 ~ 57px에서 31 ~ 49px로 10 ~ 15% 증가에 그침 (안정적 구분에 필요한 2 ~ 3배에 크게 미달). 오히려 판이 오른쪽으로 치우쳐 U줄 오른쪽이 잘리는 물리적 한계 봉착.
→ 카메라 물리 배치는 그대로 유지하고, 차체 가림이 없는 새로운 신호를 찾기로 결정함.

## 3. 차체 측면 시점 분석과 앞쪽 틈(front gap) 방식 채택
- 발상의 전환 : 미니카가 화면에서 옆모습으로 찍히므로, 차의 운전석과 조수석 양옆 차선이 화면상 위아래 사다리 가로선에 대응함을 확인.
- 차체에 가려져 뒤쪽과 좌우 여백은 보이지 않지만, 차 앞쪽(카메라 쪽) 틈은 바닥면과 함께 뚜렷하게 관측 가능했음.
- 차가 칸 깊이를 거의 다 채우기 때문에, 앞쪽 틈 하나로 앞뒤 어느 쪽으로 밀렸는지 전부 파악할 수 있음.
- 12프레임 중앙값 실측치 비교 (앞선 기준 바퀴 접지선 거리, +는 안쪽/뒤로 밀림, -는 앞선 바깥/앞으로 돌출) :
  - 정상 주차 10대 범위 : -2.7 ~ +4px
  - 앞쪽 선 물기 : 주황 T09 -6.8px (정상 대비 4.1px 차이), 초록 U01 -6.9px (정상 대비 6.1px 차이) → 명확히 구분 성공.
  - 뒤쪽 선 물기 : 파랑 T01 +8.5px (정상 대비 6.8px 차이), 빨강 U02 +6 ~ 8px → 명확히 구분 성공.
  - 미세 선 물기 : 노랑 S08 -2.7px, 빨강 U07 +1.1px → 정상 범위와 겹쳐 구분 불가.
  - 옆쪽 선 물기(범퍼 방향, 사다리 좌우 끝) : 원근 왜곡으로 정상 주차도 박스 좌우가 +-10px(T01 10px, T09 10.6px) 돌출되어 구분 불가.
- 검출 박스 흔들림은 12프레임 동안 0 ~ 2px 수준(큰 차 한쪽 끝만 4px)이었으므로, 다중 프레임 중앙값을 쓰면 4 ~ 6px 이상의 변위는 안정적으로 분별 가능함을 입증함.
→ 앞쪽 틈 거리를 측정하여 주차선 침범을 판별하는 휴리스틱을 채택함.

## 4. 임계값 4px 조정 및 부저 · OLED 알림 규칙 구현
- 1/3 선 물기 배치 후 2차 실측 진행 :
  - 파랑 T01 : 정상 +1.7px → 물림 +17.4px로 검출.
  - 주황 T09 : 정상 -2.7px → T08 기준 +15.3px로 검출.
  - 초록 U01 : 정상 -0.8px → 물림 -7.9px로 검출.
  - 노랑 S08 : 정상 +0.5px → 물림 -4.5px. 초기 5px 기준에서는 0.5px 모자라 누락됨.
- 원경(S08 칸 깊이 15px) 감지를 위해 선 물기 판정 임계값을 4px로 하향 조정함.
- 알림 체계 개편 :
  - 기존 계획의 노란색 LED 경고를 폐기하고, 피에조 부저 알림으로 일원화함.
  - 신규 위반 1건당 부저 2회(각 0.2초) 울림 지정 (다중 위반 동시 등록 시 한 번에 최대 6회 울림).
  - 30초 이내 2회 연속 판정 시에만 부저 울림을 확정하여 일시적 튐을 방지하고, 동일 차량에는 90초 동안 중복 울림 방지.
- 이중주차 판정 규칙 추가 : 차량 바닥면이 칸 앞 선보다 주차칸 깊이의 50% 이상 밀려나면 이중주차(부저 0.3초)로 판정.
- OLED 문구 표시 : 신규 위반 발생 시 OLED 화면 둘째 줄에 5초 동안 위반 문구 유지.
- 위반 재등록 깜빡임 해결 : 두 칸에 걸친 차량의 점유율이 0.31로 점유 판정 기준인 0.3 경계에서 진동하는 문제 확인. 칸 상태가 바뀌어도 위반을 즉시 지우지 않고 15초 동안 보류하는 유예 시간(grace period)을 도입함.
  - 라이브 3분간 T09 점유가 6회 변동하는 동안 위반 해제 0건, 재등록 0건 유지 확인.
→ 기본 판정 체계를 완성했으나, 다음 날 실차 배치 테스트에서 예상치 못한 오탐들이 나타나 트러블슈팅에 착수함.

# 트러블슈팅

## 1. 흰 선 두께로 인한 정상 주차 4칸 선 물기 오탐
- 현상 : 익일 정상 주차 상태로 배치해 둔 4칸(T07, T08, U06, U07)이 일괄 주차선 물기로 오탐됨.
- 원인 : 먼 줄 주차선의 흰 선 두께가 6 ~ 8px에 달함. 정상 주차 차량도 범퍼가 흰 선 위로 5 ~ 7px 돌출되면서 바퀴 접지선이 칸 앞 선보다 5 ~ 7px 앞에 찍힘. 전날 설정한 4px 임계값이 흰 선 두께(6 ~ 8px)보다 작아서 정상 주차 차량이 걸린 것임.
- 해결 : 앞쪽(카메라 쪽) 돌출 기준만 10px로 완화(`line_gap_front_px: 10`)하고, 뒤쪽 밀림 기준은 4px로 유지하는 비대칭 임계값을 적용함. 이중주차(칸 깊이 50%) 판정은 그대로 유지함.
- 결과 : 배포 후 약 2분간 라이브 위반이 0건으로 정상화됨. 단, 앞으로 살짝 돌출된 선 물기(-6.9px)는 정상(-5 ~ -7px)과 1 ~ 2px 차이에 불과하여 감지를 포기하고, 시연 시에는 차를 뒤로 밀어 연출하도록 제약함.

## 2. 앞뒤 차량 간 원근 가림(Occlusion) 오탐
- 현상 : 정상 주차된 T09 주황색 차량이 주차선 물기로 오탐됨.
- 원인 : 바로 앞 칸인 T08 파란 차가 뒤 칸 T09 주황 차의 하단 바퀴 부위를 8px 가림 (T09 y좌표 306 ~ 338, T08 y좌표 330 시작). 검출 박스 하단 변이 바퀴 접지선이 아닌 앞 차 지붕선에서 잘려 실제보다 4px 위로 상승함. 원경인 T09의 칸 깊이가 17px에 불과하여 4px 오차가 칸 깊이의 23%에 달해 뒷선 침범으로 오판됨.
- 해결 : 바로 앞(카메라 쪽) 차의 박스가 뒤 차 박스 하단을 덮고 가로 폭 30% 이상 겹치면 바퀴 가림(Occlusion) 상태로 판단하여 선 물기 및 이중주차 판정을 건너뛰는 예외 규칙을 도입함.
- 결과 : 라이브 6칸 점유 상태에서 위반 1건이 0건으로 정상화됨. 앞뒤 칸에 차가 연달아 주차된 경우 뒤차의 선 물기는 감지할 수 없으므로, 시연 시에는 선 물기 차량의 바로 앞 칸을 비워두도록 운영 가이드를 정함.

# 결과
- 수치 변화 :
  - 주차선 물기 판정 : 검출 박스 요동으로 인한 오탐 및 누락(U02 0.28 → 0.08 누락, U08 0.07 → 0.27 오탐) → 앞쪽 틈 12프레임 중앙값 측정으로 오탐 0건 달성.
  - 전방 돌출 오탐 : 정상 주차 4칸(T07 · T08 · U06 · U07) 오탐 → 비대칭 임계값(전방 10px, 후방 4px) 적용으로 오탐 0건.
  - 원근 가림 오탐 : 앞 차 가림으로 인한 T09 1건 오탐 → 가림 예외 규칙(폭 30% 겹침) 적용으로 오탐 0건.
  - 점유 진동 : 점유율 0.31 경계 진동으로 인한 위반 재등록 깜빡임 → 15초 유예 시간 적용으로 라이브 3분간 T09 점유 6회 변동 시에도 위반 해제 및 재등록 0건 유지.
- 아직 안 된 것 / 한계 :
  - 앞 칸에 차가 있는 경우 뒤차의 선 물기는 원근 가림 예외 처리로 인해 판정 불가 (시연 시 앞 칸을 비워야 함).
  - 차체 앞뒤 범퍼 방향(사다리 좌우 끝) 선 물기는 원근 왜곡으로 박스가 +-10px 돌출되어 판정 불가.
  - 전방으로 10px 미만 살짝 돌출된 미세 선 물기는 흰 선 두께(6 ~ 8px)로 인해 판정 불가.

# 이번 주 다른 작업
- 위반 종류별 부저 분리 및 안정화 : 통로 · 칸 막음은 LED · OLED만 표시하고 이중주차 · 침범에만 부저 울리도록 분리, 10분간 20회 울리던 부저를 90초 유지 및 30초 내 2회 판정 로직으로 3회 이하로 안정화.
- 주차장 영역 내 특징점 제한 카메라 자동 재보정 개선 : 배경 시차로 인한 위치 추종 실패(lost) 상태를 주차장 영역(lot) 내 특징점(68 ~ 78개)으로 제한하여 4초 만에 복구.
- 이중 OLED 디스플레이 분리 펌웨어 준비 : 입구 안내용과 위반 표시용 분리, 화면 버퍼 공유로 마이크로컨트롤러 RAM 증가를 74바이트로 억제 (남은 RAM 578바이트 확보).

# 배운 점
- 픽셀 수가 절대적으로 부족한 저해상도 환경에서는 정밀한 기하학적 폴리곤 매핑보다 물리적 시점 특성을 활용한 단순한 휴리스틱이 훨씬 견고하게 동작함.
- 알고리즘으로 하드웨어의 물리적 한계(해상도, 시차, 가림)를 억지로 메우려 하기보다, 풀 수 있는 범위와 풀 수 없는 범위를 실측으로 냉정하게 가르고 시연 시나리오의 제약 조건으로 수용하는 판단이 실전에서 더 중요함.
