> TCP = 바이트 단위 순서 번호 + 누적 ACK + 단일 타이머(+빠른 재전송). 여기에 rwnd로 흐름 제어, 3-way handshake와 FIN 교환으로 연결을 관리한다.
### TCP 개요
- RFC 793, 1122, 2018, 5681, 7323
- 점대점(송신자 1 : 수신자 1), 신뢰적·순차 **바이트 스트림**, 전이중(양방향), MSS(최대 세그먼트 크기)
- 누적 ACK, 파이프라인(윈도우 크기는 혼잡·흐름 제어가 결정)
- 연결지향: 데이터 전에 핸드셰이크로 양쪽 상태 초기화
- 흐름 제어: 수신자 한계를 넘겨 보내지 않음
### 세그먼트 구조 (32비트 폭)
- source port / dest port (각 16비트)
- sequence number (32): 세그먼트 첫 바이트의 바이트 스트림 번호 (세그먼트 번호가 아님)
- acknowledgement number (32): 상대에게서 다음에 기대하는 바이트 번호
- head len(4, 32비트 워드 단위), not used, 플래그
- receive window (16): 흐름 제어용 수신 가능 바이트 수(rwnd)
- checksum (16), Urg data pointer (16), options(가변), application data(가변)
- 플래그
| 플래그 | 의미 |
|---|---|
| CWR | ECE를 받은 송신자가 혼잡 윈도를 줄였다고 알림 (ECN 사용 시) |
| ECE | SYN에서 ECN 지원 협상 / 혼잡 표시(CE)를 본 수신자가 송신자에게 에코 |
| URG | Urgent pointer 유효 (요즘은 드묾) |
| ACK | ack 번호 유효. 전송 중 거의 모든 세그먼트가 1 |
| PSH | 버퍼링 없이 바로 앱에 넘겨달라는 힌트 (주로 PSH+ACK) |
| RST | 즉시 종료/거부. 잘못된 포트, 없는 소켓 등 (RST+ACK) |
| SYN | 초기 순서 번호 동기화 → 연결 설정 |
| FIN | 더 보낼 데이터 없음 (반쪽 종료) |
### 순서 번호와 ACK
- 시작 순서 번호는 임의 선택, ACK는 누적. 순서 어긋난 세그먼트 처리는 표준이 정하지 않고 구현에 맡김.
- telnet 예
  - A → B: Seq=42, ACK=79, data='C'
  - B → A: Seq=79, ACK=43, data='C' (에코)
  - A → B: Seq=43, ACK=80
### RTT와 타임아웃
- 타임아웃은 RTT보다 커야 함. 너무 짧으면 불필요한 재전송, 너무 길면 손실 대응이 느림.
- SampleRTT: 송신 ~ ACK 수신까지 측정. 재전송한 세그먼트는 제외. 들쭉날쭉하므로 평균을 씀.
- **EstimatedRTT = (1-α)·EstimatedRTT + α·SampleRTT**, α = 0.125 → EWMA(과거 영향이 지수적으로 감소)
- **DevRTT = (1-β)·DevRTT + β·|SampleRTT − EstimatedRTT|**, β = 0.25
- **TimeoutInterval = EstimatedRTT + 4·DevRTT** (변동이 크면 여유 값도 크게)
### TCP 신뢰적 전송
- 비신뢰 IP 위에서 rdt 제공: 파이프라인, 누적 ACK, **단일 재전송 타이머**
- 재전송 계기: 타임아웃, 중복 ACK
- 송신자 3가지 이벤트
  1. 상위에서 데이터: 순서 번호 붙여 세그먼트 생성·전송, 타이머 꺼져 있으면 시작(만료 주기 = TimeoutInterval)
  1. 타임아웃: 타임아웃 원인 세그먼트 재전송, 타이머 재시작
  1. ACK 수신: 미확인 세그먼트의 ACK면 확인 처리, 남은 미확인이 있으면 타이머 재시작
### 수신자 ACK 생성 규칙 (RFC 5681)
| 이벤트 | 동작 |
|---|---|
| 기다리던 번호의 순차 세그먼트 도착, 이전 데이터는 모두 ACK됨 | 지연 ACK: 다음 세그먼트를 최대 500ms 기다렸다가 없으면 ACK |
| 순차 세그먼트 도착, ACK 대기 중인 세그먼트가 하나 있음 | 즉시 두 개를 묶어 누적 ACK |
| 기대보다 큰 번호 도착(갭 발생) | 즉시 중복 ACK (갭의 시작 번호) |
| 갭을 일부/전부 채우는 세그먼트 도착 | 갭 시작부터 채우면 즉시 ACK |
### 재전송 시나리오
- ACK 손실: Seq=92(8B) → ACK=100 손실 → 타임아웃 → 92 재전송
- 조기 타임아웃: 92, 100 보냈는데 ACK가 늦게 와서 92를 불필요하게 재전송
- 누적 ACK가 커버: ACK=100이 사라져도 뒤이어 ACK=120이 오면 둘 다 확인된 것 → 재전송 없음
### 빠른 재전송
- 타임아웃이 길면 손실 복구가 늦음. 연속 전송 중 하나가 빠지면 중복 ACK가 많이 생긴다는 점을 이용.
- **같은 데이터에 대해 중복 ACK 3개**를 받으면 다음 세그먼트가 손실됐다고 보고 타이머 만료 전에 재전송
- 예: 92, 100(손실), 120, 140, 160 전송 → ACK=100이 3번 중복 → 100번 세그먼트 즉시 재전송
### 흐름 제어
- 송신자가 너무 많이·빨리 보내 수신 버퍼가 넘치는 것을 막음
- 수신자가 헤더의 rwnd에 버퍼 여유 공간을 실어 보냄. RcvBuffer는 소켓 옵션(기본 4096B, 많은 OS가 자동 조정)
- 송신자 조건: **LastByteSent − LastByteAcked ≤ rwnd**
### 연결 관리
- 데이터 전에 서로 연결 의사 확인 + 파라미터(순서 번호, 버퍼 등) 합의
- 소켓: 클라이언트 `socket(AF_INET, SOCK_STREAM)` → `connect()`, 서버 `bind()` → `listen()` → `accept()`
- 2-way handshake의 문제: 가변 지연, 손실로 인한 재전송(req_conn(x)), 순서 뒤바뀜 → 상대 상황을 정확히 모름
  - 반열림 연결(half open): 클라이언트는 끝났는데 서버만 연결 유지
  - 중복 데이터 수락: 지연된 옛 요청 때문에 데이터가 중복 수락
### 3-way handshake
1. 클라이언트 → SYN (SYNbit=1, Seq=x, 데이터 없음). CLOSED → SYN SENT
1. 서버 → SYNACK (SYNbit=1, ACKbit=1, Seq=y, ACKnum=x+1), 서버가 버퍼·변수 할당. LISTEN → SYN RCVD
1. 클라이언트 → ACK (ACKbit=1, ACKnum=y+1), 클라이언트가 버퍼·변수 할당, 데이터 실어도 됨. 양쪽 ESTABLISHED
- 비유: "On belay?" → "Belay on." → "Climbing."
### 연결 종료
1. 클라이언트 `close()` → FIN(Seq=x). ESTAB → FIN_WAIT_1 (송신 불가, 수신 가능)
1. 서버 FIN 수신 → ACK(ACKnum=x+1), CLOSE_WAIT. 클라이언트는 FIN_WAIT_2
1. 서버도 끝나면 FIN(Seq=y), LAST_ACK
1. 클라이언트 → ACK(ACKnum=y+1), TIMED_WAIT(2 × 최대 세그먼트 수명 대기) 후 CLOSED
1. 서버는 마지막 ACK를 받자마자 CLOSED
