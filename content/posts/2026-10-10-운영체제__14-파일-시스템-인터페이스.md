> 파일 = 이름 붙은 연속된 논리 주소 공간. OS는 열기·읽기·쓰기·탐색 같은 연산과 열린 파일 테이블, 잠금을 제공하고, 파일들을 디렉터리(단일 → 2단계 → 트리 → 비순환 그래프)로 조직하고 권한(rwx, ACL)으로 보호한다.
### 파일
- 연속된 **논리 주소 공간**에 데이터나 프로그램을 저장한 것
- 종류: 데이터(숫자, 문자, 이진), 프로그램(소스, 목적, 실행) 등. 구조는 만드는 쪽이 정함
- 속성(메타데이터)
  - 이름: 사람이 읽는 유일한 정보
  - 식별자: 파일 시스템 안의 고유 번호(태그)
  - 유형, 위치(디스크상 위치 포인터), 크기, 보호(rwx)
  - 시간·날짜·사용자 ID: 보안과 사용 기록
  - 이 정보는 디스크의 디렉터리 구조에 저장. 체크섬 같은 확장 속성도 있음
| 유형 | 확장자 | 용도 |
|---|---|---|
| 실행 | exe, com, bin, 없음 | 바로 실행할 기계어 프로그램 |
| 목적 | obj, o | 컴파일됐지만 링크 안 된 기계어 |
| 소스 | c, cc, java, asm | 소스 코드 |
| 배치 | bat, sh | 명령 해석기용 명령 |
| 텍스트 | txt, doc | 문서 |
| 라이브러리 | lib, a, so, dll | 루틴 모음 |
| 인쇄·보기 | ps, pdf, jpg | 인쇄·표시용 |
| 아카이브 | zip, tar | 여러 파일을 묶음(압축) |
| 멀티미디어 | mpeg, mov, mp3, avi | 오디오·비디오 |
### 파일 연산
- 파일 = **추상 데이터 타입**
- 생성, 쓰기(쓰기 포인터 위치에), 읽기(읽기 포인터 위치에), **seek**(파일 안 위치 이동), 삭제, truncate(내용만 지움)
- **open**: 디렉터리에서 파일을 찾아 정보를 메모리로 / **close**: 메모리 정보를 디스크에 반영 (매 연산마다 디렉터리를 뒤지지 않으려고)
- 사용자는 그냥 더블클릭하지만, 이 모든 걸 OS가 처리
### 열린 파일
- **열린 파일 테이블**: 현재 열린 파일 추적 (시스템 전체용 + 프로세스별)
- 파일 포인터: 프로세스별 마지막 읽기·쓰기 위치
- 열기 카운터: 여러 프로세스가 연 경우, 마지막 프로세스가 닫을 때 테이블에서 제거
- 디스크 위치 캐시(빠른 접근), 프로세스별 접근 권한
### 파일 잠금
- 읽기-쓰기 잠금과 비슷
  - **공유 잠금**: 여러 프로세스가 동시에 (예: 여러 사용자가 같은 로그 파일을 읽으며 모니터링)
  - **배타 잠금**: 하나만 (예: DB 트랜잭션이 레코드 갱신 중)
- **강제(mandatory)**: 잠금이 있으면 OS가 접근 자체를 거부 (Windows에서 Word가 연 문서는 다른 프로그램이 못 씀)
- **권고(advisory)**: 잠금 상태를 확인하고 지킬지는 프로세스 몫 (UNIX `flock`/`fcntl` 기본 방식)
### 파일 구조와 접근 방법
- 구조: 없음(바이트 열) / 단순 레코드(줄, 고정·가변 길이) / 복합(서식 있는 문서, 재배치 가능 로드 파일). 뒤의 둘은 제어 문자를 넣어 바이트 열로 흉내 낼 수 있음. 구조를 OS가 정할지 프로그램이 정할지가 설계 문제 (UNIX는 바이트 열만)
- **순차 접근**: `read next`, `write next`, `reset`. 테이프 모델. 쓰기 직후 바로 읽는 경우 주의
- **직접(임의) 접근**: 고정 길이 논리 레코드, `read n`, `write n`, `position to n`. n은 **상대 블록 번호**(0부터), 실제 위치는 OS가 결정 → DB에 적합
- 직접 접근 위에서 순차 접근 흉내: `reset` → `cp = 0`, `read next` → `read cp; cp = cp + 1`
- **인덱스**: 키 → 레코드 위치. 인덱스가 크면 인덱스의 인덱스를 메모리에, 본 인덱스는 디스크에
  - IBM **ISAM**: 작은 마스터 인덱스 → 2차 인덱스 블록 → 데이터. 파일은 키로 정렬
  - 예: 인덱스 파일(성 → 논리 레코드 번호)에서 Smith를 찾아 상대 파일의 (smith, john | 주민번호 | 나이) 레코드로
### 디스크와 디렉터리
- 디스크는 **파티션**(미니디스크, 슬라이스)으로 나눠 여러 개처럼 쓰거나, 여러 디스크를 묶어 하나로(RAID). raw로 쓰거나 파일 시스템으로 포맷
- 파일 시스템이 있는 단위 = **볼륨**. 볼륨의 정보는 장치 디렉터리(볼륨 목차)에 기록
- 대표 범용 파일 시스템
  - FAT/FAT32: 옛 MS-DOS·Windows, 지금도 USB·SD카드
  - NTFS: Windows 기본, 저널링·권한·암호화·압축
  - APFS: macOS·iOS, SSD 최적화·스냅샷·암호화
  - UFS: 전통 UNIX(BSD)
  - ext3/ext4: Linux 표준, 저널링
- 이 밖에 특수 목적 파일 시스템(tmpfs, procfs 등)이 함께 공존
- 디렉터리 = 파일에 대한 정보를 담는 **특별한 파일** (항목: 이름, 위치 정보, 생성·수정 시각, 크기 …, 그리고 `.`, `..`)
- 디렉터리 연산: 검색, 생성, 삭제, 목록, 이름 변경, 파일 시스템 순회(백업 등)
- 조직 목표: **효율성**(빠른 검색), **이름 짓기**(사용자마다 같은 이름 가능, 한 파일에 여러 이름), **그룹화**(Java 프로그램끼리, 게임끼리)
### 디렉터리 구조
| 구조 | 특징 | 문제 |
|---|---|---|
| 단일 수준 | 모든 사용자의 모든 파일이 디렉터리 하나에 | 이름 충돌, 그룹화 불가 |
| 2단계 | 마스터 디렉터리 아래 사용자별 디렉터리, **경로명** 도입 | 이름 충돌·검색은 해결, 그룹화는 여전히 불가 |
| 트리 | 하위 디렉터리 무한히, 현재(작업) 디렉터리 | 파일·디렉터리 공유 불가 |
| 비순환 그래프 | 링크로 공유 (사이클 없음) | 별칭, 삭제 시 매달린 포인터 |
| 일반 그래프 | 사이클 허용 | 순회 무한 루프, 참조 수가 0이 안 되는 고아 |
- 트리 구조
  - 경로: 절대(`/spell/mail/prog`) / 상대(현재 디렉터리 기준)
  - `cd /spell/mail/prog`, `rm <file>`, `mkdir <dir>` (현재 `/mail`에서 `mkdir count` → `/mail/count`)
  - 디렉터리를 지우면 그 아래 서브트리 전체가 사라짐에 주의 (`rm -r`)
- 비순환 그래프: 한 파일에 이름(별칭)이 여러 개 → 하나를 지우면 다른 쪽이 가리키는 대상이 사라짐(dangling pointer)
  - 해결: 백포인터로 모든 참조를 추적(가변 크기 레코드 문제), **참조 카운트**(0이 될 때 실제 삭제 = UNIX 하드 링크), 별도 **링크** 항목(심볼릭 링크, 원본이 지워지면 링크만 깨짐)
  - 링크 해석(link resolution): 링크를 따라가 실제 파일을 찾는 것
- 일반 그래프: 사이클 방지법 → 파일에만 링크를 허용하고 디렉터리엔 불허 / 가비지 컬렉션 / 링크를 추가할 때마다 사이클 탐지
### 마운트
- 파일 시스템은 쓰기 전에 **마운트**해야 함: 기존 디렉터리 트리의 한 지점(**마운트 포인트**)에 붙임 (`mount /dev/sdb1 /mnt/usb`)
- 마운트 포인트에 원래 있던 내용은 언마운트할 때까지 가려짐
### 파일 공유
- 다중 사용자 시스템: 보호 체계로 공유 범위 제한
  - 사용자 ID로 사용자 구분, 그룹 ID로 그룹 권한, 파일·디렉터리마다 소유자와 그룹
- 원격 파일 시스템
  - 수동: FTP / 자동: 분산 파일 시스템 / 반자동: 웹
  - 클라이언트-서버: 클라이언트가 서버의 파일 시스템을 마운트, 서버 하나가 여러 클라이언트 지원
  - NFS(UNIX 표준), CIFS/SMB(Windows), Samba. OS의 파일 호출을 원격 호출로 변환
  - 사용자 식별·인증엔 분산 정보 시스템(LDAP, DNS, NIS, Active Directory)
- 장애 모드: 디스크 손상, 메타데이터 손상 + 원격이면 네트워크·서버 장애까지
  - 요청마다 상태를 추적해야 복구 가능
  - NFS v3는 **상태 비저장(stateless)**: 요청마다 필요한 정보를 다 담음 → 서버가 죽었다 살아나도 복구 쉬움, 대신 보안이 약함
### 보호
- 소유자가 누가(who) 무엇을(what) 어떻게(how) 할 수 있는지 제어
- 접근 유형: read, write, execute, append, delete, list
- **UNIX**: 소유자 / 그룹 / 그 외 × rwx (3비트씩)
  - `chmod 761 game` → 소유자 rwx(7), 그룹 rw-(6), 기타 --x(1)
  - 관리자에게 그룹 G를 만들고 사용자를 넣어 달라고 한 뒤 `chgrp G game`으로 파일을 그룹 G에 연결
- `ls -l` 읽기
```
-rw-rw-r--  1 pbg staff   31200 Sep  3 08:30 intro.ps
drwx------  5 pbg staff     512 Jul  8 09:33 private/
drwxrwxr-x  2 pbg staff     512 Jul  8 09:35 doc/
drwxrwx---  2 pbg student   512 Aug  3 14:13 student-proj/
-rw-r--r--  1 pbg staff    9423 Feb 24  2003 program.c
-rwxr-xr-x  1 pbg staff   20471 Feb 24  2003 program
drwx--x--x  4 pbg faculty   512 Jul 31 10:31 lib/
drwxrwxrwx  3 pbg staff     512 Jul  8 09:35 test/
```
  - 첫 글자 `d`는 디렉터리, 나머지 9글자가 소유자·그룹·기타 rwx. 그 다음은 링크 수, 소유자, 그룹, 크기, 수정 시각, 이름
  - 디렉터리의 x는 "들어갈 수 있음"(cd, 경로 통과) 권한 → `lib/`은 다른 사람이 목록은 못 보지만 안의 파일에 경로로는 접근 가능
- **Windows ACL**: 파일 속성 → 보안 탭에서 사용자·그룹마다 모든 권한, 수정, 읽기 및 실행, 읽기, 쓰기, 특수 권한을 허용/거부로 세밀하게 지정
