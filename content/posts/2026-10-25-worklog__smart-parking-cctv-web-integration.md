> 사전 채점된 54일치 CCTV 점유 데이터를 경량화해 웹에 연동하고, 실제 주차장과 미니어처 시연의 역할을 분리하기 위해 사이트 구조와 반응형 레이아웃을 전면 개편함.

# 배경 — 왜 하게 됐나 ?
- 상황 / 문제
  - 스마트 주차 관제 시스템 데모 웹은 원래 미니어처 주차장(25칸) 위주로 구성되어 있었음.
  - 하지만 모형 환경만 보여주는 구성으로는 실제 주차장(59칸) 환경에서도 시스템이 안정적으로 동작한다는 점을 입증하기에 설득력이 부족했음.
  - 실제 주차장에는 수개월간(2026.07.30 ~ 2026.09.22) 수집된 점유 판정 데이터(2.3GB, 459만 줄)가 있었으나, 웹 화면과 연결되지 않아 활용하지 못하고 있었음.
  - 보안과 개인정보 보호 규칙상 실제 주차장 카메라 영상 프레임을 외부 웹 화면으로 직접 내보낼 수 없었음.
  - 원본 영상을 노출하지 않으면서 점유 수치와 주차면 상태만 안전하게 표출하는 구조가 필요했음.
- 목표
  - 54일치 대용량 점유 데이터를 웹 서버에서 지연 없이 표출할 수 있도록 일 단위 경량 파일로 구조화함.
  - 실제 주차장(59칸)과 미니어처 주차장(25칸)의 상이한 데이터를 단일 웹 서비스 내에서 충돌 없이 분리 표출함.
  - 모바일(375px)과 PC(960px 이상) 화면 모두에서 가독성을 보장하는 반응형 레이아웃을 구축함.
  - 브라우저 정적 자원 캐시 문제를 해결하여 배포 후 강제 새로고침 없이도 즉시 올바른 주차면 화면이 로드되도록 함.

# 환경
- 장비 : 로컬 Mac mini, 휴대용 노트북, 엣지 보드 (Jetson)
- 카메라 환경 : 주차장 CCTV (해상도 352×240, 1분 1장 촬영), 미니어처 웹캠 (25칸 판정용)
- 소프트웨어 : Python 3, FastAPI 웹 서버, ruff, pytest

# 진행 흐름
1. CCTV 점유 데이터 활용 방안 수립 및 보안 원칙 확인
  - 이미 채점된 54일치(2026.07.30 ~ 2026.09.22) CCTV 점유 판정 데이터(2.3GB)를 웹 화면에 표출하는 세 가지 방안을 검토함.
    - 1번 : 현재 시각 맞춤 재생 (현재 요일 및 시각에 해당하는 과거 기록을 불러와 실시간처럼 표출).
    - 2번 : 임의 날짜 및 시각의 과거 기록 조회.
    - 3번 : 요일별 30분 단위 예측 모델 대비 실제 점유율 비교.
  - 처음 계획 : 세 가지 기능을 운전자용 시연 메인 화면에 모두 나열하고자 함.
  - 버린 이유 : 시연 화면은 "지금 주차장에 자리가 있는가"를 직관적으로 보여주어야 하는데, 과거 조회나 오차 분석 같은 개발자 지표가 섞이면 화면이 복잡해짐.
  - 바꾼 방법 : 1번(현재 시각 재생)을 메인 시연 화면에 두고, 2번(과거 기록)과 3번(예측 비교)은 개발자 지표 페이지(`/dev`)의 세부 지표 카드로 분리 수용하기로 결정함.
  - 보안 원칙 준수 : 실제 주차장 카메라 영상 및 프레임 이미지는 웹 화면으로 일절 송출하지 않고, 점유 수치와 주차면 상태 데이터만 전송하는 원칙을 유지함.
  → 대용량 점유 데이터를 웹 서버가 빠르게 읽을 수 있도록 사전 경량화 도구를 작성하게 됨.

2. 데이터 경량화 도구 구현 및 판정 로직 검증
  - 2.3GB 용량에 달하는 459만 줄의 원본 점유 데이터 CSV 압축 파일을 웹 요청마다 파싱하는 것은 부하가 큼.
  - 일 단위 경량 JSON 파일을 사전에 생성하는 변환 도구를 직접 작성함.
  - 하루 1,440분 동안 59칸의 상태를 `1`(점유), `0`(빈자리), `?`(신뢰 낮은 칸)으로 표기하는 압축 문자열 구조를 설계함.
  - 변환 결과 : 54개(55일치) 일 단위 JSON 파일이 생성되었으며, 총 용량 5.3MB, 하루 평균 약 85KB 수준으로 압축됨. 전체 변환 소요 시간은 4초 만에 완료됨.
  - 점유 판정 기준 통일 : 예측 모델 표 생성 로직과 일치하도록 확률 p ≥ 0.5를 점유로 간주하고, 빈 주차면 집계는 신뢰 주차면 48칸만 세도록 통일함.
  - 데이터 교차 검증 : 전체 77,770개 프레임의 빈 주차면 수를 기존 예측 모델 표와 1:1로 대조 검증함. 그 결과 77,766개 프레임(99.99%)이 일치함을 실측함.
  - 불일치한 4개 프레임은 동일 분에 중복 촬영된 10건 중 후속 프레임을 채택한 차이였음을 확인함.
  → 경량 데이터 파이프라인의 신뢰성을 확인하고 데모 웹 화면에 이를 연동하는 작업으로 넘어감.

3. 사이트 구조 왜곡 인지 및 롤백
  - 기존 라우터 분리 구조에 맞춰 CCTV 연동 라우터를 신설하고 데모 경로(`/demo`)에 별도의 "CCTV" 탭을 추가함.
  - 동시에 데모 메인 화면 문구를 "미니어처 주차장"으로 수정함.
  - 문제 발생 : 기존 사이트는 메인(`/`)이 미니어처 주차장이고 하위 경로(`/demo`)가 실제 주차장 역할을 담당하고 있었는데, 별도 탭을 추가하면서 기존 역할 분리가 무너지고 페이지 간 문구 혼동이 발생함.
  - 즉시 조치 : 별도 탭 방식을 즉시 철회하고, 데모 경로(`/demo`) 자체의 메인 화면과 지도 데이터를 CCTV 녹화 재생 데이터로 대체함.
  - 화면 상단 배지에 "녹화 기록 재생 · 실시간 아님" 표시를 부착하여 실시간 관제와 녹화 재생 데이터 간의 차이를 명확히 구분함.
  → 화면에 주차면 지도를 띄웠으나 일부 주차면에 공백이 생기는 현상을 발견함.

4. 주차면 지도 배치 및 미검출 칸 채우기 결정
  - 352×240 저해상도 CCTV 환경에서 주차면 차량 분류기의 교차검증 정확도를 검사한 결과, 기준선인 85% 미만인 9개 칸(O04 · O05 · O11 · O13 · I13 · U15 · U17 · U18 · U19)이 발생함.
  - 정확도 실측값은 0.77 ~ 0.85 범위에 분포함. U줄 외곽 4칸(0.82 · 0.79 · 0.77 · 0.85)은 렌즈 왜곡 때문이었고, O줄 4칸(0.85 · 0.85 · 0.77 · 0.82)은 원거리 해상도 저하 및 그늘 때문이었음.
  - 정확도 0.846을 기록한 주차면은 39장 중 33장을 맞힌 것으로, 기준 통과 최저선인 0.872(34장 적중)와 불과 1장 차이였음.
  - 처음 구현 : 판정 신뢰도가 낮은 9개 칸을 집계뿐만 아니라 화면 지도에서도 제외함.
  - 버린 이유 : 주차면 지도 중간중간에 빈 구멍이 뚫려 화면이 시각적으로 미완성처럼 보이고 사용자 혼란을 초래함. 향후 카메라 추가 설치와 재학습이 이루어지면 정확도가 개선될 영역임.
  - 바꾼 방법 : 빈 주차면 수 집계(38 / 48칸 등)는 신뢰 주차면 48칸 기준으로 엄격히 유지하되, 화면 지도에는 59칸 전체 주차면을 채워서 온전한 형태로 렌더링함.
  → 전체 주차면 지도를 완성한 후 로그인 사용자 맞춤 예측 화면을 연동하는 작업으로 이어짐.

5. 맞춤 예측 탭 통합 및 반응형 레이아웃 구현
  - 로그인 시 제공되는 '맞춤 예측' 탭과 '현황' 탭을 하나로 통합하는 과정에서, 착오로 '맞춤 예측'과 '예측'을 통합하는 실수를 저지름.
  - 또한 화면 해상도가 달라져도 모든 UI 요소가 세로 1줄로 늘어서서 넓은 PC 화면에서 여백 낭비가 발생함.
  - 바꾼 방법 : 맞춤 예측 탭 내부에 현황 카드와 요약 지도를 통합하고, CSS 미디어 쿼리를 도입하여 화면 해상도에 따라 배치가 유동적으로 바뀌는 반응형 레이아웃을 구현함.
    - 모바일 좁은 화면(375px) : 맞춤 예측 카드 아래에 현황 카드가 세로 1단으로 자연스럽게 스크롤되도록 배치함.
    - PC 넓은 화면(960px 이상, 1440px 테스트) : 왼쪽에 맞춤 예측 카드, 오른쪽에 현황 및 요약 지도가 나란히 배치되는 좌우 2단 레이아웃을 적용함.
  - 중간 작업 내역의 안전한 버전 관리를 위해 로컬 커밋 이력을 차곡차곡 유지하면서 작업을 진행함.
  → 단일 호스트 환경에서 미니어처와 실제 주차장의 라우팅 체계를 재검토하는 단계로 이어짐.

6. 라우팅 체계 및 기본 사이트 구조 역전
  - 사이트 사용 맥락 점검 : 미니어처 주차장 페이지에는 사용자 개인화(시간표 기반 맞춤 예측)가 필요 없음.
  - 별도 하위 도메인이나 DNS 분리가 없는 단일 호스트 환경에서 미니어처 페이지에 로그인 버튼이 있으면 로그인 후 돌아올 페이지 경로가 모호해지는 구조적 한계가 있었음.
  - 사용자 중심 구조 역전 결정 :
    - 실제 사용자가 접속하는 기본 경로(`/`)를 실제 주차장으로 전면 전환함. 로그인 버튼과 맞춤 예측 탭을 기본 경로에 집중 배치함.
    - 시연용 미니어처 페이지는 로그인 버튼이 없는 숨김 경로(`/live`)로 분리함.
    - 기존 데모 주소(`/demo`) 접속 시 `/live`로 자동 리다이렉트 처리함.
    - 자연어 질의응답 기능도 접속 페이지의 대상 주차장 정보를 기준으로 답변하도록 분기함 (`/`에서는 실제 주차장 기준 44자리 빈자리 안내, `/live`에서는 미니어처 기준 4자리 빈자리 안내).
  → 기본 주소가 실제 주차장으로 전환되면서 실제 주차장 전용 시연 탭이 필요해짐.

7. 주차장별 독립 시연 탭 구축 및 영상 배제 시연 구현
  - 기본 주소를 실제 주차장으로 변경하자, 기존 시연 탭이 미니어처 페이지만 보여주고 실제 주차장 시연 화면이 부재한 문제가 나타남.
  - 두 주차장의 카메라 구성과 판정 방식이 다르므로, 각 페이지마다 독립적인 시연 탭을 분리 배치함.
    - 미니어처 시연(`/live`) : 25칸 미니어처 웹캠 영상 + 차량 검출 박스 + 엣지 추론 속도 + OLED 디스플레이 표출.
    - 실제 주차장 시연(`/`) : 59칸 실제 주차장. 보안 원칙상 실제 카메라 영상을 노출하지 않고, 주차면 지도 위에 실시간 판정 상태를 오버레이하고 최근 2시간 동안의 주차면 변동 판단 로그(예: "U13 주차 감지", "추천 자리 변경")를 시간순으로 표출하는 방식으로 구현함.
  → 이 과정에서 브라우저 캐시로 인해 주차면 칸수가 잘못 출력되는 트러블슈팅이 발생함.

# 트러블슈팅
## 1. 데모 경로 별도 탭 신설로 인한 사이트 역할 구조 왜곡
- 현상 : 데모 경로(`/demo`)에 별도 "CCTV" 탭을 만들고 메인 화면을 미니어처로 변경했더니, 메인은 미니어처이고 데모는 실제 주차장이라는 기존 사이트의 역할 분리가 깨지고 사용자 혼란이 발생함.
- 원인 : 기존 웹 애플리케이션의 라우팅 구조와 역할 분담을 충분히 고려하지 않고 단순히 새로운 탭을 덧붙이는 방식으로 접근했기 때문임.
- 해결 : 별도로 추가했던 CCTV 탭을 즉시 삭제하고, 데모 경로(`/demo`) 자체의 메인 화면과 지도 데이터를 CCTV 녹화 재생 데이터로 대체함. 상단에 "녹화 기록 재생 · 실시간 아님" 배지를 명시하여 실시간 현황과 명확히 구분함.
- 결과 : 기존 사이트의 역할 분리를 유지하면서 녹화 재생 배지를 통해 실시간 현황과 명확히 구분함.

## 2. 탭 통합 대상 착오 및 고정 레이아웃으로 인한 여백 낭비
- 현상 : 맞춤 예측과 현황을 통합해야 하는데 맞춤 예측과 예측을 잘못 통합하였고, 화면 해상도가 달라져도 요소가 세로 1자로 고정되어 여백 낭비가 발생함.
- 원인 : 사용자 요구사항의 통합 대상을 오인하였고 화면 폭 변화에 따른 반응형 스타일(CSS 미디어 쿼리)이 누락됨.
- 해결 : 맞춤 예측 탭 내부에 현황 카드와 요약 지도를 배치하도록 바로잡음. 모바일 좁은 화면(375px)에서는 세로 1단 스크롤로, 데스크톱 넓은 화면(960px 이상)에서는 좌우 2단으로 나란히 배치되도록 CSS 미디어 쿼리를 구축함.
- 결과 : 모바일 화면(375px)과 PC 화면(1440px) 모두에서 최적의 가독성을 확보하고 여백 낭비 없이 안정적으로 표시되도록 함.

## 3. 브라우저 영구 캐시로 인한 시연 탭 주차면 수 불일치
- 현상 : 실제 주차장 시연 탭에서 59칸이 아닌 미니어처 25칸 화면이 나타남.
- 원인 : 서버에서 `no-cache` 헤더를 반환하도록 수정했으나, 이전에 브라우저에 영구 캐시된 정적 스크립트 파일이 갱신되지 않고 미니어처 화면 로직을 지속 실행함.
- 해결 : 서버가 웹 페이지를 응답할 때 정적 파일 경로 뒤에 파일 내용 기반 해시 쿼리스트링(`app.js?v=e1a11fb274`)을 붙이는 캐시 무효화(Cache Busting)를 적용하고, 시연 전용 뷰 경로(`/demo-view?lot=real`)를 명시적으로 분리함.
- 결과 : 사용자가 브라우저 캐시를 수동으로 비우거나 강력 새로고침(Cmd+Shift+R)을 하지 않아도 즉시 정확한 59칸 실제 주차장 화면이 렌더링됨.
