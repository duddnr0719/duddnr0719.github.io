### 네트워크 계층 제어 평면과 두 가지 구성 방식
- **네트워크 계층의 두 가지 핵심 기능 복습**
  - **포워딩(전달, forwarding)** = 입력 링크로 들어온 패킷을 알맞은 출력 링크로 옮기는 동작 → **데이터 평면(Data Plane)** 담당
  - **라우팅(routing)** = 송신지에서 목적지까지 패킷이 밟고 갈 전체 경로를 정하는 동작 → **제어 평면(Control Plane)** 담당
- **제어 평면을 구성하는 두 가지 구조**
  - **라우터 당(per-router) 제어** = 전통적 구조로, 각 라우터에 탑재된 개별 라우팅 알고리즘 컴포넌트가 자체적으로 포워딩 테이블을 산출함
  - **논리적 중앙 집중화 제어(소프트웨어 정의 네트워크, SDN)** = 원격 제어기가 전체 포워딩 테이블을 계산한 뒤 각 라우터의 **지역 제어 에이전트(Control Agents, CAs)**와 연동해 반영함

### 라우팅 프로토콜, 그래프 추상화, 알고리즘 분류
- **라우팅 프로토콜(Routing Protocol)과 경로**
  - 네트워크 주요 과제(`top-10`) 중 하나로, 송신 호스트에서 수신 호스트까지 라우터 망을 통과하는 최적의("좋은") 경로를 찾아내는 역할을 수행함
  - **경로(path)** = 최초 송신 호스트와 최종 목적지 호스트 사이에서 패킷이 순차적으로 거치는 라우터의 나열
  - **"좋은" 경로의 기준** = 최소 비용(cost) · 최단 지연(가장 빠름) · 최소 혼잡 경로를 뜻하며, 평가 지표로 비용(돈) · 거리 · 대역폭 · 단계 · 속도 · 전력량 등이 활용됨
- **그래프 추상화(Graph Abstraction)**
  - **핵심 문제** = 그래프 위에서 출발 노드 `u`로부터 목적 노드 `z`에 이르는 **최소비용경로(least-cost path)**를 탐색하는 것
  - **링크 비용 `c(x, x')`** = 노드 `x`와 `x'`를 잇는 링크의 비용 (예: `c(w, z) = 5`)
    - 고정값 `1`을 두거나, 대역폭에 반비례하거나, 혼잡도에 비례하도록 책정함
  - **경로 비용 산출** = 경로 `(x1, x2, …, xp)`를 이루는 연속된 링크 비용을 모두 더함
    - `c(x1, x2) + c(x2, x3) + … + c(xp-1, xp)`
- **라우팅 알고리즘 분류 기준**
  - **글로벌(global) vs 분산(decentralized) 정보**
    - **글로벌 알고리즘** = 네트워크 전체 토폴로지와 링크 비용 정보를 모든 라우터가 공유한 상태에서 계산함 → **링크 상태(link state, LS) 알고리즘**
    - **분산 알고리즘** = 각 라우터가 맞닿은 이웃 링크 비용만 파악한 채, 이웃끼리 정보를 주고받으며 반복 계산(iterative process)을 진행함 → **거리 벡터(distance vector, DV) 알고리즘**
  - **정적(static) vs 동적(dynamic)**
    - **정적 알고리즘** = 사람이 라우터 포워딩 테이블을 직접 손보므로 경로 변화 주기가 매우 느림
    - **동적 알고리즘** = 주기적 갱신이나 링크 비용 변동에 반응해 경로를 신속하게 바꿈

### 링크 상태(LS) 알고리즘: 다익스트라 알고리즘
- **다익스트라 알고리즘(Dijkstra algorithm)의 원리**
  - 각 노드가 링크 상태 패킷을 브로드캐스트 → 네트워크 전체 토폴로지와 링크 비용을 모든 노드가 동일하게 보유함
  - 특정 출발 노드가 나머지 모든 노드까지의 최소 비용 경로를 산출해 자신의 **포워딩 테이블(forwarding table)**을 완성함
  - `k`회 반복을 마치면 `k`개 목적지 노드의 최소 비용 경로가 확정됨
- **표기 기호**
  - `c(x, y)` = `x`와 `y` 사이 링크 비용 (직접 연결된 이웃이 아니면 `∞`)
  - `D(v)` = 현재까지 파악된 출발지~목적지 `v` 경로 비용
  - `p(v)` = 출발지에서 `v`로 가는 현재 경로상 `v` 직전 노드
  - `N'` = 최소 비용 경로가 확정된 노드 집합
- **수행 단계**
  - **초기화(step 0)** = `N'`에 출발 노드 `u`만 넣고, 모든 노드 `a`에 대해 `u`와 인접하면 `D(a) = c(u, a)`, 비인접이면 `∞`로 둠
  - **반복(모든 노드가 `N'`에 들 때까지)**
    - `N'` 바깥의 노드 중 `D(a)` 값이 가장 작은 `a`를 골라 `N'`에 편입함
    - `a`의 이웃이면서 아직 `N'`에 속하지 않은 모든 `b`에 대해 `D(b) = min(D(b), D(a) + c(a, b))`로 최소 비용을 업데이트함
- **동작 예와 최소 비용 경로 트리 구성**
  - **첫 번째 예(`u · v · w · x · y · z`)** = `step 0`에서 `u`가 인접 노드 비용 `D(v)=2` · `D(w)=5` · `D(x)=1`(모두 이전 노드 `u`)로 시작함
    - 이후 `x` → `y` → `v` → `w` → `z` 순서로 `N'`이 넓어지며 최종 `D(z)=4`(이전 노드 `y`)까지 확정됨
  - **두 번째 예(예 1-2)** = `step 0`에서 `D(v)=7` · `D(w)=3` · `D(x)=5`(이전 노드 `u`)로 출발해 `u` → `uw` → `uwx` → `uwxv` → `uwxvy` → `uwxvyz` 순으로 확정됨
    - 과정에서 `D(v)`는 `7(u)`에서 `6(w)`로, `D(y)`는 `11(w)`에서 `10(v)`로, `D(z)`는 `14(x)`에서 `12(y)`로 더 짧은 경로를 따라 갱신됨
  - **경로 트리 생성과 동률 처리** = 각 노드의 `p(v)`를 거슬러 올라가 **최소 비용 경로 트리(least-cost-path tree)**를 만들며, 비용이 같은 경우(ties)는 임의로 선택함
- **복잡도(Complexity)**
  - **시간(계산) 복잡도(`n`개 노드)** = 매 반복마다 `N'`에 없는 최소 비용 노드 `w`를 찾기 위해 전체 노드를 훑으면 총 `n(n+1)/2`회 비교가 필요해 `O(n²)`이 됨
    - 힙(heap) 자료구조를 적용해 `w` 탐색을 가속하면 `O(n log n)`으로 줄어듦
  - **메시지 복잡도** = `n`개 라우터가 각자 `O(n)`개 링크로 링크 상태 정보를 브로드캐스트해야 하므로 총 `O(n²)` 메시지가 발생함
- **진동(Oscillation) 문제**
  - 링크 비용을 현재 흐르는 트래픽 양에 연동할 때 나타나는 현상임
  - 처음에는 반시계 방향(`D→A` · `C→B→A`)이 유리해 선택되지만, 트래픽이 몰린 뒤 LS 알고리즘을 다시 돌리면 시계 방향(`B→C→D→A`)으로 쏠리고, 재실행할 때마다 양방향을 끝없이 왕복함

### 거리 벡터(DV) 알고리즘: 벨만-포드 식과 상태 확산
- **동적 계획법과 벨만-포드 식(Bellman-Ford equation)**
  - **동적 계획법(dynamic programming)** = 큰 문제를 여러 하위 문제(subproblem)로 쪼개 각각 해를 구한 뒤 조합해 전체 해를 도출하는 방식
  - `u`의 이웃 `x · v · w`가 목적지 `z`까지의 예상 비용을 보유할 때, 그중 합산 비용이 가장 작은 이웃이 최단 경로의 다음 홉이 되어 `u`의 포워딩 테이블 엔트리를 채움
  - **벨만-포드 갱신 식** = 모든 목적 노드 `y ∈ N`에 대해 `Dx(y) ← minᵥ{c(x, v) + Dv(y)}`로 갱신함
- **동작 원리와 특성**
  - 각 노드는 주기적·필요 시 자신의 **거리 벡터(Distance Vector, DV)** 추정치를 이웃에게 전달함
  - 노드 `x`는 이웃에게서 새 DV를 받을 때마다 벨만-포드 식을 적용해 자신의 DV를 고치며, 이 교환을 반복하면 추정 비용 `Dx(y)`가 실제 최소 비용 `dx(y)`로 수렴함
  - **반복적 · 비동기적(iterative, asynchronous)** = 로컬 링크 비용이 변하거나 이웃 DV가 도착할 때만 각자 반복 계산을 수행함
  - **분산적(distributed)** = 자신의 DV 값이 달라질 때에 한해 이웃에게 광고하고, 광고를 수신한 노드만 후속 계산을 이어감
- **거리 벡터 알고리즘 계산 예(`a` ~ `i` 9개 노드 격자)**
  - **초기 비대칭 조건** = 대부분 링크 비용이 `1`이지만 `a-b` 링크는 큰 비용(`8`)을 가지며, `c-f` 사이에는 링크가 빠져 있음
  - **`t=0` 초기화** = 각 노드는 직접 맞닿은 이웃까지의 거리만 설정하고 비이웃은 `∞`로 둔 로컬 DV를 이웃에게 송신함 (예: `a`는 `Da(a)=0` · `Da(b)=8` · `Da(d)=1`, 나머지 `∞`)
  - **`t=1` 계산(노드 `b` 예)** = `b`는 이웃 `a · c · e`의 DV를 수신해 새 DV를 산출함
    - `Db(d) = min{8+1, 1+∞, 1+1} = 2`
    - `Db(f) = min{∞, ∞, 1+1} = 2`
    - `Db(h) = min{∞, ∞, 1+1} = 2`
  - **`t=1` 계산(노드 `c` · `e` 예)** = `c`는 `b`의 DV를 받아 `Dc(a) = 1+8 = 9` · `Dc(b) = 1+0 = 1` · `Dc(e) = 1+1 = 2` 등을 구하고, `e`는 `b · d · f · h`로부터 DV를 수신해 `t=1`의 새 DV를 계산하도록 제시됨
- **상태 정보 확산**
  - 통신과 계산 라운드가 거듭될수록 한 노드의 상태 정보가 네트워크 전역으로 번짐
  - 예: `t=0` 시점 `c`의 상태는 `c` 자신에게만 있다가 `t=1`에 1홉(`b`) → `t=2`에 2홉(`b · a · e`) → `t=3`에 3홉(`f · h` 등) → `t=4`에 4홉(`g · i`까지)의 거리 벡터 산출에 순차적으로 반영됨

### 링크 비용 변경, 무한 카운트, 포이즌 리버스
- **링크 비용 변동 처리 절차** = 링크 비용 변화 감지 → 라우팅 테이블 업데이트 및 DV 재계산 → DV 변동이 발생하면 이웃 노드에게 전파
- **비용 감소(좋은 소식)의 빠른 전파**
  - 예: `t=0`에 `y`가 `x`와의 링크 비용 하락(`4 → 1`)을 포착해 DV를 고쳐 알림 → `t=1`에 `z`가 이를 수신해 `x`까지 최소 비용을 `5`에서 `2`로 낮춰 전파 → `t=2`에 `y`가 받지만 `y`의 최소 비용은 그대로여서 추가 송신 없이 수렴함
- **비용 증가(나쁜 소식)와 무한 카운트(count to infinity) 문제**
  - 링크 비용 상승 소식은 망 전체로 더디게 퍼지며 라우팅 루프와 무한 카운트를 일으킴
  - **발생 예** (`c(z, x)=50` · 변동 전 `Dy(x)=4` · `Dy(z)=1` · `Dz(y)=1` · `Dz(x)=5`):
    - `t=0`: `y`가 링크 비용 상승(`4 → 60`)을 감지하고 기존에 `z`가 갖고 있던 `Dz(x)=5`를 참조해 `Dy(x) = min{60+0, 1+5} = 6`으로 계산함 → `y→z`, `z→y` **라우팅 루프** 형성
    - `t=1` 이후: `z`가 `Dy(x)=6`을 받아 `Dz(x) = min{50+0, 1+6} = 7`로 올리고 다시 알리며, `Dy(x)=8`, `Dz(x)=9`로 연쇄 상승이 이어짐
    - 결국 `z`가 `y`를 경유하는 비용이 `50`을 넘는다는 것을 깨달을 때까지 **44번**의 반복을 거침
- **포이즌 리버스(poison reverse)**
  - **원칙** = `z`가 `y`를 경유해 목적지 `x`에 도달하는 경로를 택한 경우, `z`는 역으로 `y`에게 `x`까지의 거리를 `∞`(`Dz(x) = ∞`)로 속여 광고함
  - **동작 예(`4 → 60` 상황)**
    - `t=0`: `z`가 `y`의 링크 비용 변화(`4 → 60`) 시 기존 `y` 경유 거리 벡터(`Dz(x)=5`) 대신 `Dz(x) = ∞`로 광고해 `y`가 `Dy(x) = min{60+0, 1+∞} = 60`을 계산하고 `x`로 직접 라우팅한 뒤 `Dy(x)=60`을 `z`에 알림
    - `t=1`: `z`가 `x`행 경로를 직접 링크 `z→x`로 전환하고 `Dz(x)=50`을 `y`에 통보함
    - `t=2`: `y`가 `z` 경유 경로를 택해 `Dy(x)=51`로 갱신 후 알림
    - `t=3`: 이제 `z`가 `y`의 최단 경로 다음 홉이므로 `y`는 실제 값(`51`) 대신 `Dy(x) = ∞`를 `z`에 보내 `y`를 경유하는 역경로 형성을 막음
  - **한계** = **세 개 이상의 이웃 노드**가 얽힌 루프에 대해서는 무한 카운트 문제를 막지 못함

### 링크 상태(LS) vs 거리 벡터(DV) 비교
- **정보 교환 범위와 방식(상호 보완적 접근)**
  - **LS** = 네트워크 내 다른 모든 노드와 통신하며, 자신에게 직접 붙은 링크 비용 정보만 발신함
  - **DV** = 인접한 이웃 노드와만 통신하며, 전체 목적 노드까지의 최소 비용 추정치를 전달함
- **메시지 복잡성(message complexity)**
  - **LS** = 노드 `n`개 · 링크 `E`개일 때 `O(nE)` 메시지를 주고받으며 `N²`으로 수렴함
  - **DV** = 인접 이웃 간에만 메시지를 주고받으며, 환경에 따라 수렴 소요 시간이 달라짐
- **수렴 속도(speed of convergence)**
  - **LS** = `O(nE)` 메시지가 드는 `O(n²)` 연산으로 수렴하지만, **진동(oscillation)** 현상이 생길 수 있음
  - **DV** = 수렴 시간이 가변적이며, **라우팅 루프** 및 **무한 카운트 문제**가 나타날 수 있음
- **강건성(robustness) — 오류 및 오동작 시 영향**
  - **LS** = 특정 노드가 잘못된 링크 비용을 퍼뜨려도 각 노드는 자기 포워딩 테이블만 계산함
  - **DV** = 특정 노드가 엉터리 경로 비용을 알리면 이웃 노드의 테이블 계산에 그대로 반영되어 오류가 망 전체로 번짐 → **블랙홀 효과** 발생 (임의의 노드가 실수로 cost `0`을 선언하면 인터넷 전체 패킷이 그 노드로 몰려 장애를 유발하는 현상)
