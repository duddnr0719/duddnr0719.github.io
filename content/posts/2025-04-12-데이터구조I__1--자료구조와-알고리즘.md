# 자료구조란 ?
> 자료들을 정리하여 보관하는 여러 가지 구조
프로그램 = 자료구조 + 알고리즘
→ 알고리즘 : 컴퓨터로 문제를 풀기 위한 단계적인 절차.
---
### 알고리즘의 조건
- 입력 : 0개 이상의 입력이 존재하여야 한다.
- 출력 : 1개 이상의 출력이 존재하여야 한다.
- 명백성 : 각 명령어의 의미는 모호하지 않고 명확해야 한다. (clearance)
- 유한성 : 한정된 수의 단계 후에는 반드시 종료되어야 한다.
- 유효성 : 각 명령어들은 실행 가능한 연산이어야 한다.
> 알고리즘에는 입력은 없어도 되지만 출력은 반드시 하나 이상 있어야 하고 모호한 방법으로 기술된 명령어들의 집합은 알고리즘이라고 할 수 없다.
### 알고리즘 표현 방법
- 한글이나 영어 같은 자연어 : 자연어를 사용하기 때문에 모호함 존재. 따라서 명령어로 사용되는 단어들을 명백하게 정의해야함.
- 흐름도(flow chart) : 도형을 사용하여 알고리즘을 기술하는 방법. 하지만 알고리즘이 복잡해질수록 기술하기 힘들어짐.
- 의사코드(pseduo-code) : 가장 많이 사용하는 방법. 알고리즘의 핵심적인 내용만 표현 가능.
- 프로그래밍 언어 : 알고리즘의 가장 정확한 기술 가능. 하지만 많은 구체적인 사항들이 알고리즘의 핵심 내용을 파악하는 데 방해할 수 있음.

# 추상자료형(ADT : Abstract Data Type)
## 자료형 ?
→ 데이터의 종류. 정수, 실수, 문자열 등이 기초적인 자료형의 예.
## 추상자료형 ?
> → 실제적인 구현으로부터 분리되어 정의된 자료형. 즉, 자료형을 추상적(수학적)으로 정의한 것.
→ 데이터나 연산이 무엇인가는 정의되지만 데이터나 연산을 어떻게 컴퓨터 상에서 구현할 것인지는 정의하지 않음.
### ex) 자연수를 나타내는 ADT
```
- 객체 : 0에서 시작하여 INT_MAX까지의 순서화된 정수의 부분범위
- 함수 : 
Nat_Number zero() ::= 0
Nat_Number successor(x) ::= if(x==INT_MAX) return x           else return x+1
Boolean is_zero(x) ::= if(x) return False                     else return True
Boolean equal(x,y) ::= if(x==y) return True                   else return False
Nat_Number add(x,y) ::= if((x+y) <= INT_MAX) return x+y       else return INT_MAX
Nat_Number sub(x,y) ::= if(x<y) return 0                      else return x-y
```
→ ADT = 객체 + 함수
→ 객체 : 추상 데이터 타입에 속하는 객체가 정의됨. 객체는 주로 집합의 개념을 사용하여 정의.
→ 함수는 함수의 이름, 매개변수, 반환형, 수행하는 기능의 기술 등이 포함.
→ ::= 기호는 ~으로 정의된다 를 의미.
## TV와 ADT의 유사성
> 
### TV
- TV의 인터페이스가 제공하는 특정한 작업만을 할 수 있다.
- 사용자는 이러한 작업들을 이해해야 한다. 즉 TV를 시청하기 이해서는 무엇을 해야 하는지 알아야 한다.
- 사용자는 TV의 내부를 볼 수 없다.
- TV의 내부에서 무엇이 일어나고 있는지를 몰라도 이용할 수 있다.
- 누군가가 TV 내부의 기계장치를 교환한다고 하더라도 인터페이스만 바뀌지 않는 한 그대로 사용이 가능하다.
> 
### 추상 자료형(ADT)
- 사용자들은 ADT가 제공하는 연산만을 사용할 수 있다.
- 사용자들은 ADT가 제공하는 연산들을 사용하는 방법을 알아야 한다.
- 사용자들은 ADT 내부의 데이터를 접근할 수 없다.
- 사용자들은 ADT가 어떻게 구현되었는지 모르더라도 ADT를 사용할 수 있다.
- 만약 다른 사람이 ADT의 구현을 변경하더라도 인터페이스가 변경되지 않으면 사용자들은 여전히 ADT를 같은 방식으로 사용할 수 있다.

## 알고리즘의 성능분석
### 알고리즘의 성능 분석 기법
1. 수행 시간 측정
→ 두 개의 알고리즘의 실제 수행 시간을 측정하는 것
→ 실제로 구현하는 것이 필요. 알고리즘이 단순한 경우에는 쉽게 구현할 수 있지만 복잡한 경우 구현하기 부담이 될 수 있음.
→ 반드시 동일한 하드웨어를 사용하여야 함.
---
1. 알고리즘의 복잡도 분석
→ 직접 구현하지 않고서도 수행 시간을 분석하는 것
→ 알고리즘이 수행하는 연산의 횟수를 측정하여 비교함.
→ 일반적으로 연산의 횟수는 n의 함수로 나타냄.
### 복잡도 분석
1. 시간 복잡도 : 알고리즘의 수행 시간 분석. 알고리즘을 이루고 있는 연산들이 몇 번이나 수행 되는지를 숫자로 표시.
1. 공간 복잡도 : 알고리즘이 사용하는 기억공간 분석.
→ 알고리즘의 복잡도를 얘기할 때 보통은 시간 복잡도를 말함.
## 시간 복잡도 표기법
- **Big-O**(빅 오) 표기법 : 알고리즘의 최악의 실행 시간을 표기. 가장 많이 사용하는 표기법. 최소한 보장되는 성능을 표기하기 때문에 일반적으로 사용됨. 함수의 상한을 표시.
- **Big-Ω**(빅 오메가) 표기법 : 알고리즘의 최상의 실행 시간을 표기. 함수의 하한을 표시.
- **Big-θ**(빅 세타) 표기법 : 알고리즘의 평균 실행 시간을 표기. 함수의 상한과 하한을 동시에 표시.
### Big-O 표기법 특징
: 시간 복잡도에 미미한 영향을 주는 것들은 배제하고 표기 → 자료의 개수가 많은 경우에는 차수가 가장 큰 항이 가장 영향을 크게 미치기 때문.
1. 상수항 무시
1. 계수 무시
1. 최고차항만 표기
