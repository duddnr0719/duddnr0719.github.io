4. 클래스와 객체 I

2025년 8월 27일 Java(교재)

객체지향 프로그래밍(Object-oriented programming)

  • 객체(object)를 사용하는 프로그래밍 방식
  • 데이터와 함수를 하나의 덩어리로 묶어서 생각하는 방법 ⇒ 데이터와 함수를 하나의 덩어리(객체)로 묶는 것을 캡슐화(encapsulation)라고 부른다.
  • 객체들은 객체 나름대로의 고유한 기능을 수행하면서 다른 객체들과 상호 작용한다.
  • 객체들은 메세지를 통하여 상호 작용한다.

객체(Object)

- 객체는 상태와 동작을 가지고 있다. - 객체의 상태(state)는 객체의 속성이다. - 객체의 동작(behavior)은 객체가 취할 수 있는 동작이다. ![](/images/68d2f20f24bd9e6e.png) ## 객체지향 프로그램의 특징 - 캡슐화 ![](/images/632fa47de6a08448.png) - 상속 ![](/images/931c0fccbb7c94bf.png) - 다형성 → 동일한 이름의 동작이라고 하여도 객체의 실제 타입에 따라서 동작의 내용이 달라질 수 있다는 것을 의미한다. → 객체의 동작이 실제 타입에 따라서 달라지는 것을 말한다. ⇒ ex) 같은 speak() 메소드를 실행하여도 실행 문장을 받은 객체들이 모두 다르게 소리를 낸다. ![](/images/c973a8a7de58ef95.png) - 추상화 → 불필요한 정보는 숨기고 중요한 정보만들 표현함으로써 프로그램을 간단히 만드는 기법. ⇒ 필요한 것만 남겨 놓는 것. (추상화 과정이 없다면 사소한 것도 신경 써야 한다.) --- # 절차지향 프로그래밍 - 프로시저(procedure)에 기반을 둔 프로그래밍 방식 - 절차라는 용어는 procedure를 번역한 것이며, 프로시저는 함수 또는 서브루틴을 뜻한다. - 절차지향 프로그래밍에서 프로그램은 함수(procedure)들의 집합으로 이루어진다. ## 절차지향의 문제점 - 유지보수가 어렵다. → 절차지향 프로그래밍은 프로그램의 흐름이 복잡해지고 코드량이 많아질수록 수정 및 유지보수가 어려워진다. 특히, 프로그램의 특정 부분을 변경하기 위해선 관련된 다른 부분까지 함께 수정해야 하는 경우가 많아 오류 발생 가능성이 높아진다. - 코드 재사용성 부족 → 각 함수나 절차가 독립적으로 정의되어 있어, 다른 프로그램에서 재사용하기가 어렵다. - 순서 의존성 → 프로그램의 실행 순서가 엄격하게 정해져 있어서 순서 변경 시 오류가 발생하거나 예상치 못한 결과가 나올 수 있다. - 디버깅 어려움 → 프로그램의 흐름이 복잡해지면 디버깅에 어려움을 겪기 쉽다. --- # 클래스 - 객체를 생성하기 위한 설계도 또는 템플릿과 같은 역할을 수행한다. - 클래스는 객체의 상태(변수)와 행동(메소드)를 정의한다. ![](/images/6c6be006f0dcbb62.png) ## 객체 생성 → 위에서 말했듯, 클래스는 객체를 생성하기 위한 설계도에 해당한다. 설계도만 가지고는 어떠한 작업도 할 수 없다. 따라서 작업을 하기 위해선 객체를 생성하여야 한다. ```java public class Circle{ // 필드 public int radius; public String color;

public class Test{ public static void main(String args[] { Circle obj; // 객체 참조 변수 선언 obj = new Circle(); // new 연산자를 사용하여 객체를 생성하고 객체의 참조값을 참조 변수에 저장 // 객체의 속성 할당 obj.radius = 100; obj.color = “blue”;

> 💡 참조 변수

- 객체를 참조할 때 사용되는 변수로서 객체의 참조값(일반적으로 객체의 주소를 가리킨다)이 저장된다.

- 참조 변수만 선언하고 new 연산자를 이용하지 않으면 객체가 생성되지 않는다.

## 메소드 오버로딩(Method Overloading)
- 클래스 하나에 같은 이름의 메소드를 여러 개 정의하는 것.
- 이름이 같은 메소드를 여러 개 정의하는 것.
- 각각의 메소드가 가지고 있는 매개 변수는 달라야 한다.
  - ex) add(x,y) / add(x,y,z)
## 생성자(Constructor)
- 객체가 생성될 때 객체를 초기화하는 특수한 메소드
```java
class Pizza {
	int size;
	String type;
	public Pizza() {
		size = 12;
		type = "슈퍼슈프림";
	}
	public Pizza(int s, String t) {
		size = s;
		type = t;
	}
public class PizzaTest() {
	public static void main(String args[]) {
		Pizza obj1 = new Pizza(); // 매개 변수가 존재하지 않으므로 type이 슈퍼슈프림인 피자 객체가 생성된다.
		Pizza obj2 = new Pizza(24, "포테이토"); // 매개 변수가 존재하므로 type이 포테이토인 피자 객체가 생성된다.
	}
}

기본 생성자(Default Constructor)

  • 매개 변수가 없는 생성자
  • 클래스에 생성자를 하나도 정의하지 않으면 자바 컴파일러는 기본 생성자를 자동으로 만든다
class Box {
	int width, height, depth;
}

public class BoxTest() {
	public static void main(String args[]) {
		Box b = new Box(); // Box 클래스에 생성자가 없으므로 기본 생성자가 생성되어 객체의 필드 값이 0으로 초기화된다.
	}
}

this 참조 변수 vs this()

> 💡 this 참조 변수 - 현재 객체 자신을 가리키는 참조 변수.

  • this는 컴파일러에서 자동으로 생성한다.

  • 생성자에서 매개 변수 이름과 필드 이름이 동일한 경우에 혼동을 막기 위해서 사용한다. > 💡 this()

  • 다른 생성자를 의미한다. 

public class Circle {
	int radius;
	
	public Circle(int radius) {
		this.radius = radius; // this.radius는 필드의 radius를 가리킨다.
	}
	public Circle() { // 위의 생성자를 호출한다.
		this(0);
	}
}

접근 제어(Access Control)

  • 클래스의 멤버에 접근하는 것을 제어하는 것
  • public , private 등을 멤버 앞에 붙여 접근을 제한한다.
  • private → 클래스 안에서만 접근할 수 있다.
  • public → 누구나 접근할 수 있다.
  • protected → 자식 클래스만 접근할 수 있다.(상속)
  • 접근 지정자가 없는 경우 → default라고 불리며 동일한 패키지 안에서만 접근이 가능하다.

접근자와 설정자

  • 필드값을 반환하는 접근자(Getters), 필드값을 설정하는(Setters).
  • 이러한 메소드는 대게 get이나 set을 메소드 이름 앞에 붙여 사용한다.
    • ex) getBalance() / setBalance()

접근자와 설정자를 사용하는 이유

  • 접근자와 설정자를 사용해야만 나중에 클래스를 업그레이드할 때 편하다.
  • 접근자에서 매개 변수를 통하여 잘못된 값이 넘어오는 경우, 이를 사전에 차단할 수 있다.
  • 필요할 때마다 필드값을 동적으로 계산하여 반환할 수 있다.
  • 접근자만을 제공하면 자동적으로 읽기만 가능한 필드를 만들 수 있다.

클래스 간의 관계 설정

  • 클래스 간의 관계를 설정하는 부분은 객체 지향 설계에서 가장 어려운 부분이다.
  • 상속(Inheritance)
  • 구성(Composition)
