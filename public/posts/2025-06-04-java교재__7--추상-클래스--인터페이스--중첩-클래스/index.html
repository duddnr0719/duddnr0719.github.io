7. 추상 클래스, 인터페이스, 중첩 클래스

2025년 6월 4일 Java(교재)

추상 클래스

: 완전하게 구현되어 있지 않은 메소드를 가지고 있는 클래스 → 메소드가 미완성 되어 있으므로 추상 클래스로는 객체를 생성할 수 없다. → 추상 클래스는 주로 상속 계층에서 추상적인 개념을 나타내기 위한 용도로 사용된다. → 추상 클래스는 하나 이상의 추상 메소드를 가지고 있어야 한다. → abstract 키워드를 사용하여 선언하여 사용한다.

추상 클래스의 용도

→ 자식 클래스에서 반드시 오버라이드 하도록 강제성을 부여한다. ⇒ 추상 클래스를 상속받는 자식 클래스의 주제에 따라서 상속 받는 메서드의 내용이 다를 수 있기 때문에 강제성을 부여하는 것이다.

public abstract class ... {
public abstract void ...(); // 추상 메소드 정의
};

인터페이스

: 다른 클래스를 작성할 때 기본이 되는 틀을 제공하면서 다른 클래스 사이의 중간매개 역할까지 담당하는 일종의 추상 클래스 → interface 키워드를 사용하여 선언한다. → 인터페이스는 추상 메소드들과 디폴드 메소드들로만 이루어진다. ⇒ 인터페이스 내부에서는 필드(변수)가 선언될 수 없다. (상수는 정의할 수 있다.) → 인터페이스 안에서 선언되는 메소드들은 모두 묵시적으로 접근 지정자가 public abstract이다. (public으로 선언 시 어떤 패키지의 어떤 클래스도 사용할 수 있다는 것을 의미한다.) → 인터페이스도 extends 키워드를 사용하여 다른 인터페이스를 상속 받을 수 있다. → 인터페이스 내에서 정의된 변수는 자동적으로 public static final이 되어 상수가 된다.

인터페이스 구현

: 클래스를 정의할 때 implements 키워드를 사용하여 클래스에서 구현할 수 있다. (인터페이스의 구현은 인터페이스에 정의된 추상 메소드의 몸체를 정의한다는 의미이다.)

public interface ... { // 인터페이스 정의 
public void ...(); // 추상 메소드 정의
}

인터페이스의 용도

클래스 - 클래스 간의 is a 관계는 상속(extends)이다. 하나의 클래스는 하나의 슈퍼클래스만 상속받을 수 있다는 뜻이다. 즉, 다중 상속이 지원되지 않는다. - 인터페이스는 상속 관계가 아닌, 클래스 간의 유사성을 인코딩하는 데 사용된다. → 다중 상속이 필요한 경우 인터페이스를 사용한다. ex) 사람과 자동차는 둘 다 달릴 수 있다. 이를 위해 부모 클래스로 Runner를 작성하고, 사람과 자동차 클래스를 Runner 클래스의 자식 클래스로 나타내는 것은 약간 이치에 맞지 않는다. → Runnable 인터페이스를 만들고 이 인터페이스를 양쪽 클래스가 구현하게 하면 된다 !

인터페이스 VS 추상 메소드

  • 추상 메소드를 사용할 때
  • 관련된 클래스들 사잉에서 코드를 공유할 때
  • 공통적인 필드나 메소드의 수가 많은 경우
  • public 이외의 접근 지정자를 사용해야 하는 경우
  • 정적이 아닌 필드나 상수가 아닌 필드를 선언하기를 원할 때
  • 인터페이스를 사용할 때
  • 관련 없는 클래스들이 동일한 동작을 구현하기를 원할 때
  • 특정한 자료형의 동작을 지정하고 싶지만 누가 구현하든지 신경 쓸 필요가 없을 때
  • 다중 상속이 필요할 때

인터페이스 / 추상메소드의 공통점 & 차이점

- 공통점 객체 생성 → 둘 다 객체를 생성(인스턴스화)할 수 없다. 추상 메소드 → 추상 메소드를 포함한다. 기능적 목적 → 상속받는 클래스에서는 추상 메소드를 반드시 재정의하여 구현해야 한다. - 차이점
목적 추상 클래스 인터페이스
개념적 목적 상속 받아 기능을 확장시키는데 목적 구현 객체의 동일한 실행 기능을 보장하기 위한 목적
클래스 클래스가 맞다 (abstract class) 클래스가 아니다 (interface)
일반 메소드 일반 메소드 정의가 가능 일반 메소드 정의 불가능 (디폴트 메소드 정의 가능)
멤버 변수 클래스와 동일하게 변수 선언 및 사용 가능 상수만 사용 가능
상속 키워드 extends implements
다중 상속 불가능 가능
## 다중 상속 : 하나의 클래스가 여러 개의 부모 클래스를 가지는 것. ex) 하늘을 나는 자동차는 자동차의 특성도 가지고 있지만 비행기의 특징도 가지고 있다. - 다중 상속은 애매모호한 상황을 만들 수 있기 때문에 자바에서는 금지되어 있다. → 다이아몬드 문제 \<다이아몬드 문제\> 클래스 B와 C가 A로부터 상속을 받는다고 가정. 클래스 D는 B와 C에서 상속받는다. 클래스 A에 myMethod()가 있는데 이것을 B와 C가 모두 오버라이드를 하였다고 가정. D를 통하여 myMethod()를 호출하게 되면 어떤 메소드가 호출되는가 ? ![](/images/62f0950e87a2974b.png)

인터페이스를 이용한 다중 상속

→ 클래스를 사용하는 것이 아닌 인터페이스를 사용하여 다중 상속과 비슷한 효과를 낼 수 있다. ⇒ 하나의 클래스로부터 상속을 받으면서 동시에 여러 개의 인터페이스도 구현하면 다중 상속과 비슷해진다.

  1. 여러 개의 인터페이스를 동시에 구현한다.
  2. 하나의 클래스를 상속받고 또 하나의 인터페이스를 구현하는 것이다.

다중 상속 예시

interface Drivable { void drive(); }
interface Flyable { void fly(); }

public class FlyingCar implements Drivable, Flyable {
public void drive() { System.out.println("I'm driving"); }
public void fly() { System.out.println("I'm flying"); }

public statci void main(String args[]) {
FlyingCar obj = new FlyingCar();
obj.drive();
obj.fly();
}
}

디폴트 메소드 (Default Method)

: 인터페이스 개발자가 메소드의 디폴트 구현을 제공할 수 있는 기능. → 디폴트 메소드가 정의되어 있으면 인터페이스를 구현하는 클래스가 메소드의 몸체를 구현하지 않아도 메소드를 호출할 수 있다. → default 키워드를 메소드 앞에 추가하여 선언한다. 디폴트 메소드가 중요한 이유는 인터페이스가 기존의 코드를 건드리지 않고 확장될 수 있도록 하기 위함이다.
→ 인터페이스에 의하여 정의된 메소드는 클래스에 의해서 반드시 구현되어야 하는데, 인터페이스에 새로운 메소드가 추가되면 이 인터페이스를 사용하는 모든 클래스들이 수정되어야 한다. 디폴트 메소드가 이 문제를 해결한다 !

정적 메소드(Static Method)

: 클래스로 객체를 생성하지 않아도 호출이 가능한 메소드. → 해당 메소드가 정의되어 있는 클래스의 이름이나 생성된 객체 등을 통해 호출할 수 있다. → 인터페이스에 추가하기 위해선 메소드 이름 앞에 static 키워드를 추가한다.

팩토리 메소드 (Factory Method)

: 공장처럼 객체를 생성하는 정적 메소드. → 디자인 패턴의 하나로서 객체를 만드는 부분을 부모 클래스에 위임하는 패턴이다. 즉, new를 호출하여서 객체를 생성하는 코드를 부모 클래스에 위함한다는 의미.

중첩 클래스

- 정적 중첩 클래스 : 앞에 static이 붙어서 내장되는 클래스 - 비정적 중첩 클래스 : static이 붙지 않은 일반적인 중첩 클래스 - 내부 클래스(inner class) : 클래스의 멤버처럼 선언되는 중첩 클래스 - 지역 클래스(local class) : 메소드의 몸체 안에서 선언되는 중첩 클래스 - 익명 클래스(annoymouse class) : 수식의 중간에서 선언되고 바로 객체화 되는 클래스 - 중첩 클래스를 사용하는 이유 → 내부 클래스는 외부 클래스의 private 멤버도 접근할 수 있기 때문에 중첩 클래스를 사용한다. ![](/images/9391a321c656d8f5.png) ## 내부 클래스 : 클래스 안에 클래스를 선언하는 것 → 내부 클래스는 외부 클래스의 인스턴스 변수와 메소드를 전부 사용할 수 있다.

지역 클래스

: 메소드 안에 정의되는 클래스 → 지역 클래스는 메소드 안에서만 사용이 가능하고 외부 클래스의 private 변수에 접근할 수 있다.

익명 클래스

: 클래스 몸체는 정의도지만 이름이 없는 클래스 → 익명 클래스는 클래스를 정의하면서 동시에 객체를 생성한다. 즉, 이름이 없기 때문에 한 번만 사용이 가능하다.

내부 클래스 예시

class OuterClass {
private int value = 10;

class InnerClass { // 내부 클래스
public void myMethod() {
System.out.println("외부 클래스의 private변수 값: " + value);
}
}

OuterClass() {
InnerClass obj = new InnerClass();
obj.myMethod();
}
}
public class InnerClassTest {
public static void main(String args[]) {
OuterClass outer = new OuterClass();
}
}
// 외부 클래스의 private 변수 값 : 10 이 출력된다.

지역 클래스 예시

class localInner {
private int data = 30;

void display() {
final String msg = "현재의 데이터값은 ";

class Local { // 지역 클래스 선언 
void printMsg() {
System.out.println(msg + data);
}
}
Local obj = new Local();
obj.printMsg();
}
}
public class localInnerTest {
public static void main(String args[]) {
localInner obj = new localInner();
obj.display();
}
}
// 현재의 데이터값은 30 이 출력된다.

익명 클래스 예시

public interface RemoteControl {
void turnOn();
void turnOff();
}

public class AnonymousClassTest {
public static void main(String args[]) {
RemoteControl ac = new RemoteControl() { // 익명 클래스 정의 -> 익명 클래스가 정의되면서 동시에 객체도 생성된다.
public void turnOn() {
System.out.println("TV turnOn()");
}
public void turnoff() {
System.out.println("TV turnOff()");
}
};
ac.turnOn();
ac.turnOff();
}
}
// TV turnOn()
// TV turnOff() 가 출력된다.
