2025년 6월 3일 Java(교재)

패키지

: 관련있는 클래스들을 하나로 묶은 것. → package 키워드로 선언한다. ### 패키지의 종류

  • 내장 패키지 : 자바에서 기본적으로 제공하는 패키지
  • 사용자 정의 패키지 : 사용자가 정의하는 패키지

패키지를 사용하는 이유

  1. 서로 관련된 클래스들을 하나의 단위로 모을 수 있다.
  2. 이름 충돌을 피하고 유지 관리가 쉬운 코드를 작성할 수 있다.
  3. 패키지를 이용하여 세밀한 접근 제어를 구현할 수 있다. → 패키지 안의 클래스들은 패키지 안에서만 사용이 가능하도록 선언될 수 있는데, 이렇게 선언이 되면 패키지 외부에서는 이 클래스들을 사용할 수 없다. 따라서 클래스들이 캡슐화될 수 있는 또 하나의 방법을 제공한다.
  4. 패키지를 사용하는 중요한 이유 중 하나 이름공간 때문이다. 원칙적으로 모든 클래스는 서로 다른 이름을 가져야 하는데, 프로그램을 만들다보면 이는 쉬운 일이 아니다. 따라서 이름 충돌을 방지할 방법이 패키지이다. → 패키지만 다르면 동일한 클래스 이름을 마음껏 사용할 수 있다.

패키지를 사용하는 방법

  1. 완전한 이름으로 참조한다. (완전한 이름이란 패키지 이름이 클래스 앞에 붙은 것이다.) → 외부 패키지에 있는 클랫흐를 사용하려면 원칙적으로 앞에 패키지를 붙인 정식 클래스 이름을 써주어야 한다. 반복적으로 많이 사용되는 클래스의 경우에는 import를 사용하여 해당 클래스나 패키지를 포함하여 사용할 수 있다. ex) graphics 패키지에 있는 Rectangle 클래스의 정식 이름은 graphics.Rectangle이다.
  2. 패키지 안에서 우리가 원하는 클래스만을 포함한다. → 외부 패키지의 특정한 멤버를 import하여 사용한다. ex) import java.util.Scanner;
  3. 패키지 안의 모든 클래스를 포함한다. → 하나의 패키지 안에 포함된 모든 클래스를 포함한다. ⇒ 이는 “ * “ 을 사용한다. ex) import java.util.*;

계층 구조의 패키지 포함하기

예를 들어 java.awt.* 를 포함시키면 java.awt 아래에 있는 패키지는 자동으로 포함될 것이라고 생각하기 쉬운데, 사실 그렇지 않다. 따라서 계층 구조로 되어 있는 패키지의 경우 하위 패키지라고 하더라도 *를 사용하여 포함해주어야 한다.

클래스 파일이 로드되는 시점

자바 소스 파일이 컴파일 되면 .class 확장자를 가지는 클래스 파일로 변환되고 파일 시스템에 저장된다. 클래스 파일은 자바 가상 기계(JVM)에 의하여 로드 된다.

  • 클래스 파일은 요청 시 JVM에 로드된다. 이것이 기본적인 방법으로 지연 클래스 로드(Lazy Class Loading)이라고 한다.
  • 애플리케이션 코드를 구성하는 기본적인 클래스 파일은 시작 시 로드된다.

자바 가상 기계(JVM)가 클래스를 찾는 순서

  1. 부트스트랩 클래스 - 자바 플랫폼을 구성하는 핵심적인 클래스이다. 디렉터리 jre/lib가 있는 rt.jar 및 기타 여러 jar 파일이다. Java 9부터는 모듈화되어 있는 jmods파일들이 로드된다.
  2. 확장 클래스 - 자바 확장 메커니즘을 사용하는 클래스이다. 이들은 확장 디렉터리에 있는 jar 파일들이다. 디렉터리 jre/lib/ext의 모든 jar 파일은 확장으로 간주되며 로드된다.
  3. 사용자 클래스 - 확장 메커니즘을 사용하지 않는 개발자 및 타사에서 정의한 클래스이다. 가상 머신 명령줄에서 -classpath 옵션을 사용하거나 CLASSPATH 환경 변수를 사용하여 이러한 클래스의 위치를 식별한다.
  • 확장 메커니즘 : 자바는 다양한 방법을 통해 기능을 확장할 수 있는데, 대표적으로 상속, 인터페이스, 람다 표현식 등이 있다. 이처럼 자바의 객체지향적 특성을 더욱 강화하고 재사용성 및 확장성을 높여주는 역할을 하는 것.
  • CLASSPATH : 사용자가 직접 작성하였거나 외부에서 다운로드 받은 클래스를 찾기 위하여 가상 머신이 살펴보는 디렉터리들을 모아둔 클래스 경로.

가상 기계가 클래스를 찾는 3가지의 방법

  1. 첫 번째로 가상 기계는 현재 디렉터리부터 찾는다.
  2. 일반적으로 환경 변수인 CLASSPATH에 설정된 디렉터리에서 찾는다.
  3. 가상 머신을 실행할 때 옵션 -classpath를 사용할 수 있다. 즉, 가상 머신을 실행할 때, 클래스 경로를 알려주는 것이다.

JAR 압축 파일

: Java Archive의 줄임말로서 자바 애플리케이션을 한 개의 파일로 만들어서 사용자에게 전달할 방법이다. → 자바 파일들을 압축하여 하나의 파일로 만드는 데 사용된다.

JAR 파일 만드는 방법

  • JDK 안에 포함된 jar 도구를 이용하여 만든다.

C:> jar cvf Name.jar *.class icon.png → Name.jar은 파일 이름을 뜻하고, *.class는 압축할 클래스를 의미한다.

  • 실행 가능한 JAR 파일을 생성하려면 e를 추가한다.

C:> jar cvfe Name.jar Main *.class icon.png → Main은 처음 실행 시 실행될 클래스를 의미한다.

  • JAR 파일로 압축된 파일을 실행하려면 다음의 문장을 입력한다.

C:> java -jar Name.jar

Object 클래스

: java.lang 패키지에 들어 있으며 자바 클래스 계층 구조에서 최상단에 위치하는 클래스

Object 클래스의 메소드

  • public boolean equals(Object obj) : obj가 이 객체와 같은지를 검사한다. → Object에서 제공되는 equals()는 == 연산자를 사용하여 객체의 주소가 동일한지를 검사하여 true or false를 반환한다. (객체에 대해서는 올바르지 않은 경우가 많이 있다.)
  • public String toString() : 객체의 문자열 표현을 반환한다.
  • protected Object clone() : 객체 자신의 복사본을 생성하여 반환한다.
  • public int hashCode() : 객체에 대한 해쉬 코드를 반환한다.
  • protected void finalize() : 가비지 콜렉터에 의하여 호출된다. → 객체가 소멸되기 직전에 호출된다. Object 클래스의 finalize() 에서는 아무것도 하지 않지만 자식 클래스에서 재정의하여 자원을 반납하는 등의 정리 과정을 실행할 수 있다.
  • public final Class getClass() : 객체의 클래스 정보를 반환한다. → 객체가 어떤 클래스로 생성되었는지에 대한 정보를 반환한다.
